# AI-202 — 学习计划生成接口 `POST /api/ai/plan/generate`

> 状态: in-progress | 栈: node-ts (NestJS) | 分支: feat/ai-202 | 依赖: AI-106, AI-201（均 done）

## 1. 目标

为 M2 学习计划提供首个可调用后端接口：前端（AI-207 向导页）提交孩子的年龄/等级/每日时长/兴趣/周数，
后端调用 `AiProvider.chat` 生成结构化学习计划 JSON 并返回（**不落库**——落库与应用由 AI-206 负责）。
无 key（`AI_PROVIDER=mock`）时仍可返回可用结果，保证 AI-104「无 key 全流程演示」契约。

## 2. 接口契约

### 后端
- 路由：`POST /api/ai/plan/generate`（全局前缀 `api` → `PlanController('ai/plan')` + `@Post('generate')`）
- 鉴权：本接口按设计文档 `docs/ai-integration.md` 契约 `childId` 由 body 传入，**不加 JwtAuthGuard**（保持与文档 body 一致；AI-206 apply 接口再决定鉴权）。
- 请求体 `GeneratePlanDto`：
  | 字段 | 类型 | 校验 |
  |---|---|---|
  | childId | string(uuid) | `@IsUUID()` |
  | ageRange | string | `@Matches(/^\d{1,2}-\d{1,2}$/)`（如 `6-8`） |
  | level | enum | `@IsIn(['pre-a1','a1','a2'])`（Pre-A1→A2） |
  | dailyMinutes | int | `@IsInt() @Min(5) @Max(120)` |
  | interests | string[] | `@IsArray() @ArrayNotEmpty() @IsString({each:true}) @ArrayMaxSize(20) @MaxLength(30,{each:true})` |
  | weeks | int | `@IsInt() @Min(1) @Max(4)`（表单 1-4 周） |
- 响应 `GeneratePlanResponse`：`{ plan: GeneratedPlan, model?: string, degraded: boolean }`
  - `GeneratedPlan`：宽松结构（容忍 LLM 自由 JSON），已知字段 `weeks?: { week?, days?: { day?, date?, skillType?, title?, lessons?: {...}[], content? } }[]`，带索引签名 `[k:string]: unknown`。
  - `degraded: true` 表示 AI 返回非 JSON（如 MockProvider 演示文本）→ `plan` 退化为 `{ rawText: <原文> }`，仍返回 200，前端可降级展示。

### 前端
- 本 feature 不含前端（向导页为 AI-207）。前端调用点将在 AI-207 复用 `POST /api/ai/plan/generate`。

## 3. 数据模型
- 复用 AI-201 实体 `StudyPlan` / `StudyPlanDay`（已建表，本接口不写入；写入在 AI-206）。
- `PlanModule` 已是 `TypeOrmModule.forFeature([StudyPlan, StudyPlanDay])` 并 export；本 feature 在其内新增 Controller + Service。

## 4. 验收标准
- [ ] `POST /api/ai/plan/generate` 合法入参 → 返回 `GeneratePlanResponse`（plan 为结构化 JSON，`degraded:false`）。
- [ ] 非法入参（缺字段/类型错误/越界）→ 被全局 `ValidationPipe`(class-validator) 拦截返回 400。
- [ ] `AI_PROVIDER=mock` 时（返回演示文本）接口仍 200，`degraded:true` + `plan.rawText` 兜底。
- [ ] `PlanModule` 注册进 `AppModule`，路由真实可达。
- [ ] 单元测试覆盖：DTO 校验规则、Service 解析成功/非 JSON 兜底/provider 异常传播、Controller 路由+DTO 装配。

## 5. 风险点
- **LLM 返回 Markdown 代码围栏**（```json ... ```）：`PlanService` 解析前先剥离围栏，否则真实 provider 会误判 `degraded`。
- **MockProvider 不返回 JSON**（其 spec `mock-ai.provider.spec.ts` 断言返回 `[Mock 计划]` 文本）：**不改 MockProvider**（会破坏 AI-104 演示契约与已有 spec），由 `PlanService` 的 `degraded` 兜底处理演示路径。
- **`PLAN_SYSTEM_PROMPT` 仅为占位**：完整双语 PlanAgent 提示词（安全红线/间隔复习/技能交错）属 AI-203，本 feature 内联最小可运行 prompt 并标注待替换，避免过度构建 AI-203。
- JSON 严格 Schema 校验 + 重试 + 模板降级属 AI-204/AI-205，本 feature 仅做 best-effort 解析。

## 6. 测试计划（硬约束 #6）
### 单元测试（覆盖有逻辑分支的源码）
- `generate-plan.dto.spec.ts`：逐一验证各字段合法/非法（UUID/ageRange 正则/level 枚举/数值边界/interests 数组）必中 class-validator。
- `plan.service.spec.ts`：① provider 返回合法 JSON → `degraded:false` 且 `plan.weeks` 透传；② provider 返回非 JSON 文本 → `degraded:true` + `plan.rawText`；③ provider `chat` 抛错 → 异常向上传播（AI-106 重试/配额在外层）。
- `plan.controller.spec.ts`：经 TestingModule 装配 `PlanController` + mock `AI_PROVIDER_TOKEN`；合法 body 调 `generate` 返回结构化响应；非法 body 经 `ValidationPipe` transform 抛 `BadRequestException`（等价 400）。
- 更新 `plan.module.spec.ts`：原仅测建表，`PlanModule` 现含注入全局 `AI_PROVIDER_TOKEN` 的 `PlanService`，需在测试模块补 mock provider 避免 Nest 依赖解析失败。
### BDD/E2E 用户旅程
- **豁免**：本 feature 为纯后端 API，约束 #6 明确「不为纯后端 API 写 BDD」；`/plan` 页端到端旅程（向导提交→展示计划）由 AI-207/AI-208 自带 E2E。AI-201 已确立同口径豁免。
