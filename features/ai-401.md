# AI-401 — 对话陪练数据模型（实体 + 建表）

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM, better-sqlite3 / postgres 双驱动) | 分支: feat/ai-401
> 依赖: — | 前置: 当前链 …←feat/ai-309←feat/ai-401（在 feat/ai-309 上建新分支）

## 1. 目标
为 M4「AI 对话陪练」落地**数据底座**：建立 `ai_chat_sessions`（会话头）与 `ai_chat_messages`（会话消息）两张表，分别承载「某 child 用户的某次场景对话」与「该会话的逐轮消息」。后续 AI-402（TTS）、AI-403（聊天接口）、AI-407（会话 UI）、AI-408（星标）、AI-409（历史续聊）将直接消费本 feature 的实体与 `ChatModule` 仓库。

## 2. 接口契约
### 后端（纯数据模型，无新 HTTP 路由）
- 新增 `AiChatSession` 实体 → 表 `ai_chat_sessions`：会话头，`@Column userId`(varchar 255, index) + `sceneId`(varchar 64, index, 可空) + `stars`(int, 默认 0) + `createdAt`/`updatedAt`(UpdateDateColumn nullable)。
- 新增 `AiChatMessage` 实体 → 表 `ai_chat_messages`：`@Column sessionId`(varchar 255, index) + `role`(varchar 16, 取值 `user`/`assistant`/`system`，由 `CHAT_MESSAGE_ROLES` 常量约束) + `text`(text) + `audioPath`(varchar 512, 可空) + `createdAt`。
- 导出 `ChatMessageRole` 联合类型 + `CHAT_MESSAGE_ROLES` 常量数组，供 AI-403 DTO/校验复用。
- 新增 `ChatModule`（`TypeOrmModule.forFeature([AiChatSession, AiChatMessage])` 并导出 `TypeOrmModule`），作为 AI-403+ 注入仓库的注册点（与 `PlanModule` 同级，非 `@Global`）。
- 两实体注册进 `config/database.config.ts` 的 `appEntities`（dev `synchronize` 自动建表，与 AI-107/108/201/301 一致）；`ChatModule` 注册进 `app.module.ts` imports。

## 3. 数据模型
- `AiChatSession` (`ai_chat_sessions`)：
  - `id` uuid PK、`userId`(varchar 255, index)、`sceneId`(varchar 64, index, nullable)、
  - `stars`(int, default 0)、`createdAt`(CreateDateColumn)、`updatedAt`(UpdateDateColumn, nullable)
- `AiChatMessage` (`ai_chat_messages`)：
  - `id` uuid PK、`sessionId`(varchar 255, index)、`role`(varchar 16)、`text`(text)、
  - `audioPath`(varchar 512, nullable)、`createdAt`(CreateDateColumn)
- **不写迁移**：沿用项目 `synchronize` 模式（与 AI-107/108/201 一致）。
- **时间列铁律**：一律 `@CreateDateColumn()` / `@UpdateDateColumn()`，不用 `@Column({type:'timestamp'})`（better-sqlite3 不支持，AI-107 踩坑）。
- **关联口径**：与 `AiSpeechAttempt` / `AiCallLog` 同口径——`userId`/`sessionId`/`sceneId` 存 `varchar` **非硬外键**（AI 追加型审计记录，不因用户/会话删除而级联清理，避免与 `User` 实体强耦合）；故不修改 `User` 实体、不引入跨模块级联。

## 5. 风险点
- **枚举可移植性**：`role` 用 `type: 'varchar'` + TS 联合类型（与 `AiCallLog.status` 同口径），不用 DB 原生 enum，确保 sqlite/postgres 双驱动兼容。
- **时间列**：遵守 TypeORM 时间列铁律，避免 CI seed `DataTypeNotSupportedError`。
- **非硬外键**：`userId`/`sessionId` 仅 varchar 引用，与 AI-301 口径一致，避免级联与模块耦合风险。
- **不越界**：本 feature 仅建表 + 实体 + 模块注册，不实现聊天/星标逻辑（属 AI-403/AI-408），不自创需求。
