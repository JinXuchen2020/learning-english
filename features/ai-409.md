# AI-409 — 会话历史与续聊（我的会话列表 + 恢复历史 + 续聊）

> 依赖：AI-407（`/chat` 会话 UI）、AI-401（`ai_chat_sessions` / `ai_chat_messages` 实体）、AI-403（`POST /api/ai/chat/messages` 已支持 `sessionId` 复用与历史回载）。
> 类型：**前后端协同功能**，按项目测试约定（约束 #6）前端部分需 **BDD/E2E**（用户可感知端到端旅程），后端纯逻辑（摘要构建/排序/角色过滤）需 **单元测试**。

## 1. 目标
为 5-10 岁孩子提供「对话陪练」的连续性体验：
- **我的会话列表**：进入 `/chat` 即拉取该用户全部历史会话摘要（场景、最近消息预览、星星数、消息数），按最近活动倒序。
- **恢复历史**：点任意会话 → 回显其全部历史消息到对话 thread，狐狸与孩子的发言完整呈现。
- **续聊不丢上下文**：恢复后继续发言，`sendMessage` 携带 `sessionId`，后端自动从该会话历史重建 LLM 上下文（AI-403 既有能力），保证「续聊上下文不丢」。
- **开新对话**：随时「+ New chat」清空当前会话，回到初始态发起新对话。

## 2. 前后端契约

### 2.1 `GET /api/ai/chat/sessions?userId=`（AI-409 新增）
```
→ ChatService.listSessions(userId?)
   SELECT * FROM ai_chat_sessions WHERE userId = :uid
   + 其全部 ai_chat_messages（WHERE sessionId IN (:ids)，升序）
   → 纯函数 buildSessionSummaries 按「最近活动」倒序（最后一条 user/assistant 消息时间，无消息用 createdAt）
→ 返回 ChatSessionSummary[]：
   { id, sceneId, stars, messageCount(仅 user/assistant，排除 system),
     lastMessagePreview(截断 80), createdAt, updatedAt }
```
- `userId` 缺省 `anonymous`（与 messages 接口口径一致）。
- 排序不依赖 `updatedAt`：避免「从未触发星星落库 → updatedAt 为 null」导致排序异常；以真实对话时间（最后一条消息）为准。

### 2.2 `GET /api/ai/chat/sessions/:id/messages?userId=`（AI-409 新增）
```
→ ChatService.getSessionMessages(id, userId?)
   SELECT * FROM ai_chat_messages WHERE sessionId = :id ORDER BY createdAt ASC
   → 过滤 role ∈ {user, assistant}（排除 system 系统提示）
   → 纯函数 toHistoryMessage 映射为 ChatHistoryMessage
→ 返回 ChatHistoryMessage[]：
   { id, role, text, ttsUrl(当前恒 null，历史音频未落库路径), createdAt }
```
- `ttsUrl` 当前恒为 `null`：`ai_chat_messages.audioPath` 始终为 null（AI-402 的 TTS 音频以 URL/data URI 直接返回，未持久化路径），故历史回显仅文本（满足验收「历史消息完整回显」）。若未来落库音频路径再启用。

### 2.3 `POST /api/ai/chat/messages`（AI-403 既有，AI-409 复用）
续聊时前端携带上次 `sessionId`；后端 `resolveSession` 复用既有会话（不存在 → 404），并从 `ai_chat_messages` 重建历史注入 LLM 上下文——**续聊上下文不丢**由该既有链路保证（单测见 AI-403「历史消息按时间升序进入 LLM 上下文」）。

### 2.4 前端类型（`src/lib/types.ts`）
- 新增 `ChatSessionSummary { id, sceneId, stars, messageCount, lastMessagePreview, createdAt, updatedAt }`
- 新增 `ChatHistoryMessage { id, role, text, ttsUrl, createdAt }`
- `src/lib/api.ts` 新增 `getChatSessions(userId?)` → `GET /api/ai/chat/sessions?userId=`；`getChatSessionMessages(sessionId, userId?)` → `GET /api/ai/chat/sessions/:id/messages?userId=`

## 4. 前端 UI 与 data-component 钩子（供 E2E 定位）
- **`/chat`（`src/app/chat/page.tsx` → `ChatInner`）**
  - 「My conversations」面板 `ChatSessionList[data-component]`（置于头部星标/庆祝横幅之下、场景卡之上）。
  - 列表项 `ChatSessionItem[data-component][data-session-id][data-active]`：显示 `sceneTitle(sceneId)`（或 "Free chat"）、`lastMessagePreview`、`stars`（>0 时）、`messageCount`；点击 → `handleResumeSession`。
  - 空列表提示 `ChatSessionEmpty[data-component]`：「No past chats yet 🐾」。
  - 「+ New chat」按钮 `button[data-action="new-chat"]` → `handleNewChat`（清空 `sessionId/messages/selectedSceneId/sessionStars/celebration`）。
  - `handleResumeSession(session)`：`getChatSessionMessages` → 映射为 `ChatMessage[]`（role/text/ttsUrl）→ `setMessages` + `setSessionId(session.id)` + `setSelectedSceneId(session.sceneId)` + `setSessionStars(session.stars)`；失败 `catch` 仅置 `sendError`，不阻塞。
  - 加载/续聊失败均独立 `catch`，保留空列表，新对话照常可用。

## 5. 边界与降级
- `listSessions` 异常 / 无会话 → 返回 `[]`，前端显示空提示，不阻断聊天。
- `getSessionMessages` 异常 → 续聊失败提示，用户可返回或开新对话。
- `userId` 缺省 → `anonymous` 占位，与 `sendMessage` 口径一致。
- 续聊时如再点其他场景卡：仅高亮变更，`handleSend` 因 `messages>0` 不重发 `sceneId`，后端以会话本身 `sceneId` 为准（不影响续聊链路）；属已知小交互细节，不阻断功能。
- **无 DB migration**：复用 AI-401 已建表与列；新增的仅为查询端点与字段映射。

## 6. 越界声明
- 会话删除/重命名/搜索不在本 feature（后续可加 `DELETE /api/ai/chat/sessions/:id`）。
- 跨用户会话隔离依赖统一鉴权 feature（当前 deferred）。
