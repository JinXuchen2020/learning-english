# AI-201 — 学习计划数据模型（实体 + 建表）

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM) | 分支: feat/ai-201
> 依赖: — | 前置: 当前链 feat/ai-106←feat/ai-107←feat/ai-108←feat/ai-201（在 feat/ai-108 上建新分支）

## 1. 目标
为 M2「AI 学习计划生成」落地**数据底座**：建立 `study_plans`（计划头）与 `study_plan_days`（按天计划）两张表，并与 `User` 关联；定义 `skill_type`（`vocab`/`listen`/`speak`/`write`）与 `status`（`draft`/`applied`/`archived`）枚举。后续 AI-202（生成接口）、AI-206（应用计划落库 `tasks`）、AI-208（计划展示）、AI-209（进度回写）将直接消费本 feature 的实体与 `PlanModule` 仓库。

## 2. 接口契约
### 后端（纯数据模型，无新 HTTP 路由）
- 新增 `StudyPlan` 实体 → 表 `study_plans`：计划头，`ManyToOne(User)` + `userId` 列（与现有 `lesson_progress`/`word_progress`/`task_completion` 风格一致，含 `onDelete: 'CASCADE'`）；`skillType`、`status`（默认 `draft`）；`OneToMany(StudyPlanDay, { cascade: true })`。
- 新增 `StudyPlanDay` 实体 → 表 `study_plan_days`：`ManyToOne(StudyPlan)` + `planId` 列（`onDelete: 'CASCADE'`）；`dayIndex`、`date`(YYYY-MM-DD, 可空)、`skillType`、`title`、`content`(text, AI-202 写入)、`isDone`(默认 false)。
- 导出 `STUDY_PLAN_SKILL_TYPES` / `STUDY_PLAN_STATUSES` 常量数组 + `StudyPlanSkillType` / `StudyPlanStatus` 联合类型，供后续 feature 与 DTO 复用。
- 新增 `PlanModule`（`TypeOrmModule.forFeature([StudyPlan, StudyPlanDay])` 并导出 `TypeOrmModule`），作为 AI-202+ 注入仓库的注册点。
- 两实体注册进 `config/database.config.ts` 的 `appEntities`（dev `synchronize` 自动建表，与 AI-107/108 一致）。

## 3. 数据模型
- `StudyPlan` (`study_plans`)：
  - `id` uuid PK、`userId`(varchar 255, index, FK→users)、`skillType`(varchar 16)、`status`(varchar 16, default 'draft')、
  - `days`(OneToMany, cascade)、`createdAt`(CreateDateColumn)、`updatedAt`(UpdateDateColumn, nullable)
- `StudyPlanDay` (`study_plan_days`)：
  - `id` uuid PK、`planId`(varchar 255, index, FK→study_plans)、`dayIndex`(int, default 0)、`date`(varchar 10, nullable)、
  - `skillType`(varchar 16)、`title`(varchar 255, default '')、`content`(text, default '')、`isDone`(boolean, default false)、
  - `createdAt`、`updatedAt`(nullable)
- **不写迁移**：沿用项目 `synchronize` 模式（与 AI-107/108 一致）。
- **时间列铁律**：一律 `@CreateDateColumn()` / `@UpdateDateColumn()`，不用 `@Column({type:'timestamp'})`（better-sqlite3 不支持，AI-107 踩坑）。

## 5. 风险点
- **枚举可移植性**：用 `type: 'varchar'` + TS 联合类型（与 `AiCallLog.status` 同口径），不用 DB 原生 enum，确保 sqlite/postgres 双驱动兼容。
- **时间列**：遵守 TypeORM 时间列铁律，避免 CI seed `DataTypeNotSupportedError`。
- **级联删除**：`onDelete: 'CASCADE'` 保证删用户/删计划时子行清理，与现有进度实体一致。
- **不越界**：本 feature 仅建表 + 实体 + 模块注册，不实现生成/应用逻辑（属 AI-202/AI-206），不自创需求。
