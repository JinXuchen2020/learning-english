## 1. 目标

实现 `AiProvider` 接口的第一个真实后端 **BigModelProvider**，对接智谱 BigModel 的 OpenAI 兼容端点，让业务层（plan / speech / chat / report）在 `AI_PROVIDER=bigmodel` 时获得可用的 LLM 对话与多模态能力。`chat` / `chatWithImage` 走真实 API；`transcribe` / `assessPronunciation` / `synthesize` 在 AI-102 范围内暂无 BigModel 对应能力，返回**降级结果**（不抛错，日志标记），待后续 feature（AI-304/AI-305/AI-402）接入真实 STT/TTS。

## 2. 接口契约

文件: `server/src/ai/bigmodel.provider.ts`（实现 `server/src/ai/ai-provider.interface.ts`）

### 2.1 chat — 文本对话（LLM）

- 端点：`POST {BIGMODEL_BASE_URL}/chat/completions`（默认 `https://open.bigmodel.cn/api/paas/v4`）
- 鉴权：`Authorization: Bearer {BIGMODEL_API_KEY}`
- 请求体（OpenAI 兼容）：
  - `model`：默认 `BIGMODEL_MODEL`（`glm-4.7-flash`，推理模型）
  - `messages`：`[{ role, content }]`（由 `ChatMessage[]` 映射）
  - `temperature`：透传 `options.temperature`（缺省不传）
  - `max_tokens`：默认 `512`（推理模型 `content` 不被截断）；可经 `options.maxTokens` 覆盖
- 响应解析：
  - `choices[0].message.content` → `ChatResult.text`
  - `choices[0].message.reasoning_content` → `ChatResult.reasoningContent`（推理模型专属，可能缺省）
  - `usage.{prompt_tokens,completion_tokens,total_tokens}` → `ChatResult.usage`
  - `model` 回填到 `ChatResult.model`
- 超时：默认 `60000ms`（推理模型需充裕），可经 `options.timeoutMs` 覆盖，用 `AbortSignal.timeout` 实现

### 2.2 chatWithImage — 多模态 / OCR

- 同一 `/chat/completions` 端点，`model` 默认 `BIGMODEL_VISION_MODEL`（`glm-4.6v-flash`）
- `messages[0].content` 为数组：`[{type:'text',text:prompt}, {type:'image_url', image_url:{ url: 'data:{mimeType};base64,{data}' }}]`
- 解析同 chat（仅取 `content`）

### 2.3 降级方法（AI-102 范围外能力）

- `transcribe` → `{ text:'', confidence:0, durationMs:0 }`
- `assessPronunciation` → `{ score:0, readableText:referenceText, weakPhonemes:[], feedback:'发音评测暂不可用，请稍后再试。', mascotExpr:'thinking' }`
- `synthesize` → `{ audioBase64:'', mimeType:'audio/mp3', durationMs:0 }`
- 三者均通过 `Logger.debug` 标记"暂未实现，返回降级结果"，**不抛错**。

### 2.4 错误处理（清晰化）

`postJson` 统一封装，抛出自有的 `AiProviderException`（含 `statusCode` / `code`）：

- 未配置 `BIGMODEL_API_KEY` → `401`「API key 未配置」
- 网络异常 → `0 / NETWORK`「网络请求失败」
- `AbortError`（超时） → `504`「请求超时」
- HTTP `401/403` → `401/403`「鉴权失败（无效或过期 key）」
- HTTP `429` → `429`「触发限流」（带 BigModel `error.code`，如 `1305`）
- 其他非 2xx → 对应 `statusCode`「接口错误」
- 2xx 但结构异常（缺 `choices[0].message.content`） → `502`「返回结构异常」

> 说明：重试/降级编排属 AI-106；AI-102 仅负责把失败**清晰抛出**供上层捕获。

## 3. 数据模型

无数据库实体（AI-102 纯 provider 实现）。配置从环境变量读取，构造函数允许注入 `BigModelConfig` 便于测试与 AI-103 动态装配：

```ts
export interface BigModelConfig {
  apiKey?: string;
  baseUrl?: string;
  model?: string;
  visionModel?: string;
}
```

`fetch` 函数以构造参数注入（默认 `globalThis.fetch`），便于单测 mock，且不引入 `axios` 等新依赖。

## 5. 风险点

- **推理模型响应结构**：`glm-4.7-flash` 返回 `reasoning_content`+`content`，provider 只读 `content`，`max_tokens` ≥512 避免 `content` 截断。
- **超时机制**：用 `AbortSignal.timeout(timeoutMs)`，捕获 `AbortError` 映射为 504；Node 17.3+ 支持，本机 Node 22 满足。
- **fetch 类型**：项目 tsconfig 默认含 DOM lib，`fetch`/`Response`/`AbortSignal` 类型可用；为避免不同 lib 解析差异，`postJson` 返回值用显式 `BigModelChatResponse` 接口，避免 `any`。
- **不越界**：AI-102 **不**创建 `AiModule`（属 AI-103）、**不**做重试/降级编排（属 AI-106）、**不**改 `.env.example`（AI-105 已有 `BIGMODEL_*`）。
