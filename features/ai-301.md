# AI-301 — 口语尝试数据模型（实体 + 落库服务）

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM) | 分支: feat/ai-301
> 依赖: — | 前置链: feat/ai-209（在最新分支 feat/ai-209 上建新分支）| 下游: AI-302/303/306/307 消费本实体

## 1. 目标

为 M3「AI 每日口语训练」落地**数据底座**：建立 `ai_speech_attempts` 表，记录每次跟读尝试的
`userId / wordId / sentenceId / audioPath / score / weakPhonemes / createdAt`；提供
`AiSpeechAttemptService` **最佳努力（best-effort）持久化**与按用户查询，供 AI-303（评测接口）/
AI-306（评分反馈）/ AI-307（跟读卡片）消费。后续 AI-302（录音采集）、AI-305（STT）、AI-309（句库）
将直接复用本 feature 的实体与 `AiModule` 仓库。

## 2. 接口契约

### 后端（纯数据模型 + 持久化服务，无新 HTTP 路由；路由在 AI-303 落地）
- 新增 `AiSpeechAttempt` 实体 → 表 `ai_speech_attempts`（字段见 §3）。
- 新增 `AiSpeechAttemptService`（`@Injectable`，注册进 `AiModule`）：
  - `record(entry: AiSpeechAttemptEntry): Promise<boolean>` — 最佳努力落库：`score` 经 `clampScore`
    钳制到 [0,100] 并取整；`weakPhonemes` 经 `sanitizePhonemes` 清洗（去首尾空白、过滤空串）；
    DB 写入失败**仅 warn 并返回 false，不阻断主流程**（与 AI-108 `AiCallLogService` 同口径）。
  - `findByUser(userId: string, limit = 50): Promise<AiSpeechAttempt[]>` — 按 `createdAt DESC`
    取最近 N 条（供 AI-307 历史展示 / AI-306 弱音素聚合）。
  - 导出纯函数 `clampScore(score)` / `sanitizePhonemes(phonemes)` 供单测直接覆盖分支。
- 与 `AiCallLog` 同口径：`userId` 存 `varchar`（**非硬 FK**，审计型追加记录，不级联删 User），
  与 `lesson_progress` / `word_progress` 既有 `userId` 列风格一致。
- 实体注册进 `config/database.config.ts` 的 `appEntities`（dev `synchronize` 自动建表，与
  AI-107/108/201 一致）。

## 3. 数据模型

- `AiSpeechAttempt` (`ai_speech_attempts`)：
  - `id` uuid PK
  - `userId`(varchar 255, **index**)
  - `wordId`(varchar 255, nullable, **index**) — 单词跟读时填，句子模式为空
  - `sentenceId`(varchar 255, nullable, **index**) — 句子跟读（AI-309）时填，单词模式为空
  - `audioPath`(varchar 512) — 录音文件路径（AI-302 落盘）
  - `score`(int, default 0) — 发音评分 0-100（AI-305/306 写入）
  - `weakPhonemes`(simple-array, default '') — 弱音素列表（`simple-array` 在 sqlite/postgres 双驱动可移植）
  - `createdAt`(CreateDateColumn)
- **不写迁移**：沿用项目 `synchronize` 模式（与 AI-107/108/201 一致）。
- **时间列铁律**：一律 `@CreateDateColumn()`，不用 `@Column({type:'timestamp'})`（better-sqlite3 不支持，AI-107 踩坑）。
- **可移植**：无 DB 原生 enum；`score` 用 int、`weakPhonemes` 用 `simple-array`（database.config 注释确认可移植）。

## 4. 验收标准

- [ ] `ai_speech_attempts` 表由 `synchronize` 自动建立（`DataSource.initialize` 不抛错，CI seed 同等校验）。
- [ ] `record` 落库成功返回 `true`；`score` 越界被钳制（<0→0, >100→100, 小数→取整）；`weakPhonemes` 空/含空白被清洗。
- [ ] DB 写入失败时 `record` 返回 `false` 且不抛（best-effort）。
- [ ] `findByUser` 按 `createdAt` 倒序返回，`limit` 生效。
- [ ] `nest build` / `tsc` 0 错误；jest 全绿；覆盖率 90/70 基线不退化；pre-commit 质量门强执通过。

## 5. 风险点

- **时间列**：遵守铁律，避免 CI seed `DataTypeNotSupportedError`。
- **无硬 FK**：`userId` 不级联删 User（审计型追加记录，与 `AiCallLog` 同口径）；弱项完整性由 AI-306 业务层保证。
- **评分口径**：`score` 钳制到 [0,100] 在落库层兜底，即便上游（AI-305/306）已约束仍防越界脏数据。
- **不越界**：本 feature 仅建表 + 实体 + 落库服务，不实现评测/录音/页面（属 AI-302/303/306/307），不自创需求。
