# AI-305 — 发音评分策略（phoneme 级首选 + 相似度兜底）

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM) | 分支: feat/ai-305
> 依赖: AI-304(`AiTranscribeService.transcribe` 降级标注), AI-303(`AiSpeechEvaluatorService` 委托本服务), AI-101(`AiProvider` 契约) | 前置链: feat/ai-304
> 下游: AI-306(评分反馈 + 落库，消费本服务 `ScoredResult`), AI-307(`/speech` 消费评分)

## 1. 目标

为 M3「AI 每日口语训练」交付**统一发音评分策略编排层**：新增 `AiPronunciationScorerService.score()`，
对一次录音产出**统一 `ScoreResult`**（score ∈ [0,100]），并明确标注实际采用的策略：

- **首选**：`provider.assessPronunciation`（Azure Pronunciation Assessment，phoneme 级打分）。
- **兜底（无 Azure / 首选失败）**：`transcribe` 转写 → **编辑距离相似度** → `provider.chat` LLM 评估 → 综合 `ScoreResult`。

两种策略输出结构一致（`ScoreResult` + 扩展 `strategy`/`degraded`），供 AI-303 评测接口与 AI-306 反馈/落库统一消费。

## 2. 接口契约

### 2.1 纯逻辑层 `text-similarity.util.ts`（node 可测，对齐 AI-302/303/304 lib 模式）
- `levenshteinDistance(a, b): number` — 编辑距离（滚动数组 O(min(m,n)) 空间）。
- `similarityRatio(reference, transcript): number` — 对二者先 `normalizeTranscript`（复用 AI-304）后
  算 `(1 - dist/maxLen)`，clamp [0,1]（空 vs 空=1；一侧空=0）。
- `scoreFromSimilarity(ratio): number` — 映射到 [0,100]（round + clamp，含 0 下限）。
- `selectScoringStrategy({ strategy?, providerName? }): 'phoneme' | 'similarity'`
  — `strategy` 显式覆盖；否则 `providerName==='azure'` → `phoneme`，其余（bigmodel/nvidia/mock）→ `similarity`。
- `inferMascotExpr(score): MascotExpression` — ≥85 `happy`；≥60 `encourage`；否则 `thinking`（LLM 缺失兜底）。
- `parseLlmAssessment(text): { feedback?; weakPhonemes: string[]; mascotExpr? }`
  — 尝试从 LLM 文本抽取 `{feedback, weakPhonemes, mascotExpr}` JSON（容错：非 JSON / 解析失败 → 全文作 feedback，
  弱音素过滤非字符串、mascotExpr 非枚举值忽略）。
- `buildSimilarityFallbackFeedback(score, referenceText, transcript): string`
  — 无 LLM 时的三档中文鼓励文案（≥85 / ≥60 / 其余）。
- 零依赖纯函数（仅导入类型 + `normalizeTranscript`），便于 node 单测直覆。

### 2.2 服务 `AiPronunciationScorerService`
- 注入 `AI_PROVIDER_TOKEN`（`AiProvider`）+ `AiTranscribeService`（AI-304）。
- `async score(input: { audio: AudioInput; referenceText: string; opts?: AssessOptions & { strategy? } }): Promise<ScoredResult>`
  - `ScoredResult = ScoreResult & { strategy: 'phoneme'|'similarity'; degraded?: boolean }`
    （类型在 service 内定义，**不污染 `AiProvider` 接口契约 AI-101**）。
  - 流程：
    1. `selectScoringStrategy` → 决定首选路径。
    2. 首选 `phoneme`：`tryPhonemeScore` 调 `provider.assessPronunciation`，**包裹异常**（失败/返回非数字 → `null` 触发兜底）。
    3. 兜底 `similarity`：`transcriber.transcribe(audio)` → `similarityRatio(reference, transcript.text)`
       → `scoreFromSimilarity` → `provider.chat`（系统提示儿童老师 + 对比参考/转写/相似度）→ `parseLlmAssessment`
       提取 feedback/weakPhonemes/mascotExpr；**chat 抛错 → `buildSimilarityFallbackFeedback` 兜底**。
    4. `degraded = transcript.degraded || score < passLine`（无 Azure 或 phoneme 失败或低分均标记）。
- 用 `logger`，**无裸 console**；异常捕获后降级不抛错（与 AI-102/304 口径一致）。

### 2.3 改 `AiSpeechEvaluatorService`（AI-303）委托本服务
- 移除对 `AI_PROVIDER_TOKEN` 的直接注入（改由 scorer 内部编排），新增注入 `AiPronunciationScorerService`。
- `evaluate()` 末尾委托 `scorer.score({ audio, referenceText, opts: { passLine: 60 } })`，保留
  `validateSpeechUpload` 校验与 `resolveReferenceText`（wordId/sentenceId/直传）逻辑不变。
- 这样 AI-303 接口行为升级为「首选 phoneme / 无 Azure 兜底相似度」，评分策略在 AI-305 集中落地。

### 2.4 注册（AiModule，@Global）
- `providers` 加 `AiPronunciationScorerService`；`exports` 加 `AiPronunciationScorerService`（供 AI-306 注入）。
- 依赖均已模块内注册（`AI_PROVIDER_TOKEN` + `AiTranscribeService`），**不引入新 Repository 依赖**（守边界，不落库）。

## 3. 验收标准
- [ ] `auto` + `provider.name==='azure'` + phoneme 成功 → 返回 `strategy:'phoneme'` 且 score 来自 `assessPronunciation`。
- [ ] `auto` + 非 azure（bigmodel/mock/nvidia）→ 走 `similarity`（transcribe + chat），`strategy:'similarity'`。
- [ ] `auto` + azure 但 `assessPronunciation` 抛错 → 降级到 `similarity`（**不抛异常**）。
- [ ] `strategy:'similarity'` 显式 → 跳过 `assessPronunciation`，直接走兜底。
- [ ] transcribe 降级（空文本）→ 相似度 0 → 低分 + `degraded=true` + 友好反馈。
- [ ] LLM chat 返回合法 JSON → 解析出 `weakPhonemes` / `mascotExpr`；chat 抛错 → 走 `buildSimilarityFallbackFeedback`。
- [ ] `AiSpeechEvaluatorService` 委托 scorer：referenceText 解析后调 `scorer.score`（含 audio + referenceText + passLine）。
- [ ] `tsc --noEmit`(server) 0 错误；`nest build` 通过；`jest` 全绿；覆盖率 90/70 基线不退化。
- [ ] pre-commit 质量门强执通过。

## 4. 风险点
- **E2E 豁免（约束 #6）**：纯后端服务（无 HTTP 端点、无前端 UI；AI-303 评测接口是消费者）。
  按本项目「不为纯后端逻辑写 BDD」铁律豁免 BDD/E2E，验收由单元测全覆盖；用户级口语旅程随 AI-307 `/speech` 交付。
  与 AI-301 / AI-303 / AI-304 纯后端豁免同口径。
- **真实 Azure 未接入（边界）**：当前所有 provider（含 'azure' 名）均回退 `MockAiProvider`
  （AI-102/106 已定，无 key 不联网），`assessPronunciation` 返回 Mock 确定性分数。本项目**不硬接未配置真实端点**
  （无 key 无法验证，违反质量门）。scorer 的策略选择（`selectScoringStrategy`）已正确建模「azure→phoneme / 其他→similarity」，
  真实 Azure 接入时只需替换 provider 实现，scorer 无需改动；当前 Mock 下 `auto` 对 bigmodel/mock 自然走 similarity 兜底路径，
  保证两种策略均可测（phoneme 路径用 `strategy:'phoneme'` 强制 + fake provider 验证）。
- **不落库**：评分结果持久化在 AI-306（消费 AI-301 `ai_speech_attempts`），本 feature 不引入该依赖。
- **降级不抛错**：phoneme 失败 / chat 失败均降级标记，与 AI-102/304 既定降级口径一致，避免阻断上游评分流程。
