# AI-104 — MockProvider 扩展夹具（确定性假数据）

> 状态: done | 栈: node-ts (NestJS 10) | 分支: feat/ai-104 | 依赖: AI-101(done)；基线由 AI-103 建立

## 1. 目标
将 AI-103 建立的 `MockAiProvider` 基线**扩展为丰富、可信的确定性夹具**：`chat` 按意图返回固定「计划文本 / 报告文本 / 通用演示回复」，`assessPronunciation` 返回真实感假评分（非满分 + 弱音素），`transcribe` 返回示例句。使 **`AI_PROVIDER=mock` 时前端无需 key 即可跑通全流程演示**（plan / speech / report / chat 各场景都有像样的返回内容）。

## 2. 接口契约
复用 `AiProvider` 接口（`ai-provider.interface.ts`），**不改签名、不加方法**，仅丰富返回内容。

### 行为契约（新增意图识别，纯函数）
- `chat(messages)`：取最后一条 `user` 消息文本，小写化后做关键词匹配：
  - **计划意图**（命中 `计划|plan|学习计划|schedule|每日|周计划|学习方案|课程` 任一）→ 返回固定示例学习计划文本（`[Mock 计划]` 前缀）。
  - **报告意图**（命中 `报告|report|小结|日报|总结|summary|今日|今日小结` 任一）→ 返回固定示例每日小结文本（`[Mock 今日小结]` 前缀）。
  - **通用** → 返回固定演示回复（`[Mock]` 前缀）。
  - 空消息 → 返回通用演示回复（不崩溃）。
- `assessPronunciation(_audio, referenceText)`：返回 **score=88**（非满分，演示弱项高亮）、`readableText=referenceText`、`weakPhonemes=['θ','v']`、`feedback='[Mock] 很接近啦！注意 th 和 v 的发音～'`、`mascotExpr='encourage'`（确定性，不随机）。
- `transcribe`：返回示例句 `'[Mock] I see a red apple on the table.'`，`confidence=1`。
- `chatWithImage` / `synthesize`：保持 AI-103 的演示占位（已满足演示需求，不在本 feature 改动）。

## 3. 数据模型
无（不新增实体/表）。

## 4. 验收标准
- [ ] `AI_PROVIDER=mock`（或缺省）下 `chat` 对计划/报告/通用三类输入分别返回对应固定文本。
- [ ] `assessPronunciation` 返回 score=88 且含 weakPhonemes（演示弱音素高亮与 encourage 表情）。
- [ ] `transcribe` 返回可读示例句。
- [ ] 内容与返回类型严格符合 `AiProvider` 接口；`name` 仍为 `'mock'`。
- [ ] 不依赖任何外部 API / key；结果完全确定性（同输入同输出，便于单测）。

## 5. 风险点
- **不与未来 schema 耦合**：AI-203/AI-204 才会定义真实 plan JSON Schema。本 feature 的 `chat` 夹具**只返回可读演示文本**（非最终 JSON 结构），避免伪造未定稿 schema 误导消费方；未来 AI-202 解析失败会走 AI-204 降级模板，演示模式不受影响。
- **边界**：意图识别为纯关键词子集匹配，命中即分类；未命中统一走「通用」。无外部 IO，不可能抛网络异常。
