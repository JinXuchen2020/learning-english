# AI-106 · 重试与降级

> 状态: done | 栈: node-ts (NestJS 10) | 分支: feat/ai-106 (建在 feat/ai-105 之上) | 依赖: AI-103(done)；前置已具备 BigModelProvider(AI-102)/AiConfig(AI-105)

## 1. 目标
为 **provider 调用层** 增加统一的「瞬时错误重试 + 并发保护 + 错误归一化」，使所有消费方（AI-202/303/304/402/502/601）免费获得韧性，无需各自写 try/catch 重试。

- `chat` / `chatWithImage`（真实网络调用）包 3 次指数退避重试。
- 超时（默认 60s，推理模型）、网络错误、`429 限流`、`5xx` 视为**瞬时错误** → 退避重试。
- `401/403` 鉴权失败、NVIDIA `404 Function not found for account` → 识别为**账户权限错误**（`AiAccessError`），**不重试**，给出明确文案。
- 其余 4xx（含 BigModel 结构异常 `502`）→ **永久错误**，不重试。
- **并发保护**：`chat/chatWithImage` 经信号量限流（默认并发上限 4），避免自伤式触发 `429`（对应 backlog「降低并发」）。

## 2. 设计

### 2.1 错误分类 `server/src/ai/ai-retry.ts`
- `classifyError(err)` → `'retryable' | 'access' | 'permanent'`：
  - `AiAccessError` 实例 → `access`
  - `AiProviderException`：
    - `statusCode` ∈ {401,403} → `access`（鉴权/权限）
    - `statusCode===404 && (code==='FUNCTION_NOT_FOUND' || message 含 "Function not found for account")` → `access`（NVIDIA 账户权限）
    - `statusCode===429` → `retryable`（限流）
    - `statusCode∈{0,504}` → `retryable`（网络/超时）
    - `500<=statusCode<600 && statusCode!==502` → `retryable`（网关 5xx 瞬时）
    - 其余（4xx 非上述、BigModel 结构异常 `502`）→ `permanent`
  - 非 `AiProviderException` 的未知错误 → `permanent`（不盲目重试裸 Error）
- `withRetry<T>(fn, options?)`：循环 `maxAttempts` 次，仅当 `classifyError` 为 `retryable` 时退避重试；`access`/`permanent` 立即抛出；耗尽后抛**最后一次错误**（保留原始 `statusCode/code`，可识别）。
- `normalizeError(err)`：`access` 类非 `AiAccessError` 归一为 `AiAccessError`；其它 `AiProviderException` 原样返回；裸 Error 包成 `AiProviderException`。保证上层永远拿到可识别异常。
- `DEFAULT_RETRY_OPTIONS`：`maxAttempts=3`、`baseDelayMs=400`、`maxDelayMs=8000`、`factor=2`、`delay` 默认 `setTimeout`（可注入做无等待测试）。

### 2.2 并发限制 `server/src/ai/concurrency-limiter.ts`
- `ConcurrencyLimiter(max=4)`：Promise 信号量，`run(fn)` 在 `<max` 时立即执行，否则入队；`finally` 中 `release` 唤醒队首。
- 满足 backlog「降低并发」：固定上限避免自伤式 `429`；**自适应收缩**（命中 429 后动态调小 `max`）留作后续增强，本 feature 仅提供固定上限能力（已在 §6 标注）。

### 2.3 包装器 `server/src/ai/retryable-ai-provider.ts`
- `RetryableAiProvider implements AiProvider`：构造注入 `inner: AiProvider` + 重试选项 + 限流器。
  - `chat` / `chatWithImage` → `limiter.run(() => withRetry(() => inner.xxx(...)))`（网络调用才重试+限流）
  - `transcribe` / `assessPronunciation` / `synthesize` → 直接 `inner.xxx(...)`（本地/降级方法，无网络，不重试）
  - `get name()` 透传 `inner.name`
- `createRetryableProvider(inner, retryOptions?, limiter?)` 工厂。

### 2.4 接入 `ai.module.ts`
- `createAiProvider` 仍按 `AI_PROVIDER` 选 `inner`，最后 `return createRetryableProvider(inner)`。
- 重试选项 / 并发上限走**代码内常量默认值**（不新增 env 变量、不碰 `.env.example`/`.gitignore`，与 AI-105 边界一致；未来可由 AI-107 配额/外部化配置接管）。

### 2.5 `AiAccessError`（`bigmodel.provider.ts`）
- 新增 `AiAccessError extends AiProviderException`（`name='AiAccessError'`）。
- `BigModelProvider.throwOnError` 的 `401/403` 分支改为抛 `AiAccessError`，文案含「账户权限问题（key 无效或过期）」且保留「鉴权失败」子串（兼容既有测试）。

## 3. 边界（不越界）
- 不新增 env 变量 / 不改 `.env.example` / 不碰 `.gitignore`（AI-105 已覆盖密钥不进 git）。
- 不新建 provider 类；不改 `AiProvider` 接口签名；不实现 NvidiaProvider（仅分类支持其错误码）。
- 不接额度（`ai_usage` 表，AI-107）与调用日志（AI-108）；重试/限流**不**写库。
- 重试/限流对 `MockAiProvider` 透明（其方法永不动网络、永不抛错）。
