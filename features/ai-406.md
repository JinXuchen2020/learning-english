# AI-406 内容安全双保险（对话陪练）

> 里程碑：M4 对话陪练 · 依赖：AI-403（聊天接口）/ AI-405（场景包） · 优先级：P0
> 状态：doing · 分支：`feat/ai-406`

## 1. 目标

为儿童英文陪练对话（`POST /api/ai/chat/messages`）加一道**内容安全双保险**，在文本送入 LLM 之前拦截不适合 5-10 岁小朋友的内容，命中时返回狐狸吉祥物的**安全兜底回复**（不调用 LLM，不暴露拦截细节）。

双保险 = 两层串联闸门：

1. **关键词黑名单（同步，第一道硬闸）**：命中即拦，零网络开销、必然生效。
2. **NVIDIA 内容安全分类器（异步，语义兜底）**：调用 `nvidia/llama-3.1-nemoguard-8b-content-safety` 把用户文本二分类为 safe/unsafe，兜住黑名单漏掉的语义有害内容（如绕过关键词的隐晦表达）。

## 2. 范围

- **本 feature 做**：
  - `chat-safety.config.ts`：启发式黑名单（脏话/色情、暴力/自伤、违禁品、仇恨辱骂、提示词注入，中英文）+ 安全兜底回复常量。
  - `chat-safety.classifier.ts`：`SafetyClassifier` 接口 + `NvidiaSafetyClassifier`（HTTP 调 NVIDIA NIM，可注入 `FetchFn` 便于测试）。
  - `chat-safety.service.ts`：`ChatSafetyService.checkUserInput(text)`，串联黑名单 + 分类器，返回 `SafetyVerdict { safe, reason? }`。
  - `chat.service.ts`：注入 `ChatSafetyService`，在 LLM 调用**之前**检查；不安全 → 直接返回安全兜底回复（含 TTS）。
  - `chat.module.ts`：装配 `SAFETY_CLASSIFIER_TOKEN`（NVIDIA 配置来自 `ConfigService` 的 `NVIDIA_*`）+ `ChatSafetyService`。

- **不做（越界）**：
  - 输出侧过滤（对已生成回复再过滤）——本 feature 仅守输入；LLM 侧已有 `BASE_SAFETY_RULE` 软约束。输出硬过滤留待后续 hardening（不在 M4 范围）。
  - 把命中内容写入独立审计表——仅 `logger.warn` 记录 sessionId/原因，`ai_call_logs`（AI-108）不因此新增字段。
  - 越权/鉴权——保持 `anonymous`（与 AI-403 一致，鉴权 deferred）。

## 3. 设计要点

### 3.1 黑名单匹配（启发式，第一道闸）
- 归一化：文本与关键词均 `toLowerCase()` + 去除空白 + 去除非字母数字/非 CJK 标点，再做 `includes` 子串匹配。
  - 中文关键词（如 `暴力`）在 `好暴力啊` 中能命中；英文（如 `shit`）在 `you shit` 中命中。
  - 选用无歧义词条（不放 `ass` 等会误伤 `class` 的短词）降低误伤。
- 命中返回命中词条，reason=`blocklist`。
- 黑名单为**可扩展常量数组**，注释说明启发式性质与误伤取舍。

### 3.2 NVIDIA 分类器（语义兜底，fail-open）
- 请求：`POST {NVIDIA_BASE_URL}/chat/completions`，`model=NVIDIA_SAFETY_MODEL`（默认 `nvidia/llama-3.1-nemoguard-8b-content-safety`），messages=`[{user: 文本}, {assistant: ''}]`，`temperature:0, max_tokens:8`。
- 判定：响应 `choices[0].message.content` 含 `unsafe`（不区分大小写）→ 不安全（reason=`classifier`）；否则安全。
- **fail-open（降级放行）** 的三种情况，避免安全服务异常时全站不可用，且黑名单仍是硬闸：
  1. `NVIDIA_API_KEY` 未配置 → 放行，打一次告警（仅黑名单生效）；
  2. HTTP 非 2xx → 放行 + warn；
  3. 网络/超时/解析异常 → 放行 + warn。
- 超时默认 10s（`AbortSignal.timeout`）。

### 3.3 ChatService 集成
```
sendMessage(dto):
  userId = dto.userId ?? anonymous
  session = resolveSession(dto, userId)          // 含 404 分支
  verdict = await safety.checkUserInput(dto.text) // 双保险
  if !verdict.safe:
    replyText = SAFE_FALLBACK_REPLY
    logger.warn(`[ChatService] 内容安全命中(${verdict.reason}) session=${session.id}`)
  else:
    history = loadHistory(session.id)
    messages = [system, ...history, user]
    replyText = (await generateReply(messages)).text
  // 统一落库 user + assistant，再合成 TTS（兜底回复同样 TTS）
  persist(user, assistant(replyText))
  ttsUrl = synthesizeTtsUrl(replyText)
  return { sessionId, messageId, replyText, ttsUrl }
```
- 不安全时**不调用 LLM**（`provider.chat` 不被调用），降低风险与成本。
- 仍落库 user + 助手安全兜底消息，保持会话线程连续（前端可正常展示一次温柔带离）。
- 响应形状 `{ sessionId, messageId, replyText, ttsUrl }` 不变，前端无需改契约。

## 4. 注入与可测性

- `SAFETY_CLASSIFIER_TOKEN = 'CHAT_SAFETY_CLASSIFIER'`：`ChatSafetyService` 经此 token 注入 `SafetyClassifier`。
- `NvidiaSafetyClassifier` 构造接受 `{ apiKey, baseUrl, model, timeoutMs }` + 可注入 `FetchFn`，默认读 `process.env.NVIDIA_*`，与 `BigModelProvider` 同构。
- 模块单测：`TestProviderModule` 额外提供 `SAFETY_CLASSIFIER_TOKEN`（mock 放行），`ChatModule` 自身提供 `ChatSafetyService`。

## 5. 测试策略（纯后端，E2E 豁免，约束 #6）

- `chat-safety.classifier.spec.ts`：假 `fetchFn` 覆盖——安全返回 / 不安全返回 / 无 key → fail-open 放行 / 非 2xx → fail-open / 抛错 → fail-open。
- `chat-safety.service.spec.ts`：黑名单命中（含提示词注入词）/ 分类器 mock 命中 / 双安全 / 空文本安全 / 黑名单优先于分类器。
- `chat.service.spec.ts`：注入 mock safety；新增「不安全 → 返回安全兜底且 `provider.chat` 不被调用」；既有 11 case 兼容（默认安全 mock）。
