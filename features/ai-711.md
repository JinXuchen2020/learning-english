# AI-711 — 每孩独立 AI provider 覆盖

> 状态: done | 栈: node-ts（NestJS 后端 + Next.js 前端，全栈） | 分支: feat/ai-711
> 来源: `features/backlog.md` M8 / AI-711；用户设想：家长可为每个孩子单独选 AI provider（不共享家长默认）。
> **确认 (2026-08-13)**：实现完成并通过四道质量门。后端 2 端点（`PUT .../provider`、`GET .../provider-options`）+ `resolveForChild` + `AiProviderRouter` 按 role 分流 + 多层降级；前端 ChildrenSection 每行 provider 下拉 + override 徽标；单测 + BDD/E2E 已编写。质量门报告：`docs/quality/ai-711-gate.md`。

## 1. 目标

在 AI-705（家长级默认 provider）+ AI-710（家庭绑定）之上，支持**每个孩子单独指定 provider**：

- 家长在「我的孩子」列表里，给某个孩子选一个自己名下的 provider 配置（智谱 / OpenAI / DeepSeek …），或留空「沿用家长默认」。
- 孩子发 AI 请求时：先查自己的 `childProviderConfigId` → 命中则用该配置；未命中则回退家长 `isDefault`（AI-705 既有逻辑）。
- 实现「老大用 DeepSeek、老二用智谱」这类多孩子异构配置。

> 本 feature 是**可选增强**：若家庭只用单一 provider，AI-710 已足够，可不实施本 feature。

## 2. 接口契约

### 2.1 后端（挂 `ParentGuard`，并校验目标 config 归属该家长）

| 方法 | 路径 | 说明 | 请求体 / 参数 | 响应 |
|---|---|---|---|---|
| PUT | `/parent/children/:childId/provider` | 设置 / 清除孩子的 provider 覆盖 | `SetChildProviderDto { providerConfigId: string \| null }` | `ChildView`（含 `hasProviderOverride`） |
| GET | `/parent/children/:childId/provider-options` | 列出家长名下可选 provider（供前端下拉） | — | `ProviderConfigView[]`（同 AI-705，掩码） |

- `SetChildProviderDto.providerConfigId`：
  - `null` / 省略 → 清除覆盖，孩子回退家长默认。
  - 非 null → 必须是该家长 `ownerUserId` 名下的 `provider_configs.id`，否则 403/404（禁止把孩子指到他人配置）。
- 复用 AI-705 `ProviderConfigService.resolveDefault` 之外的 `requireOwned` 校验归属。

### 2.2 前端

- 「我的孩子」列表每行增加 provider 下拉：选项 = 「沿用家长默认」+ 家长各 provider 配置名（`ProviderConfigView.masked` 提示）。
- 选择即 `PUT /parent/children/:childId/provider`，成功后该行显示「独立配置 / 沿用默认」徽标（`hasProviderOverride`）。

## 3. 数据模型

### 3.1 `User` 新增可空列（`server/src/entities/user.entity.ts`）
```ts
@Column({ type: 'uuid', nullable: true })
childProviderConfigId: string | null;
```
引用 `provider_configs.id`（不建物理外键，应用层校验归属）。向前兼容：初始全 null → 回退家长默认（零回归）。

### 3.2 路由层覆盖（改 `AiProviderRouter` / `ProviderConfigService`）

- `ProviderConfigService` 新增 `resolveForChild(childId)`：
  - 查 `User.childProviderConfigId`；非空且配置存在 → 返回该 `ProviderConfig`；
  - 否则走现有 `resolveEffectiveParentId` → `resolveDefault(parentId)`（家长默认）。
- `AiProviderRouter.resolve()` 在 `userId` 对应 child 时优先调 `resolveForChild`，命中则 `buildProvider`；未命中无缝回退既有 parent 默认逻辑。
- **失败 / 配置删除后悬空** → 回退家长默认 → 再回退 env 默认（多层安全降级，绝不抛启动错误）。

## 4. 与 AI-705 / AI-710 的衔接

- 依赖 AI-705 的 `ProviderConfig` + `AiProviderRouter` 已就绪。
- 依赖 AI-710 的孩子已 `parentId` 归属家长，本 feature 才能拿到「家长默认」作回退基准。
- `provider_configs` 表与 `database.config.ts` appEntities 已在 AI-705 登记，本 feature 不新增实体注册。

### 6.1 单元测试
- `provider-config.service.spec.ts` 增：`resolveForChild` 命中 child 覆盖 → 返回该配置；`childProviderConfigId` null → 回退家长默认；配置已删 → 回退。

### 6.2 BDD/E2E
- 场景：家长配 2 个 provider（A/B）→ 建 2 孩子 → 孩子1 指定 A、孩子2 指定 B → 分别登录发消息 → 断言各自落到 A/B mock 端点 → 孩子1 改回「沿用默认」→ 断言回退家长默认 → 删除 B → 孩子2 自动回退默认。

## 7. 风险点

| 风险 | 缓解 |
|---|---|
| 孩子指到他人 provider | `providerConfigId` 必须 `requireOwned` 校验归属 |
| 配置删除后悬空 | `resolveForChild` 配置不存在 → 回退家长默认，不抛错 |
| 多层降级复杂度 | 三层回退（child 覆盖 → 家长默认 → env 默认），每层异常独立捕获 |
| 新列漏同步 | 仅加一列，TypeORM `synchronize`/迁移；不改 appEntities（非新实体） |
