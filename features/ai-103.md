# AI-103 — AiModule 动态装配

> 状态: done | 栈: node-ts (NestJS 10) | 分支: feat/ai-103 | 依赖: AI-102(done)

## 1. 目标
把 `BigModelProvider`（AI-102）与 `MockAiProvider` 通过 NestJS 依赖注入**按 `.env` 的 `AI_PROVIDER` 动态装配**，业务模块只需 `@Inject(AI_PROVIDER_TOKEN)` 拿到 `AiProvider` 抽象，完全不绑定厂商。实现「无 key 时应用可启动」「切换 provider 只改 env 一处」。

## 2. 接口契约
### 后端（DI 装配）
- 注入 token：`AI_PROVIDER_TOKEN = 'AI_PROVIDER'`（`ai-provider.interface.ts` 已定义）。
- 工厂函数 `createAiProvider(config: ConfigService): AiProvider`（导出自 `ai.module.ts`）：
  | `AI_PROVIDER` 取值 | 注册实现 | 说明 |
  |---|---|---|
  | `bigmodel` | `BigModelProvider` | 读 `BIGMODEL_API_KEY/BASE_URL/MODEL/VISION_MODEL`（走 ConfigService，缺失则 provider 自身回落 env） |
  | `mock` / 缺失 / 未知 | `MockAiProvider` | 确定性假数据，保证无 key 可启动（默认值） |
  | `nvidia` / `azure` | `MockAiProvider`（告警） | 对应 provider 尚未实现，回退 mock 避免启动失败，打 `logger.warn` |
- `AiModule` 标 `@Global()`：AI 能力被 plan/speech/conversation/report 等多模块复用，全局注入免去每个消费方重复 import（与 `ConfigModule.forRoot({isGlobal:true})` 同一思路）。
- `AppModule` 新增 `imports: [AiModule]`。

### 前端
无（纯后端 DI 基建，不影响前端契约）。

## 3. 数据模型
无新增实体/表。

## 4. 验收标准
- [ ] `npm run build` / `tsc --noEmit` 通过，`AppModule` 能完成 Nest 上下文装配（DI 不报错）。
- [ ] `AI_PROVIDER=bigmodel` → 注入实例 `name === 'bigmodel'`（BigModelProvider）。
- [ ] `AI_PROVIDER` 缺失 / `mock` / 未知 / `nvidia` / `azure` → 注入实例 `name === 'mock'`（MockAiProvider），应用照常启动。
- [ ] 业务模块 `@Inject(AI_PROVIDER_TOKEN)` 取到 `AiProvider`，无 key 也能 boot。
- [ ] provider 切换只改 `.env` 的 `AI_PROVIDER` 一处，无需改代码。

## 5. 风险点
- **未实现 provider 误配**：`nvidia`/`azure` 暂未实现 → 回退 mock + `logger.warn`，避免启动崩溃（已在设计内缓解）。
- **ConfigService 全局可用性**：`ConfigModule.forRoot({isGlobal:true})` 已在 `AppModule`，`useFactory` 的 `inject:[ConfigService]` 可解析；若将来有人把它改成非 global，需在 `AiModule` 补 `imports:[ConfigModule]`。
- **与 AI-104 边界**：本 feature 建立的 `MockAiProvider` 是「确定性假数据基线」，已能满足 AI-103 的「无 key 可启动」。AI-104（MockProvider 更丰富的固定 plan/报告夹具）可在此基础上扩展同一文件，**不重复造类**；本 feature 不标记 AI-104 完成，由其单独排期。
- **不越界**：不改 `.env.example`（AI-105 负责，且 `AI_PROVIDER` 已存在于 .env.example）；不接重试/降级（AI-106）；不写任何具体业务调用。

## 6. 测试计划（硬约束 #6）

- `ai.factory.spec.ts`：`createAiProvider` 对 `AI_PROVIDER` 各取值（bigmodel / mock / 缺失 / 未知 / nvidia / azure）返回正确 provider 实例；未实现 provider 路径触发 warn（用 spy 验证）。

- **豁免（显式）**：AI-103 是 headless DI 基建，无独立 HTTP 端点、无前端 UI、无用户可感知旅程，符合硬约束 #6「不为纯后端 API 写 BDD」。其端到端行为由消费方 feature 自带（AI-202 `/plan` generate、AI-303/AI-304 口语、AI-402 TTS、AI-606 拍照学单词），届时通过真实注入的 `AiProvider` 验证整条链路。设计文档显式标注此豁免，质量报告载明。
