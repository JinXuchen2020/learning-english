# AI-206 — 计划持久化与"应用计划"

> 状态: in-progress | 栈: node-ts (NestJS + TypeORM) | 分支: feat/ai-206 | 依赖: AI-201, AI-202, AI-204, 现有 TasksModule

## 1. 目标
把 AI-202 生成的「内存计划」落库为可复用的 `StudyPlan` 草稿，并提供「应用计划」接口：
将计划置为 `applied`，按天把计划任务写入现有 `daily_tasks` 表，使孩子首页「每日任务列表」出现对应任务。
支持「重复应用提示确认」，避免误覆盖。

## 2. 接口契约
### 后端
- `POST /api/ai/plan/save`
  - body `SavePlanDto`: `{ childId: uuid(v4), plan: GeneratedPlan }`
  - 服务端用 AI-204 的 `validatePlan` 校验 `plan` 结构；不合法 → 400（含 `errors`）。
  - 落库 `study_plans`(status=`draft`) + `study_plan_days`(cascade)，返回 `{ id: uuid, status: 'draft' }`。
- `POST /api/ai/plan/:id/apply`
  - body `ApplyPlanDto`: `{ confirm?: boolean }`（可选）
  - 找不到计划 → 404 `{ code:'PLAN_NOT_FOUND' }`
  - 计划已 `applied` 且 `confirm!==true` → 409 `{ code:'PLAN_ALREADY_APPLIED', needsConfirm:true, message }`（前端据此弹确认）
  - 否则：置 `status='applied'`；按 `dayIndex` 从今天起填 `study_plan_days.date`；按天写入 `daily_tasks`（userId/planDayId/date），旧任务先清后写；返回 `{ id, status:'applied', appliedDays, tasksCreated, appliedAt }`。
- 鉴权：**本 feature 不引入 `JwtAuthGuard`**（沿用 AI-202 的 `childId` 由 body 传入契约；apply 接口补鉴权按计划文档留待后续，标记为 deferred 项）。

### 前端（本 feature 不实现页面，仅契约；页面属 AI-207/208）
- 生成 → 调用 `save` 拿 id → 调用 `apply(id)`；若 409 needsConfirm → 弹确认后带 `confirm:true` 重调。

## 3. 数据模型
- `daily_tasks` 扩展（`DailyTask` 实体，向后兼容现有全局种子任务）：
  - `userId: varchar(255) NULL` — 计划任务归属用户；种子任务为 NULL（对所有人可见）。
  - `planDayId: varchar(255) NULL + Index` — 关联 `study_plan_days.id`，用于重应用时清理。
  - `date: varchar(10) NULL` — `YYYY-MM-DD`，计划日当天；用于 `getDailyTasks` 仅当天展示。
- `study_plan_days.date` 由本 feature 在 apply 时填充（草稿期为空）。
- 写入策略：复用 `TasksService`，新增 `replacePlanTasks(userId, planDayIds, entries)`（先 `delete userId+planDayId IN(...)` 再批量 `save`），避免重应用产生重复任务；`TaskCompletion` 经 `onDelete CASCADE` 自动清理。

## 4. 验收标准
- [ ] `save` 合法 plan → 落库 draft + 返回 id；非法 plan → 400。
- [ ] `apply` 找不到 → 404；draft → 置 applied + daily_tasks 出现该用户当日任务。
- [ ] `apply` 已 applied 且未 confirm → 409 needsConfirm；confirm=true → 重应用（任务先清后写，无重复）。
- [ ] `getDailyTasks(userId)` 返回「全局种子 + 该用户当日计划任务」，完成态仍正确。
- [ ] 多用户隔离：A 的计划任务不出现在 B 的列表。

## 5. 风险点
- **多租户隔离**：`daily_tasks` 原是全局目录，写计划任务必须带 `userId` 且 `getDailyTasks` 按 `userId IS NULL`（全局）+ `userId=该用户 AND date=今天`（计划）合并，否则会泄漏给其他用户。→ 已按 Q2 决策实现。
- **重应用重复任务**：用 `planDayId` 先清后写，杜绝重复。
- **日期漂移**：`date` 用 UTC `YYYY-MM-DD`（`date.toISOString().split('T')[0]`），与 `TaskCompletion`/`getDailyTasks` 的 today 口径一致。
