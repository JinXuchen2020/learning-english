# AI-703 — 测验变体扩展（听音选图 + 组词）

> 状态: done | 栈: node-ts (NestJS 10 + Next.js 14 + better-sqlite3) | 分支: feat/ai-703

## 1. 目标

给 `/practice` 单词练习增加两种全新测验模式，丰富儿童识记方式：

- **听音选图（listen）**：音频优先、隐藏文字，孩子听单词发音后从 4 张插图中选出正确的一张。
- **组词（combination）**：颜色 + 物品类别组合，展示「颜色块 + 类别词」，孩子从候选插图中选出同时匹配该颜色与该类别的那个单词。

两种模式与既有「看字选词」多选项并存，可在练习页顶部一键切换。出题与判定为**纯前端逻辑**（`src/lib/quizVariants.ts`），附单元测试。

## 2. 接口契约

### 后端（数据模型扩展，无新接口）

- `GET /words` 与 `GET /lessons/:id/words` 返回 `Word` 新增两个可空字段 `category`、`color`（受 TypeORM 实体字段自动同步进 `words` 表，better-sqlite3 synchronize 模式无需手写迁移）。
- 无新路由 / DTO；复用现有 WordsModule。

### 前端

- `src/lib/types.ts` 的 `Word` 增加 `category?: string | null`、`color?: string | null`。
- `src/lib/quizVariants.ts` 导出：
  - 类型：`QuizMode`、`ListenQuestion`、`CombinationQuestion`、`QuizItem`。
  - `generateListenQuestions(words, opts?)` → `ListenQuestion[]`
  - `judgeListen(q, selectedIndex)` → `boolean`
  - `generateCombinationQuestions(words, opts?)` → `CombinationQuestion[]`（仅对 (color,category) 在词池中唯一的单词出题；缺 color/category 的单词被跳过）
  - `judgeCombination(q, selectedIndex)` → `boolean`
  - `buildQuizItems(words, mode, opts?)` → `QuizItem[]`（把三种模式统一为组件可消费的题项）
  - 工具：`shuffle`、`pickDistinct`（均接受可注入 `rng` 以便测试确定性）
- `src/app/practice/page.tsx` 的 `Quiz` 改为消费 `QuizItem[]`；顶部新增模式切换器（`data-component="ModeSwitcher"`，按钮 `data-action="mode-multiple|mode-listen|mode-combination"`）；答案按钮统一带 `data-answer-correct` 属性；支持 `?mode=` 查询参数预设模式。

## 3. 数据模型

`server/src/entities/word.entity.ts` 在 `Word` 实体新增两列（遵循项目约定：nullable 必须显式 `type`）：

```ts
@Column({ type: 'varchar', nullable: true })
category: string | null;

@Column({ type: 'varchar', nullable: true })
color: string | null;
```

`server/src/seed.ts` 给 10 个动物单词分配唯一 `(color, category)` 组合（用于组词模式唯一判定）：

| 单词 | color | category |
|---|---|---|
| Cat | orange | pet |
| Dog | brown | pet |
| Fish | blue | ocean |
| Bird | blue | sky |
| Rabbit | white | pet |
| Frog | green | pond |
| Horse | brown | farm |
| Duck | yellow | pond |
| Bear | brown | forest |
| Turtle | green | beach |

> 既有 `options`/`correctIndex`（看字选词用）保持不变。

## 4. 验收标准

- [ ] `Word` 实体含 `category`/`color` 两列，synchronize 后 `words` 表出现对应列；后端接口返回包含这两字段。
- [ ] `/practice` 顶部可切换到「听音选图」「组词」两种新模式，且与「看字选词」互不串扰。
- [ ] 听音选图：提示词文字默认隐藏，有「听一听」朗读按钮；选项正确判定（`index===correctIndex`）。
- [ ] 组词：展示颜色块 + 类别词；每张题仅有一个正确选项（组合合法/唯一），判定正确。
- [ ] 出题 / 判定纯函数有单测覆盖（正常 / 边界 / 异常分支）。
- [ ] 新增 BDD/E2E 场景覆盖两种模式的用户旅程（含前端 UI 行为）。
- [ ] `tsc --noEmit` 类型检查、`vitest run`、E2E 全部通过。

## 5. 风险点

- **组词唯一性**：若词池中存在相同 `(color,category)` 的多个单词，会产生歧义题。`generateCombinationQuestions` 按「目标组合在词池中唯一」过滤，跳过歧义/缺字段单词（单测覆盖此分支）。
- **听音模式无真实音频文件**：用浏览器 Web Speech API（`speechSynthesis`）朗读 `word.text`；缺失该 API 的环境静默降级（按钮仍在，不影响选图作答）。
- **旧单词缺 category/color**：前端类型设为可空，`buildQuizItems` 的 combination 分支自动过滤，不会崩。
- **契约对齐**：后端新增字段经 synchronize 自动随实体返回；前端类型补充对应可空字段，无需改 DTO。

## 6. 测试计划（硬约束 #6）

### 单元测试（前端纯逻辑模块 `src/lib/quizVariants.ts`）

- `generateListenQuestions`：
  - 正常：4+ 词 → 每词一题；正确选项位置经 shuffle 后指向目标；干扰项与目标不同；题目数 = 词数。
  - 边界：词数 < 2 → 返回 `[]`（无法构成含干扰项的题）；恰好 4 词 → 单题 4 选项；注入确定性 `rng` 验证可复现。
- `generateCombinationQuestions`：
  - 正常：唯一 `(color,category)` 的单词被出题，正确项唯一。
  - 边界：单词缺 `color`/`category` → 被跳过；存在 `(color,category)` 重复 → 该组合不出题（歧义过滤）；无合法单词 → `[]`。
- `judgeListen` / `judgeCombination`：命中/未命中分别返回 `true`/`false`；越界 index 返回 `false`（防御）。
- `buildQuizItems`：三种模式分别产出正确 `optionKind` 与 `correctIndex`；`multiple` 保留 `word.options` 文本；`listen`/`combination` 用插图选项并隐藏/展示对应提示。

### BDD/E2E 用户旅程

- `src/e2e/features/practice-variants.feature`：
  - 场景「听音选图」：登录 → 进课程 → 进第一节课 → 切到 listen 模式 → 全对作答 → 见完成页「Amazing Job!」。
  - 场景「组词」：同上流程 → 切到 combination 模式 → 见到颜色块提示（`data-component="ComboPrompt"`）→ 全对作答 → 完成。
  - 不为纯 API 写 BDD；覆盖真实 UI 行为（模式切换、插图作答、完成庆祝）。
