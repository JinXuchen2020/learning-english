# LOG-101 — 统一日志基建 (Logger + 日志文件)

> 状态: in-progress | 栈: node-ts (Next.js 14 + NestJS 10 + TypeORM) | 分支: feat/log-101-logger

## 1. 目标

移除应用生产代码中的裸 `console.error / console.log / ...` 调用，统一接入 **Logger**；后端日志落地为按日期滚动的文件 `server/logs/app-YYYY-MM-DD.log`，并提供 `POST /api/log` 接口接收前端日志、汇总进同一份文件，方便排障。约定：**之后所有新 feature 仅允许用 Logger（禁用裸 console）**。顺带修复 `src/lib/api.ts` 的 `let body: any = null` 类型。

## 2. 接口契约

### 后端

- `POST /api/log`（`LogsController`，全局前缀 `api`）
  - 请求体（`LogEnvelopeDto`，class-validator 校验）：
    - `level: 'error' | 'warn' | 'info' | 'debug'`（必填，枚举）
    - `message: string`（必填，非空）
    - `meta?: unknown`（可选，原样序列化进日志）
  - 响应：`201 { ok: true }`；非法 envelope → `400`
  - 行为：调用 `logger.write(level, message, meta)` 写入**同一日志文件**（与后端自身日志同一份）。
- **Logger 文件**：`server/logs/app-<YYYY-MM-DD>.log`，单行格式 `[<ISO时间戳>] [<LEVEL>] <message> <metaJSON?>`；异步 append（`best-effort`，写失败不崩应用）；同时镜像到 `console` 对应级别（`error→console.error` / `warn→console.warn` / `debug→console.debug` / 其它→`console.log`）。

### 前端

- `src/lib/logger.ts` 导出 `logger`：`error/warn/info/debug(msg, meta?)` 封装 console 镜像 + `best-effort` `POST ${API_BASE}/log`（仅浏览器环境且 `fetch` 可用时转发；转发失败静默；**绝不**递归用 logger 记录转发失败）。
- `src/lib/api.ts`：导出 `API_BASE`（供 logger 复用）；`let body: any = null` → 精确类型（联合 `ParsedBody | string | null`，其中解析成功为 `unknown`、解析失败保留原文 `string`），并收窄错误 `message` 类型，消除 `any`。

## 3. 数据模型

无新表。仅文件系统：`server/logs/` 按日滚动文本日志（`*.log` 已被 `.gitignore` 忽略，不入库）。

## 5. 风险点

- **浏览器不能写文件**：前端日志经 `POST /api/log` 由后端落盘，前后端日志汇总一处。前端转发 `best-effort`，绝不因日志失败影响业务。
- **E2E 夹具 console**：`src/e2e/**` 的 console 属测试基础设施（向 CI 输出吐浏览器报错），不在本次范围，且已被质量门扫描 `--exclude src/e2e` 排除。
- **better-sqlite3 原生绑定**：CI ubuntu 由 `npm ci` 现编；本地 Windows 若失效需 `npm rebuild`（已知坑）。
- **新增前端单测 runner**：项目此前无前端单测框架；为落实「前端纯逻辑模块需单测」约定，引入 `vitest`（devDependency）+ `test:unit` 脚本 + CI `frontend-unit` job。

### 单元测试

- 后端 `server/src/common/logger/logger.spec.ts`：`serializeMeta`（Error / 带 cause / 循环引用 / 数组 / 嵌套对象 / 原始值 / null-undefined）、`formatLine`（有/无 meta）、`createLogger` 写文件（临时目录）、级别过滤（`minLevel`）、写失败 best-effort（无效目录 catch 不抛）、单例 `logger` 调用。
- 后端 `server/src/logs/logs.controller.spec.ts`：合法 envelope → `logger.write` 被调用 + 返回 `{ ok: true }`；`LogEnvelopeDto` 校验（class-validator `validate()`）对非法 `level` / 非 string `message` → 报错（覆盖 400 路径）。
- 前端 `src/lib/logger.spec.ts`（vitest）：SSR 守卫（`window` 未定义直接返回）、浏览器内 `forward` 成功（mock `fetch` 201）、`forward` 失败静默（mock `fetch` reject 不抛）、console 镜像调用。

### BDD/E2E 用户旅程

- **豁免**：日志基建属跨切面基础设施，无用户可感知的 UI 旅程（前端 Logger 转发与后端落盘对用户透明，无页面交互）；且项目 TEST-102 已确立「不为纯后端 API / 基础设施写 BDD」的红线。故 LOG-101 **不写 BDD/E2E**，仅以单测 + 集成（前端 `POST` 被后端接收写入同一文件）为证据，并在质量门 `notes` 显式标注豁免。后续带 UI 的新 feature 仍须各自自带 BDD/E2E。
