# AI-204 — Plan JSON Schema 校验与重试

> 状态: in-progress | 栈: node-ts | 分支: feat/ai-204

## 1. 目标
让 `POST /api/ai/plan/generate` 的输出**可靠**：LLM 有时返回残缺/非 JSON/结构不符的计划。AI-204 在 `PlanService` 内增加结构化 Schema 校验 + 自动重试（≤3 次）+ 兜底内置模板计划，保证前端永远拿到「要么合规、要么明确 degraded 的模板」，不再出现 `rawText` 半成品。

## 2. 接口契约
- 复用 AI-202 接口：`POST /api/ai/plan/generate` → `GeneratePlanResponse { plan, model, degraded }`。
- **契约变化**：
  - `degraded` 语义升级：旧义「AI 返回非 JSON → rawText 兜底」；新义「校验 3 次仍不合规 → 降级为内置模板计划（`plan.weeks` 有效、可渲染），`model: 'template'`」。`plan.rawText` 不再由服务侧设置（保留类型字段兼容）。
  - 重试期间，重试请求（attempt>1）的 user 消息追加 `retryNote` 自我纠正提示，提升首轮命中率。
- 无新增路由 / DTO / 表 / 配置。

## 3. 数据模型
无新表。复用 `GeneratedPlan` / `PlanWeek` / `PlanDay` / `PlanLesson`（AI-202/203 定义）。

## 4. 验收标准
- [ ] `validatePlan(raw)` 对合规计划返回 `ok:true`；对根非对象 / weeks 缺失或空 / days 缺失或空 / lessons 缺失或空 / lesson.type 非法 / lesson.skillType 非法 / lesson.courseId|lessonId 非空字符串校验 等场景返回 `ok:false` 并聚合错误。
- [ ] 构造坏 JSON（无法 parse / 结构不符）→ 服务自动重试 ≤3 次；3 次后仍不合规 → 返回模板计划且 `degraded:true`、`model:'template'`、`plan.weeks` 有效。
- [ ] 合法 JSON 首轮即通过，`chat` 仅调用 1 次，`degraded:false`。
- [ ] provider 抛错（基础设施异常）仍向上传播（重试交由 AI-106 的 HTTP 层处理，避免双重重试），不进入模板降级。
- [ ] 内置模板计划 `buildFallbackPlan(dto)` 产出 `validatePlan().ok===true` 的结构（按 `weeks` 周数、每天含 main+review+speaking 任务），不依赖 LLM / 目录。

## 5. 风险点
- **重试边界**：仅「输出校验失败」重试；provider 异常传播不重试（防与 AI-106 叠加）。已在 service spec 显式断言。
- **模板与 AI-205 分工**：AI-204 的 `buildFallbackPlan` 是紧急兜底（最小有效结构）；AI-205 才是「3 套按 dailyMinutes 档位的静态周计划 + 用户可选模板生成」入口。两者不冲突，AI-205 后续可让 `generatePlan` 在用户显式选模板时直接调用 AI-205 的产物。
- **id 存在性校验**：目录未注入前，`validatePlan` 只校验 `courseId/lessonId` 为「非空字符串」（格式），**不校验存在性**；真实 id 存在性校验随目录注入留 AI-206。
