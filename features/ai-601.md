# AI-601 — AI 单词卡片生成

> 状态: done | 栈: node-ts (NestJS 10 + TypeORM + better-sqlite3 / Next.js 14) | 分支: feat/ai-601
> 来源: `features/backlog.md` M6 AI-601

## 1. 目标

按孩子的**兴趣 / 课程**动态调用 LLM 生成一组「单词卡片」（英文单词 + 中文释义 + 英文例句 + 配图 prompt），
先落入**待审表**（`ai_word_cards`，status=`pending`），经**人工/自动审核**后转为 `approved` 入库；
全部文本经**内容安全黑名单校验**（复用 AI-406 `matchBlocklist` 硬闸），校验不通过则整批拒绝。
价值：为 `words` 词库提供一个可持续、可控、安全的扩充入口，避免直接把 LLM 产出无条件写入正式词表。

## 2. 接口契约

### 后端（NestJS，`@Controller('ai/word-card')`，全局前缀 `/api`）

- `POST /api/ai/word-card/generate`
  - body：`GenerateWordCardDto { interest: string(1..80); count: number(1..10, 默认 5); courseId?: string }`
  - 响应：`{ cards: WordCardView[]; degraded: boolean; model: string }`
    - 生成失败时降级内置模板卡片（`degraded:true`），仍返回 200；
    - 内容安全命中 → 返回 422 `{ code:'CONTENT_UNSAFE', keyword }`，不落库。
  - 校验：`class-validator` 拦截非法入参 → 400。
- `GET /api/ai/word-card?status=pending` — 列出卡片（按 status 过滤，缺省返回全部），按创建时间倒序。
- `POST /api/ai/word-card/:id/approve` — body 可选 `{ reviewerNote?: string }` → status=`approved`，写 `approvedAt`。
- `POST /api/ai/word-card/:id/reject` — body 可选 `{ reviewerNote?: string }` → status=`rejected`。
  - 404：`id` 不存在；409：已终态（approved/rejected）重复操作。

### 前端（Next.js，`src/lib/api.ts` + `/word-cards` 页）

- `generateWordCards(dto)` → `POST /api/ai/word-card/generate`
- `listWordCards(status?)` → `GET /api/ai/word-card`
- `approveWordCard(id, note?)` / `rejectWordCard(id, note?)` → 对应 POST
- 类型 `WordCard` / `GenerateWordCardDto` / `WordCardStatus` 镜像进 `src/lib/types.ts`。

## 3. 数据模型

新增实体 `AiWordCard`（`server/src/word-card/ai-word-card.entity.ts`，表 `ai_word_cards`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| wordText | varchar | 英文单词 |
| meaning | varchar | 中文释义 |
| example | varchar | 英文例句 |
| exampleTrans | varchar nullable | 例句中文翻译 |
| imagePrompt | varchar | 配图生成 prompt（英文） |
| interest | varchar | 生成所用兴趣/主题 |
| courseId | varchar nullable | 关联课程（可选） |
| status | enum('pending','approved','rejected') | 默认 pending |
| reviewerNote | varchar nullable | 审核备注 |
| createdAt | datetime | |
| approvedAt | datetime nullable | |

> 选择「待审表」路线（backlog 明确允许「或待审表」）：`Word` 实体强依赖 `lessonId`/quiz 字段，
> 独立生成卡不便直接落 `words`；落 `ai_word_cards` 更贴合「审核后入库」语义，且避免污染正式词库。

`WordCardModule` 经 `TypeOrmModule.forFeature([AiWordCard])` 注册；`AiProvider` 由 `AiModule` 的 `@Global()` 注入，无需重复 import。

- [ ] 后端 jest 单测覆盖：解析/校验/重试/降级/安全拦截/状态流转；前端 vitest 覆盖纯逻辑。

## 5. 风险点

- **契约破坏**：`WordCard` 前端类型须与后端视图字段逐一对齐（Phase 2 复核）。
- **内容安全**：仅用黑名单硬闸（同步），未接入 NVIDIA 异步分类器；属 AI-406 已验证的第一道闸，足够拦截显式有害词，语义更微妙内容靠 prompt 约束 + 人工审核兜底。
- **生成质量**：真实 key 下 LLM 可能返回非 schema JSON → 自动重试 ≤3 次 → 仍失败降级模板（`degraded:true`），前端据此提示。
- **鉴权**：`/ai/word-card/*` 暂不加 `JwtAuthGuard`（与 `/ai/report/*` 同口径，userId 非必需），待全局鉴权收紧；审核动作属家长域，后续 AI-702 家长 PIN 可约束。

## 6. 测试计划（硬约束 #6）

### 单元测试

- 后端 `ai-word-card.service.spec.ts`（`@nestjs/testing` + MockProvider 替身）：
  - `generate`：合法 JSON → 解析 + 落 pending + 返回 degraded=false；
  - `generate`：坏 JSON → 重试后降级模板（degraded=true，仍落 pending）；
  - `generate`：内容安全命中 → 抛 `ContentUnsafeException`（422 映射），不留库；
  - `approve`/`reject`：pending→终态流转 + 写 approvedAt；终态重复 → 抛 ConflictException；未知 id → NotFoundException；
  - `listByStatus`：按 status 过滤正确。
- 前端 `src/lib/wordCards.spec.ts`（vitest）：`filterWordCards(cards, status)`、`countByStatus` 纯函数。

### BDD/E2E 用户旅程

- `word-cards.feature`：注册新用户 → 经 TabNav 进入 `/word-cards` → 输入兴趣「动物」→ 点击生成 →
  看到至少 1 张 pending 卡片 → 点击「批准」→ 卡片状态变为 approved（数据钩子 `data-status`）。
