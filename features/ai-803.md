# AI-803 — 学习计划 → 真实课程引用落地与学习导航（Plan→Course Reference & Navigation）

> 状态: done | 栈: node-ts (NestJS 10 + TypeORM + better-sqlite3 / Next.js 14) | 分支: feat/ai-803 | 质量门: docs/quality/ai-803-gate.md
> 来源: 用户提问（2026-08-18）—「生成的学习计划不会自动生成对应的课程然后落库吗？孩子是如何根据学习计划去学习的」。代码查证结论：计划当前只落 `StudyPlan` + `StudyPlanDay`(lessons 序列化进 `content` 文本列) + `DailyTask`(title/description/icon/date)，`courseId`/`lessonId` 从不作列、保存不校验存在、前端不跳转——计划本质是一份孤立的「主题化排期清单」。
> 与 AI-801 边界: AI-801 = 计划**生成**全新 Course+Lesson+Word（写路径）；本 feature = 计划**引用已有目录课程并驱动导航**（读路径）。二者互补。

## 1. 目标

让「学习计划」真正驱动学习，而非只是一张排期清单：

1. **引用可追溯** — 把计划每节 lesson 携带的 `courseId`/`lessonId` 从 `StudyPlanDay.content` 的 JSON 文本里**提为正式数据库列**，使它们可被查询、可被前端读取跳转。
2. **引用真实** — `savePlan`/`applyPlan` 按注入的课程目录（`CoursesService`）校验 `courseId`/`lessonId` 真实存在；AI 幻觉出的无效 id → 降级为「无深链的通用任务」，**不整计划失败**（保存期容错；生成期仍坚持「出错即抛」）。
3. **导航可用** — 前端每日任务按 `skillType` + 引用 id 深链到对应课时，孩子「点哪天/哪节就上那节课」：`vocab/listen/write` → `/practice?lessonId=<id>`（或 `/course/<courseId>`），`speak` → `/speech`；无引用时保留现状（一键完成 + 复习深链 `/practice?focusWord=`）。

## 2. 现状事实（代码查证）

- `PlanService.buildStudyPlan`（`plan.service.ts:246-263`）仅 `new StudyPlan()` + `new StudyPlanDay()`，lessons 经 `JSON.stringify` 存入 `StudyPlanDay.content`（text 列）；不创建任何 Course/Lesson/Word。
- `applyPlan`（`plan.service.ts:169-215`）写 `DailyTask`，字段仅 `title/description/icon/sortOrder/planDayId/date`（`daily-task.entity.ts:14-53`）。
- `StudyPlanDay`（`study-plan-day.entity.ts:17-57`）/ `DailyTask` 均无 `courseId`/`lessonId`/`skillType` 列。
- `validatePlan`（已改，`plan-schema.ts`）对 `courseId`/`lessonId` 仅校验「是字符串、允许空串」，**不校验真实存在**（存在性本属 AI-206）。
- 课程/课时为种子预置目录（`seed.ts`）；前端 `DailyTask` 类型（`src/lib/types.ts:111-118`）无 `courseId`/`lessonId`，首页 daily task（`src/app/[locale]/page.tsx:596-684`）默认一键完成、`mic`→`/speech`、复习→`/practice?focusWord=`。

## 3. 数据模型变更

- `StudyPlanDay` 实体新增：
  - `lessonRefsJson?: string` — 该日 4 节 lesson 的 `[{ skillType, courseId, lessonId, title }]` 序列化（保留 content 全量 lessons 文本不动，lessonRefs 为可查询的精简索引；或改为逐 lesson 提列——见 §6 决策）。
- `DailyTask` 实体新增：
  - `courseId?: string | null`
  - `lessonId?: string | null`
  - `skillType?: 'vocab'|'listen'|'speak'|'write' | null`
  - `source: 'plan'|'catalog'|'manual'`（区分来源，便于进度聚合）
- 迁移：TypeORM `synchronize`（dev）或新增 migration（prod），新增列可空、向后兼容。

## 4. 后端实现要点

- **`PlanService`**：`buildStudyPlan` 在构造 `StudyPlanDay` 时，从 `day.lessons` 提取 `lessonRefs`（含 `skillType`/`courseId`/`lessonId`/`title`）。
- **引用校验（新增 `resolvePlanRefs(catalog)`）**：遍历 lessonRefs，对每个非空 `courseId`/`lessonId` 调 `CoursesService.exists(lessonId)`；不存在 → 该 ref 标记 `resolved:false`（前端无深链），**不抛**。
- **`applyPlan`**：为每个 `lessonRef` 生成一条 `DailyTask`，写入 `courseId`/`lessonId`/`skillType`；`resolved:false` 的 ref 生成通用任务（标题取自 lesson title、无深链）。
- **依赖注入**：`PlanModule` 导入 `CoursesModule`（已导出 `CoursesService`，见 AI-801 §4），`PlanService` 注入 `CoursesService`。
- **错误映射**：目录服务不可用时（理论上不会，本地库）→ 整计划保存失败返回 500 明确文案，而非静默吞掉引用。

## 5. 前端实现要点

- `src/lib/types.ts` 的 `DailyTask` 增加 `courseId`/`lessonId`/`skillType`。
- `src/lib/api.ts` 的 daily tasks 拉取类型同步。
- 首页 `src/app/[locale]/page.tsx` daily task 卡：
  - 有 `lessonId` → 主按钮「去学习」深链：
    - `skillType==='speak'` → `/speech`
    - 否则 → `/practice?lessonId=${lessonId}`（或 `/course/${courseId}` 课程页再进课时）
  - 无引用 → 维持现状（默认一键完成；复习→`/practice?focusWord=；mic`→`/speech`）。
- i18n 补齐 `DailyTask.learn` / `DailyTask.goToLesson` 等键（中英）。
- `/practice`、`/course` 已支持按 `lessonId` 渲染课时内容（现有能力），无需改动其内核。

## 6. 关键决策（待开工时确认）

- **列粒度**：方案 A（推荐）`DailyTask` 逐 lesson 提列（一天 4 条 task，导航精准）；方案 B 仅 `StudyPlanDay.lessonRefsJson` 索引 + 每天 1 条聚合 task（改动小但导航弱）。倾向 A。
- **保存期容错 vs 生成期严格**：生成期（AI 输出）仍按用户口径「出错即抛」；保存/应用期对无效 ref 降级而非失败（避免一次幻觉整计划不可用）。
- **AI-801 协同**：若某计划经 AI-801 生成了课程，其 `courseId`/`lessonId` 由 AI-801 回填到计划 lessons，本 feature 直接复用引用/导航，无需改动 AI-801。

## 7. 验收标准

- 对一份含真实目录 id 的已保存计划 `applyPlan`：每日生成 4 条 `DailyTask`，`courseId`/`lessonId`/`skillType` 列非空且与计划 lessons 一致；`/api/tasks` 返回含引用。
- 对含**幻觉无效 id** 的计划 `applyPlan`：无效 ref 生成无深链通用任务（不抛、不整计划失败），其余有效 ref 正常深链。
- 前端首页 daily task 有 `lessonId` 时显示「去学习」按钮，点击跳 `/practice?lessonId=`（或 `/course/<courseId>`）；`speak` 跳 `/speech`；无引用时维持原行为。
- `StudyPlanDay`/`DailyTask` 新列迁移成功，存量数据列为空不报错。
- 单测：`resolvePlanRefs` 有效/无效/空混合用例、`applyPlan` 写列断言、前端 task 卡深链分支（组件或 hook 单测）。
- 后端 `tsc --noEmit` 0 + 前端 `next build` 成功 + 自带 BDD/E2E（见置顶质量约定）。

## 8. 实施备注（2026-08-18 落地）

- **列粒度采用方案 A（Plan A）**：`DailyTask` 新增 `courseId`/`lessonId`/`skillType`/`source` 四列；`StudyPlanDay` 新增 `lessonRefsJson` 索引列（与 `content` 全量文本并存，`parseLessonRefs` 优先读该列、为空回退 `content` 向后兼容）。`source` 初版 `default:'plan'` 会误标全局 seed 任务（其 `userId` 为 NULL），已改为 `nullable:true`（全局 seed 为 NULL、计划任务显式 `'plan'`）。
- **目录注入打通（Q1 决策）**：`PlanService.buildMessages` 改 async，调 `CoursesService.getCatalog()`（try/catch：失败仅 warn 降级「无目录」分支，不阻断生成）构造 `PlanCatalog`，非空时传给 `buildPlanUserPrompt(dto, catalog)` 触发 `curriculumCatalog` 分支，使 AI 产出真实 UUID（而非空字符串被 `validatePlan` 放过的幻觉 id）。
- **保存期容错（Q0 决策）**：`applyPlan` 对每节 `lessonRef` 调 `lessonExists/courseExists`，不存在 → 该任务不写深链列（字段缺省，非置 null 文本），**不抛、不整计划失败**；有效 ref 正常写 `courseId/lessonId/skillType` + `source:'plan'`；某天无任何引用 → 仅 1 条通用任务（`source:'plan'`）。与生成期「出错即抛」边界清晰。
- **AI-801 协同写回**：`generateCoursesForPlan` 在 AI-801 创建课程后调 `writeBackGeneratedCourse`，把生成的真实 `courseId/lessonId` 回填进计划 `lessonRefsJson`（day i → generated lesson i），使后续 `applyPlan` 能深链到 AI-801 产出的课程；写回失败仅 warn。
- **前端深链**：`src/lib/tasks.ts` 新增 `isLessonTask`/`lessonTaskHref`（`speak`→`/speech`，其余→`/practice?lessonId=`）；首页 `page.tsx` 在有 `lessonId` 且未完成任务时渲染 `LessonTaskLink`（`data-component=LessonTaskLink` + `aria-label` goToLesson），置于 speech 链接之前；`DailyTask` 类型与 i18n（`Home.goToLesson`）同步。
- **DI 回归修复**：`PlanService` 现注入 `CoursesService`，`plan.controller.spec.ts` 缺 provider 致 4 例失败——已补 mock，全量 jest 复绿（897/897）。
- **设计偏离（如实）**：`Lesson` 实体无 `skillType`/`level` 列，`getCatalog` 用 safe 默认（`vocab`/`a1`），不影响引用导航主目标；`savePlan` 期不做 id 存在性校验（仅结构校验），存在性校验只在 `applyPlan` 期，属 Q0「保存期容错」有意取舍。
- **测试证据**：后端 jest（plan.service AI-803 目录注入/buildStudyPlan/Plan A 拆课/无效 ref 降级/generateCourses 写回 + courses.service getCatalog/lessonExists/courseExists）+ 前端 vitest `tasks.spec` 10/10 + 新增 `plan-lesson-deeplink.feature`（mock daily-tasks 注入带 lessonId 任务 → 断言 LessonTaskLink + 跳 `/practice?lessonId=`）。全量 E2E 实跑经 user-accepted-ci 交 CI 兜底（本机 next dev 受限）。
