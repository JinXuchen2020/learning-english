# AI-405 — 对话场景包（Scene Packages）

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM) | 分支: feat/ai-405
> 依赖: AI-404（狐狸人设 System Prompt）

## 1. 目标

为对话陪练补齐「场景包」数据模型与服务端枚举能力：5 个儿童英文陪练场景
（打招呼 / 动物园 / 买东西 / 天气 / 身体部位），**每个场景包含三部分**：

1. **System Prompt（情境引导）** —— 注入 LLM 的情境 framing（狐狸人设 `FOX_PERSONA`
   由 `chat-system-prompt.ts` 统一前置，场景包只承载情境引导）。
2. **起始语（openingLine）** —— 进入场景时狐狸的第一句气泡（前端 `/chat` 页
   AI-407 首次问候用）。
3. **目标词汇（targetVocabulary）** —— 本场景 A1 简单词库（前端词库提示 / 跟读候选）。

并提供 **`GET /api/ai/chat/scenes`** 枚举接口，使前端 `/chat` 页（AI-407）能
「枚举 + 选择」场景，拿到每个场景的标题、起始语、目标词汇。

用户价值：把原先散落在 `chat-system-prompt.ts` 的 5 段场景 framing 升级为
「可枚举、含起始语与目标词汇」的结构化场景包，为 AI-407 前端场景卡提供数据契约。

## 2. 接口契约

### 后端
- 既有 `POST /api/ai/chat/messages`（AI-403）不变；其 `sceneId` 仍为可选自由字符串，
  未知 sceneId 表示「自由对话」（无场景 framing），**不被本 feature 限制**——
  前端从 `GET /scenes` 枚举出的已知场景中选择，但接口层仍兼容自由对话。
- **新增** `GET /api/ai/chat/scenes`
  - 全局前缀 `api` → 路由 `GET /api/ai/chat/scenes`
  - 无需鉴权（与本项目全部 AI 接口口径一致，userId deferred）
  - 响应（JSON 数组，顺序即展示顺序）：
    ```json
    [
      {
        "id": "greeting",
        "title": "打招呼",
        "openingLine": "Hello! I'm Fox Teacher. What is your name?",
        "targetVocabulary": ["hello", "hi", "name", "how", "are", "you", "fine", "thank", "good", "bye", "morning", "afternoon"]
      },
      { "id": "zoo", "title": "动物园", ... },
      { "id": "shopping", "title": "买东西", ... },
      { "id": "weather", "title": "天气", ... },
      { "id": "body", "title": "身体部位", ... }
    ]
    ```
  - 响应**不含** `systemPrompt`（内部提示词，不向前端暴露）；前端只需
    id / title / openingLine / targetVocabulary。
  - 错误：无（纯静态枚举，始终 200）。

### 前端（仅契约，本 feature 不实现页面）
- AI-407 `/chat` 页：拉取 `GET /api/ai/chat/scenes` → 渲染场景选择卡（id+title）；
  选场景后首条狐狸气泡用 `openingLine`；对话过程中展示 `targetVocabulary` 词库提示。

## 3. 数据模型

**无数据库变更**。场景包为静态配置（编译期常量），不入表
（`ai_chat_sessions.sceneId` 仍按既有 varchar 引用落库，不新增约束）。

新增纯 TS 数据模块 `server/src/chat/chat-scenes.ts`：
- `SceneId` 联合类型：`'greeting' | 'zoo' | 'shopping' | 'weather' | 'body'`
- `ScenePackage`：`{ id, title, systemPrompt, openingLine, targetVocabulary }`
- `SceneSummary`：`{ id, title, openingLine, targetVocabulary }`（对外契约，去 systemPrompt）
- `SCENE_PACKAGES: readonly ScenePackage[]`（5 项，展示顺序）
- `SCENE_PACKAGE_MAP`、`getScenePackage(id)`、`listSceneSummaries()`、`sceneExists(id)`

## 4. 验收标准
- [ ] `GET /api/ai/chat/scenes` 返回 5 个场景摘要，id 集合为 greeting/zoo/shopping/weather/body。
- [ ] 每个场景摘要含 title / openingLine / targetVocabulary，且**不含** systemPrompt。
- [ ] 每个场景包 systemPrompt / openingLine / targetVocabulary 均非空（引导词正确、词库非空）。
- [ ] `POST /api/ai/chat/messages` 仍能以已知 sceneId 正确组装系统提示（回归）。
- [ ] 未知 / 自由 sceneId（含 null）仍被 `messages` 接口接受（自由对话兼容）。
- [ ] 单元测试覆盖：注册表完整性、已知/未知场景查找、摘要排除 systemPrompt、枚举端点透传。
- [ ] `nest build` + `npm test` 全绿。

## 5. 风险点
- **漂移**：`SCENE_PROMPTS` 当前定义在 `chat-system-prompt.ts`，本 feature 把场景 framing
  文本迁移进 `chat-scenes.ts` 注册表，并在 `chat-system-prompt.ts` 以 `SCENE_PROMPTS`
  **重新导出**（从注册表派生），保证既有 `chat-system-prompt.spec.ts` 与 `chat.service.ts`
  调用不受影响（零回归）。
- **内容安全**：本 feature 仅做场景包数据 + 枚举，**不做**关键词/模型硬拦截（属 AI-406）。
  起始语/目标词汇均为预置安全内容；system prompt 仍叠加 `BASE_SAFETY_RULE` 基线。
- **E2E 豁免**：纯后端静态枚举 + 数据模型，无新增用户可感知端到端旅程，按 feature-builder
  约束 #6 不写 BDD/E2E（前端 `/chat` 页 AI-407 自带 E2E）。
