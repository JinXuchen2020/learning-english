# AI-402 — TTS 集成（后端 `synthesize` 真实语音合成）

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM, better-sqlite3 / postgres 双驱动) | 分支: feat/ai-402
> 依赖: AI-102（provider 接口与装配，done） | 前置链: …←feat/ai-309←feat/ai-401←feat/ai-402（在 feat/ai-401 上建新分支）

## 1. 目标
为 M4「AI 对话陪练」落地**语音合成能力底座**：把 `AiProvider.synthesize(text, voice, options)` 从「降级空结果」升级为**真实调用智谱 GLM-TTS** 并返回可播放音频（`AudioResult`：base64 或托管 URL + mimeType），让狐狸吉祥物获得**一致的儿童友好音色**（系统音色 `tongtong`，可经 `voice` 参数覆盖）。AI-403（聊天接口）会将本 feature 产出的 `ttsUrl`/`audioBase64` 嵌入回复；AI-407（会话 UI）实现「自动播放 / 中断 / 重播」。

## 2. 接口契约
### 后端（provider 层真实能力，无新 HTTP 路由）
- **`BigModelProvider.synthesize`** 真实实现（替换 AI-102 遗留的降级桩）：
  - 端点：`POST {baseUrl}/audio/speech`（智谱 GLM-TTS，与 chat 共用 `paas/v4` base）。
  - 请求体：`{ model, input: text, voice: voice||狐狸默认音色, response_format: 'mp3', speed, volume: 1.0, stream: false }`。
  - 响应解析（双路径健壮处理）：
    - `Content-Type: application/json` → 取 `url`（托管音频）或 `audio`（base64）；
    - 默认二进制音频响应（智谱直接返回 mp3/wav 字节）→ `Buffer` 转 base64；
    - 缺 `audio`/`url` 或空字节 → 抛 `AiProviderException`(502)。
  - 返回 `AudioResult { audioBase64?, audioUrl?, mimeType: 'audio/mpeg'|'audio/wav'|…, durationMs? }`。
  - 错误复用现有 `throwOnError`：401/403→`AiAccessError`、429→限流、5xx→接口错误；网络/超时(A abort)→`NETWORK`/504。
- **配置扩展**：`BigModelConfig` / `BigModelConfigView` 增加 `ttsModel`（默认 `glm-tts`）、`ttsVoice`（默认 `tongtong`，狐狸音色）。
- **`ai-config.ts`**：读取 `BIGMODEL_TTS_MODEL` / `BIGMODEL_TTS_VOICE`，缺省取默认。
- **`ai.module.ts` `createAiProvider`**：透传 `ttsModel` / `ttsVoice` 给 `BigModelProvider`。
- **`MockAiProvider.synthesize`**：保持返回 `{ audioBase64: '', mimeType: 'audio/mp3', durationMs: 0 }`（无 key 演示模式信号，前端回退浏览器 TTS，与 AI-307 既有行为一致）。

## 3. 关键实现要点
- **狐狸音色默认值**：`DEFAULT_TTS_VOICE = 'tongtong'`（智谱童声系统音色，儿童场景适配）；`DEFAULT_TTS_MODEL = 'glm-tts'`；`DEFAULT_TTS_TIMEOUT_MS = 30_000`（TTS 比 LLM 快）。
- **媒体类型推导**：`mimeFromContentType` 把 `audio/mpeg|mp3`→`audio/mpeg`、`audio/wav|x-wav`→`audio/wav`、`audio/pcm`→`audio/pcm`，兜底 `audio/mpeg`（与 `response_format: 'mp3'` 一致）。
- **响应健壮性**：智谱 `/audio/speech` 默认返回**二进制音频**；个别网关/代理可能包 JSON（`{audio}` / `{url}`）。两种形态都解析，避免环境差异导致 502。
- **不新增 HTTP 路由**：TTS 作为 provider 能力内聚，由 AI-403 聊天接口与 AI-407 会话页消费，避免与 `/api/ai/chat/messages` 的 ttsUrl 返回重复。

## 4. 验收标准
- [ ] `BigModelProvider.synthesize` 向正确端点发送正确请求体（model/input/voice/response_format/speed/volume/stream）。
- [ ] 二进制 mp3 响应 → 返回 `audioBase64` + `mimeType: 'audio/mpeg'`。
- [ ] JSON 信封 `{url}` → `audioUrl`；`{audio}` → `audioBase64`；缺字段 → 抛 502。
- [ ] 缺 `BIGMODEL_API_KEY` → 抛 `AiProviderException`(401)；429 → 限流；网络/超时 → `NETWORK`/504。
- [ ] `readAiConfig` 正确读取 `BIGMODEL_TTS_MODEL` / `BIGMODEL_TTS_VOICE` 并应用默认。
- [ ] `nest build` / `tsc` 0 错误；jest 全绿（全局基线不退化）；pre-commit 质量门强执通过。

## 5. 风险点
- **API 形态差异**：智谱 TTS 默认返回二进制、少数网关包 JSON；双路径解析规避。
- **音色可用性**：`tongtong` 为系统音色（非复刻），不依赖用户上传样本；`voice` 参数可覆盖以接后续复刻音色（AI-603 等）。
- **配置形状断言**：`ai-config.spec.ts` 对 `cfg.bigmodel` 用 `toEqual` 精确断言，新增 `ttsModel`/`ttsVoice` 后须同步更新该断言（否则误红）。
- **不越界**：本 feature 仅落地 provider 合成能力 + 配置，不实现聊天/会话 UI（属 AI-403/AI-407），不自创 HTTP 路由。
