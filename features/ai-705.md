# AI-705 — AI 提供商配置（家长页面）

> 状态: done | 栈: node-ts（NestJS 后端 + Next.js 前端，全栈） | 分支: feat/ai-705
> 来源: `features/backlog.md` M7 / AI-705；用户决策：每家长账号一份、按原设计全量实现。

## 1. 目标

家长可在「家长页」自由增 / 删 / 改 AI provider（优先 OpenAI 兼容类：智谱 / OpenAI / DeepSeek / Qwen 等，统一通用适配器覆盖 chat / 多模态 / STT / TTS），并配置**默认 provider**。配置按**每家长账号隔离**；密钥服务端 AES-256-GCM 加密落库、前端掩码展示；后端把启动期单例 `AI_PROVIDER_TOKEN` 改为**运行时解析器（`AiProviderRouter`）**，改完即时生效、无需重启服务。接口仅家长 PIN 会话可访问。

用户价值：机构 / 家庭可自带大模型 key（合规、成本可控），不依赖部署方预设的 `AI_PROVIDER` 环境变量。

## 2. 接口契约

### 2.1 后端 `ProviderConfigModule`（全部路由挂 `ParentGuard`）

| 方法 | 路径 | 说明 | 请求体 / 参数 | 响应 |
|---|---|---|---|---|
| GET | `/provider-config` | 列出当前家长账号下的 provider 配置 | — | `ProviderConfigView[]`（apiKey 掩码，仅返 `masked` + `hasKey`） |
| POST | `/provider-config` | 新增 | `CreateProviderConfigDto` | `ProviderConfigView` |
| PUT | `/provider-config/:id` | 修改（`apiKey` 可空=不改） | `UpdateProviderConfigDto` | `ProviderConfigView` |
| DELETE | `/provider-config/:id` | 删除（删默认则回退 env 默认） | — | `204` |
| POST | `/provider-config/:id/default` | 设为该账号默认（同账号互斥） | — | `ProviderConfigView` |
| POST | `/provider-config/:id/test` | 轻量连通性探测（chat 1 token） | — | `{ ok: boolean, message: string }` |

`CreateProviderConfigDto`：`name`(string)、`type`(`'openai-compatible'|'bigmodel'|'mock'`)、`baseUrl`(string, nullable)、`apiKey`(string, nullable)、`models`(`{ chat?, vision?, tts? }`)、`capabilities`(`('chat'|'vision'|'stt'|'tts'|'pronunciation')[]`)。
`ProviderConfigView`：`id, ownerUserId, name, type, baseUrl, models, capabilities, isDefault, hasKey, masked, createdAt, updatedAt`（**绝不**返回明文 `apiKey`；`masked` 仅后 4 位 + 长度，如 `****abcd`）。

鉴权：沿用 `ParentGuard`（校验 `role==='parent'` 的 JWT，`req.user.userId` = 家长 `User.id`）。`ownerUserId` 一律取自身 JWT 的 userId，**不允许**跨账号操作（越权返回 403/404）。儿童 JWT（`role` 缺省）天然被 `ParentGuard` 拒绝。

### 2.2 前端（家长页新增「AI 提供商」配置区）

- 新增 `src/lib/api.ts` 的 `providerConfig` 客户端方法（GET/POST/PUT/DELETE/test）。
- 家长页 `src/app/parent/page.tsx` 增加「AI 提供商」卡片：列表（名称 / 类型 / 默认徽标 / 掩码密钥）、新增 / 编辑表单（类型下拉、名称、baseUrl、apiKey、模型、能力多选）、设为默认、删除（带确认）、测试连通性按钮。

### 3.2 `User.parentId` 新增可空列（`server/src/entities/user.entity.ts`）
```ts
@Column({ type: 'uuid', nullable: true })
parentId: string | null;
```
作用：儿童 → 家长归属，使**儿童发起的 AI 请求**也能解析到其家长的默认 provider，真正实现「每家长账号」生效。向前兼容：初始全 null，解析器遇 null 回退 env 默认（零回归）。家庭绑定 UX（家长认领儿童）超出 AI-705 范围，本 feature 仅预留字段。

## 4. 运行时解析器（核心改动，零回归保证）

把 `AiModule` 里 `AI_PROVIDER_TOKEN` 的工厂产物由固定 provider 换成 **`AiProviderRouter`**（实现 `AiProvider` 接口）：

- 构造时持有：env 默认 provider（复用现有 `createAuditedProvider` 构建，作为回退基准）+ `ProviderConfigService`。
- 每次方法调用（`chat`/`chatWithImage`/`transcribe`/`assessPronunciation`/`synthesize`）先解析 **effective parent**：
  - 从 `AsyncLocalStorage`（全局拦截器在鉴权后写入 `{ userId, role }`）取上下文；
  - `role==='parent'` → 自身 userId；`role==='child'`/缺省 → 查 `User.parentId`（null 则回退）。
- 命中 parent 且其有 `isDefault` 配置 → 解密 `apiKeyEnc` → 按 `type` 构建 `OpenAiCompatibleProvider` / `BigModelProvider` / `MockAiProvider`，**复用现有 `createRetryableProvider` / `createUsageLimitedProvider` / `createLoggedProvider` 链**包裹 → 调用；
- 未命中 / 解密失败 / 无配置 / 任何异常 → **回退 env 默认 provider**。

> 这是「破坏性后端改动」的安全措施：默认路径与改动前完全一致（env `AI_PROVIDER` 单例），仅当家长显式配置默认 provider 时才走自定义路径；任一环节失败都安全降级，绝不抛启动期错误。

## 5. 加密（`server/src/ai/provider-config/crypto.util.ts`）

- AES-256-GCM；密钥取自 env `PROVIDER_ENC_KEY`（生产必填）。dev 缺失时回退固定 dev key + `logger.warn`（仅演示，不用于生产）。
- 存储格式：`iv(base64)::tag(base64)::ciphertext(base64)`。
- `encrypt(plain, key)` / `decrypt(blob, key)` roundtrip；错误（wrong key / 损坏）→ 抛清晰异常，由解析器捕获回退。
- **API 绝不返回明文**；读路径只产出 `hasKey` + `masked`（末尾 4 字符 + 长度占位）。

## 6. OpenAI 兼容适配器（`server/src/ai/provider-config/openai-compatible.provider.ts`）

实现 `AiProvider`，对接标准 OpenAI 兼容端点（智谱 / OpenAI / DeepSeek / Qwen 等）：
- `chat` → `POST {baseUrl}/chat/completions`（复用 BigModelProvider 的响应解析形状）。
- `chatWithImage` → 同端点，content 走 `image_url` 数组（vision 模型）。
- `transcribe` → `POST {baseUrl}/audio/transcriptions`（multipart）。
- `synthesize` → `POST {baseUrl}/audio/speech`（返回音频二进制 / base64）。
- `assessPronunciation` → **通用 OpenAI 不提供发音评测**，返回 `unsupported` 降级结果（`score:0, mascotExpr:'thinking', feedback:'该提供商不支持发音评测'`），由解析器在需要时回退默认 provider 的该项能力（后续增强，本 feature 先标注）。
- 失败统一抛 `AiProviderException`（沿用 BigModelProvider 的错误分类：`statusCode`/`code`），重试 / 降级由 AI-106 编排复用。
- `fetchFn` 可注入，便于单测 mock。
