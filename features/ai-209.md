# AI-209 — 计划进度回写与 Home 完成度展示

> 状态: in-progress | 栈: node-ts (Next.js 前端 + NestJS 后端) | 分支: feat/ai-209
> 依赖: AI-206 (save/apply + daily_tasks 多租户) · AI-208 (计划展示与交互) | 下游: 无（M2 闭环收尾）

## 1. 目标

把 M2 学习计划闭环的最后一块补上：孩子**完成计划内的每日任务**时，后端把对应
`study_plan_days.isDone` 回写为 `true`；Home 页据此展示**计划完成度**（已完成 X / 总 Y 天 +
进度环），让孩子看到自己的学习节奏。后端零新增数据模型（复用 AI-201 的 `study_plan_days.isDone` 与
AI-206 的 `daily_tasks.planDayId` 关联）。

## 2. 接口契约

### 后端（新增 1 个只读端点 + 修改 completeTask 副作用）
- `TasksService.completeTask(userId, taskId)`（AI-206 既有）：在写入 `task_completions`
  之后，若该 `DailyTask` 的 `planDayId` 非空 → `StudyPlanDayRepository.update({ id: planDayId }, { isDone: true })`。
  幂等（重复完成同一任务仍只置 `isDone=true`，不产生副作用）；全局种子任务（`planDayId IS NULL`）不受影响。
- `GET /api/ai/plan/status?childId=<uuid>`（**新增**，沿用 AI-206/208 计划接口「childId 走 query、不加 JwtAuthGuard」约定）：
  返回该 childId 最近一份 `status='applied'` 计划的完成度快照 `PlanStatusResult`：
  ```
  { hasPlan: boolean, totalDays: number, doneDays: number, completionRatio: number /*0-1*/, planId?: string, appliedAt?: string }
  ```
  - 无 applied 计划 → `{ hasPlan:false, totalDays:0, doneDays:0, completionRatio:0 }`（不报错，前端据此隐藏卡片）。
  - 有 → `totalDays = plan.days.length`、`doneDays = days.filter(isDone).length`、`completionRatio = doneDays/totalDays`。
  - 取最新：`planRepo.findOne({ where:{userId:childId,status:'applied'}, relations:['days'], order:{updatedAt:'DESC'} })`。

### 前端（新增/扩展）
- `src/lib/types.ts`：`PlanStatusResponse { hasPlan; totalDays; doneDays; completionRatio; planId?; appliedAt? }`。
- `src/lib/api.ts`：`getPlanStatus(childId)` → `GET /api/ai/plan/status?childId=<id>`，复用 `request`。
- `src/app/page.tsx`（`HomeContent`）：新增 `planStatus` state；`load()` 并行拉取 `getPlanStatus(user.id)`；
  新增 `data-component="PlanProgress"` 卡片（仅 `planStatus.hasPlan` 时渲染）：复用现有 `ProgressRing`
  展示 `Math.round(completionRatio*100)%` + 文案「本周学习计划 / 已完成 X/Y 天」；
  `handleCompleteTask` 在 `completeTask` 成功后额外 `getPlanStatus(user.id)` 刷新完成度（乐观更新任务态后仍回源）。

## 3. 数据模型
无新增后端表/字段。`study_plan_days.isDone`（AI-201 已建，注释「由 AI-209 进度回写」）被本 feature 实际写入；
`daily_tasks.planDayId`（AI-206）作为回写关联键。`StudyPlanDay` 仓库经 `tasks.module.ts`
`TypeOrmModule.forFeature([..., StudyPlanDay])` 注册供 `TasksService` 注入（实体类导入不构成模块循环依赖：
`PlanModule` 仍单向 import `TasksModule`）。

## 4. 验收标准
- [ ] 完成 planDayId 非空的每日任务 → 对应 `study_plan_days.isDone` 置 true（幂等）。
- [ ] 完成全局种子任务（planDayId 空）不影响任何计划日。
- [ ] 无 applied 计划时 `/api/ai/plan/status` 返回 `hasPlan:false`，Home 不显示完成度卡。
- [ ] 有 applied 计划时 Home 显示完成度卡（X/Y 天 + 进度环）。
- [ ] 在 Home 完成计划任务后，完成度卡的数字/进度环随之更新。

## 5. 风险点
- **模块依赖方向**：`TasksService` 注入 `StudyPlanDay` 仓库须在 `TasksModule` 内 `forFeature` 注册该实体，
  不可反向 import `PlanModule`（保持 `Plan → Tasks` 单向，避免循环依赖）。
- **回写时序/幂等**：`completeTask` 先查 `DailyTask` 取 `planDayId` 再 `update` 日行；已完成任务（已存在 completion）
  仍走回写（无害），保持逻辑简单。
- **完成度口径**：计划日仅在 `date=今天` 时进入当日每日任务（AI-206 按 `dayIndex` 填 UTC 日期），故当天可见的计划任务
  通常只有 `dayIndex=0` 那条；Home 完成度当天最多 +1，属预期，不要求一天内刷满整份计划。
- **E2E 跨场景隔离**：沿用 plan-display.feature 的「每场景注册唯一用户名」约定，applied 计划按用户隔离，避免污染。
