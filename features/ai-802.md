# AI-802 — 聊天语音输入（Chat Voice Input）

> 状态: done | 栈: node-ts (Next.js 14 前端, 纯客户端) | 分支: feat/ai-802
> 来源: 用户需求（2026-08-16）— 聊天页 `/chat` 目前只有键盘输入，`ChatInner` 的受控 `<textarea>`（src/app/[locale]/chat/page.tsx 第 783–791 行）希望能用语音输入，让孩子不用键盘也能对狐狸老师说英语。

## 1. 目标

给 `/chat` 聊天输入框增加**语音输入入口**：一个麦克风按钮 + 实时英文听写，把口语直接变成输入框文本（发送前可编辑）。技术底座复用已验证的**浏览器 Web Speech API**——跟读功能（`ReadAlongPanel` 的 `transcribeWithBrowserApi`）已接入 `src/types/speech-recognition.d.ts` 的 `SpeechRecognition`/`SpeechRecognitionEvent` 类型，本 feature 复用同一套类型与运行时能力，零新增依赖。

> 与跟读 `transcribeWithBrowserApi` 的区别：跟读是把「录音 blob 播放给识别器」的一次性 hack（为拿到云端 STT 不可达时的兜底文本）；本 feature 是**实时听写**（直接 `SpeechRecognition` + `interimResults`，无需录音 MediaRecorder），二者逻辑独立，不复用。

## 2. 接口契约 / 交互

**纯前端，无新后端 API**（识别结果只是输入框文本，发送仍走既有 `POST /api/ai/chat/messages`）。

- 在 `ChatComposer`（第 782–803 行 flex 容器，textarea 左侧）加一个 🎤 按钮。
- 点击麦克风 → 启动 `SpeechRecognition`：
  - `lang = "en-US"`（英语对话场景，默认英文听写）；
  - `interimResults = true`、`continuous = true`（实时预览 + 连续说话）；
  - `maxAlternatives = 1`。
- 识别处理：
  - **最终结果（final）** → 追加进受控 `input`（`setInput(prev => (prev ? prev + " " : "") + finalTranscript)`），用户发送前可编辑/删除；
  - **中间结果（interim）** → 仅做实时预览展示（不写入 input，避免抖动）。
- 再次点击麦克风 → `recognition.stop()` 停止；识别中按钮高亮/脉冲动画。
- **降级**：浏览器不支持（`window.SpeechRecognition`/`webkitSpeechRecognition` 均不存在）或处于非安全上下文（非 HTTPS/localhost）时，`supported=false`，按钮**隐藏或禁用并给出提示**，绝不报错。

## 3. 数据模型

无新实体、无新 DB 表。语音识别结果仅在客户端作为输入框文本存在，发送沿用既有 `ChatMessage` 流程（`handleSend` 读取 `input.trim()`）。

## 4. 实现要点

- **新增 `src/lib/useSpeechDictation.ts`（hook）**：
  - 从 `window` 取 `SpeechRecognition ?? webkitSpeechRecognition`，取不到则 `supported=false`；
  - 用 `useRef` 持有 `recognition` 实例，避免重复创建；
  - 暴露 `{ supported, listening, interim, start, stop }`；
  - `start()`：新建实例、绑 `onresult`（区分 final/interim）/ `onerror` / `onend`，调 `recognition.start()`；`onend` 时把 `listening` 置 false（continuous 模式浏览器可能自动 onend，需处理重连或停止）；
  - `stop()`：调 `recognition.stop()` 并清状态；
  - 组件卸载（`useEffect` cleanup）时 `stop()`，防止泄漏。
- **`ChatInner` 接线**：
  - `const dictation = useSpeechDictation("en-US");`
  - textarea 左侧渲染 Mic 按钮：`dictation.supported && <button onClick={dictation.listening ? dictation.stop : dictation.start}>`；识别中加脉冲样式（`animate-pulse` 或项目已有动画类）；
  - `value={input}` 不变；`onChange` 不变；但需在 `handleSend` 前把 `dictation.interim` 合并（interim 仅预览，发送以 input 为准即可）；
  - 在 composer 下方/上方渲染 `dictation.interim` 实时预览条（可选，提升体验）。
- **i18n**：`messages/zh.json` + `messages/en.json` 的 `Chat` 命名空间补：
  - `voiceInput`（麦克风 aria-label / tooltip）
  - `listening`（识别中提示）
  - `tapToSpeak`（点击说话引导）
  - `voiceNotSupported`（不支持时的提示）
- 复用 `SpeechRecognition` 类型（已声明），不装 `@types/dom-speech-recognition`（项目铁律：离线不可靠，已用本地声明）。

## 5. 验收标准

- Chrome / Edge / Safari（含 iOS Safari）下：点麦克风 → 说英文 → 输入框出现对应英文文本；再点停止。
- 不支持的浏览器（Firefox）/ 非安全上下文：按钮隐藏或禁用，且有明确提示，不抛错、不阻断键盘输入。
- 语音填入的文本可正常发送（走既有 `handleSend`，后端无改动）。
- 前端 `tsc --noEmit` 0/0；按项目约定，**BDD/E2E 必做**：覆盖「麦克风按钮可见 → 点击进入 listening → 输入出现英文文本 → 发送」（UI 确定性夹具，不依赖真实语音；可用 `page.route`/mock `SpeechRecognition` 或 `data-component` 断言态切换）。
- i18n 中英键齐全，i18n spec 通过。

## 6. 注意 / 风险

- **安全上下文**：Web Speech API 仅 HTTPS 或 `localhost` 可用。本地 `localhost:3000` 开发正常；线上必须 HTTPS，否则 `supported=false` 自动降级。
- **语言固定 en-US**：契合英语对话；若后续要中英混输，再加语言切换（本期不做）。
- **continuous 自动 onend**：部分浏览器 continuous 模式会在静音后自动 `onend`，需在 `onend` 里判断是否仍 `listening` 意图以决定是否重启或停止——避免「说一半突然停」。
- **与 AI-801 无关**：独立前端增强，不阻塞 AI-801（计划→课程生成）的代码实现。
