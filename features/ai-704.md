# AI-704 — 逾期 / 补学循环（Makeup Queue）

> 状态: done | 栈: node-ts | 分支: feat/ai-704

## 1. 目标

把「昨日未掌握单词」与「昨日未完成计划任务」聚合成一个**补学队列**，在 Home 以独立卡片呈现，引导孩子补学并照常拿分；与 AI-605 间隔复习**协同且不重复**（同一弱词不会既出现在「今日复习」卡又出现在「补学」卡，补学练习不重复计分）。补学完成后回写完成态（弱词经练习提升掌握度 / 未完成计划日标记为 isDone）。

用户价值：不让孩子「欠账式」流失进度，给一个明确的「昨天没搞定的，今天补上」入口，同时保持积分激励一致。

## 2. 接口契约

### 后端（ProgressModule，复用 JwtAuthGuard）

- `GET /api/progress/makeup`
  - 返回 `{ weakWords: MakeupWordItem[], missedTasks: MakeupTaskItem[] }`
  - `MakeupWordItem { wordId, wordText, meaning, mastery, lastPracticedAt }`
  - `MakeupTaskItem { planDayId, title, date }`
- `POST /api/progress/makeup/task/:planDayId/complete`
  - 标记该 `study_plan_days` 为 `isDone=true`（仅当归属当前用户），best-effort 补学拿分（`POINT_RULES.TASK_COMPLETE`），幂等。返回 `{ success }`。

### 前端（src/lib/api.ts + Home）

- `getMakeupQueue(): Promise<MakeupQueue>` → `GET /progress/makeup`
- `completeMakeupTask(planDayId): Promise<{success}>` → `POST /progress/makeup/task/:planDayId/complete`
- Home `MakeupCard`：队列非空时展示；弱词 → 深链 `/practice?focusWord=<wordText>`（复用 AI-703/AI-507 下钻，练习照常计分与回写掌握度）；未完成计划日 → 标题 + 「标记完成」按钮（`completeMakeupTask`，乐观移除 + 失败回滚）。

## 3. 数据模型

**无新实体 / 无迁移**（better-sqlite3 `synchronize` 自动落库）。补学队列是**实时视图**，由现有表计算：

- 弱词来源：`word_progress`（`userId` + `lastPracticedAt` ∈ 昨日窗口 + `mastery < 60`）。`mastery` 由 AI-602 `computeMastery` 推导；「未掌握」阈值 `MAKEUP_MASTERY_THRESHOLD = 60`，与 AI-503 弱项口径（correct/attempts < 0.6）一致。
- 未完成计划日来源：`study_plan_days`（LEFT JOIN `study_plans` 取 `userId`）+ `date = 昨日(YYYY-MM-DD)` + `isDone = false`。
- **协同去重**：弱词集合排除「已出现在 AI-605 到期复习（`getDueReviews` 返回 wordId 集合）」的词，保证不重复展示。

## 4. 验收标准

- [ ] 昨日练过且 `mastery < 60` 的词进入补学队列（Home 出现 MakeupCard）。
- [ ] 今日练过 / `mastery >= 60` 的词**不**进入补学队列。
- [ ] 与 AI-605 到期复习重合的弱词只在一处出现（不重复）。
- [ ] 昨日 `isDone=false` 的计划日进入补学队列（未完成计划日）。
- [ ] 点击弱词 → `/practice?focusWord=` 练习并能正常完成（计分 + 掌握度回写，无重复计分）。
- [ ] 点击未完成计划日「标记完成」→ 该计划日 `isDone=true`、补学拿分、卡片移除该项。
- [ ] 空库 / 无昨日数据 → 队列为空数组，不报错，Home 不渲染 MakeupCard。
- [ ] 前后端 tsc 0 错误；`next build` 成功；单测 + E2E 全绿。

## 5. 风险点

- **「昨日」窗口口径**：后端用 UTC `YYYY-MM-DD`（`new Date().toISOString().split('T')[0]` 减一天），与 `task_completions.date` / `study_plan_days.date` 既有 UTC 口径一致，避免时区漂移。
- **与 AI-605 重复展示**：靠 `getMakeupQueue` 内部排除 due-review wordId 解决；若未来 AI-605 也展示「昨日弱词」，此处为唯一真相源，天然不重。
- **重复计分**：弱词补学走普通 `/practice`（每次正确尝试由 AI-701/605 正常计一次分），补学不额外加奖；未完成计划日因 `date=昨日` 不会出现在今日 `daily_tasks`，故 `completeMakeupTask` 单独加一次 `TASK_COMPLETE` 分也不与今日任务重复。
- **DB 种子可行性**：E2E 需「昨日」数据，而 `recordWordAttempt` 固定写 `lastPracticedAt=now`。提供 DB 直写种子脚本（`server/src/scripts/seed-makeup.ts`，经 tsx 跑，复用 `buildDataSourceOptions`），插入 `lastPracticedAt=昨日` 的 `word_progress` 行与 `date=昨日` 的 `study_plan_days` 行，供 E2E 验证。
