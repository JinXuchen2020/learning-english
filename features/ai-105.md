# AI-105 — 配置与密钥管理

> 状态: done | 栈: node-ts (NestJS 10) | 分支: feat/ai-105 (建在 feat/ai-104 之上) | 依赖: AI-103(done)

## 1. 目标
把散落在 `createAiProvider` 里的 `config.get(...)` 调用**集中为单一、类型化的 AI 配置读取**（`ai-config.ts` 的 `readAiConfig`），并在**应用启动（DI 装配期）**对「选中的真实 provider 缺 key」打印清晰告警；同时确认 `.env` 不进 git、`.env.example` 已含全部所需变量。让「配置从哪来、缺了会怎样」一目了然，便于后续 NVIDIA（AI-???）等 provider 接入。

## 2. 接口契约
无新增 HTTP 接口。新增内部模块：
- `server/src/ai/ai-config.ts`：
  - `interface AiConfig { provider: string; bigmodel: BigModelConfigView; nvidia: NvidiaConfigView }`
  - `BigModelConfigView { apiKey?; baseUrl?; model?; visionModel? }`
  - `NvidiaConfigView { apiKey?; baseUrl?; model?; safetyModel? }`
  - `readAiConfig(config: ConfigService): AiConfig` —— 经 `ConfigModule`（已 `isGlobal:true`）读取全部 `AI_*`/`BIGMODEL_*`/`NVIDIA_*` 变量，`provider` 做小写+trim 归一化（缺省 `mock`），各 model/baseUrl 应用默认值（与 `.env.example` 一致）。

### 启动告警契约（在 `createAiProvider` 装配期执行，不阻断启动）
- `provider==='bigmodel'` 且 `BIGMODEL_API_KEY` 缺失 → `logger.warn('[AI] AI_PROVIDER=bigmodel 但未配置 BIGMODEL_API_KEY …')`。
- `provider==='nvidia'`/`'azure'`（尚未实现）→ 维持既有「回退 MockAiProvider + warn」；nvidia 缺 key 时在告警中一并提示。
- `provider==='mock'` / 缺失 / 未知 → 维持既有行为（mock 不告警；未知回退 mock + warn）。
- 行为与 AI-103 既有契约完全一致，**仅新增 bigmodel 缺 key 告警**。

## 3. 数据模型
无（不新增实体/表）。

## 4. 验收标准
- [ ] `readAiConfig` 正确读取并归一化 `AI_PROVIDER`（大小写/空格容错，缺省 `mock`）。
- [ ] `readAiConfig` 对 `BIGMODEL_*`/`NVIDIA_*` 应用默认值，缺失 key 时为 `undefined`（不抛）。
- [ ] `AI_PROVIDER=bigmodel` 且缺 `BIGMODEL_API_KEY` → 启动期 `logger.warn` 被调用，应用仍可启动。
- [ ] `AI_PROVIDER=bigmodel` 且 key 存在 → 无缺 key 告警。
- [ ] `.env` 已在 `.gitignore` 中（不进 git）；`.env.example` 已被跟踪且含 `AI_PROVIDER`/`NVIDIA_*` 变量（验证，不重写）。

## 5. 风险点
- **不阻断启动**：告警而非抛错，保持 AI-103「无 key 应用可启动」契约；真实失败仍发生在调用期（BigModelProvider 抛 `AiProviderException`）。
- **不静默吞错**：未知 provider 仍 warn + 回退 mock（既有行为保留）。
- **不引入新依赖**：仅用已存在的 `ConfigService` + `logger`。
