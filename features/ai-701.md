> 里程碑：M7（成长激励与家长模式）· 优先级 P0 · 依赖：现有 ProgressModule、AI-209、AI-307
> 来源：`docs/ai-integration.md` M7 分析 + `english-kids-workbench.html` 单文件 Demo 融合分析
> 状态：**in-progress**（feat/ai-701，自 master 派生）

## 1. 目标与范围

为儿童英语学习产品补齐「成长激励」这一核心留存钩子：

- **统一积分/星星货币**：学习行为（完成任务 / 答对单词 / 口语通过 / 完成课程）累加积分；积分 = 累计星星 `User.totalStars` 的「可消费副本」。
- **等级环**：等级由累计星星经 `computeLevel` 推导（阈值 `[0,50,120,200,300,500]`，共 6 级，档名「英语宝宝→英语新星→英语之星→英语达人→英语小将→英语大师」），与众吉祥物成长剧情（AI-603）共用同一推导，保证等级单一真相。
- **奖励商城**：家长可维护奖励目录（增删改）；孩子浏览并「兑换申请」，状态 `pending → approved/rejected`（家长审批）。
- **家长审批**：兑换走「孩子申请 → 家长批准/驳回 → 已兑换」状态机。AI-702（PIN 锁）未上线前，审批端点用 `x-parent-approval` 请求头临时门禁（明文 dev token），并在代码与文档中标注后续由 AI-702 PIN 会话替换。

> 模型要点：**积分余额（可消费）** 与 **累计星星（lifetime，驱动等级）** 分离。
> - 获得行为：`totalStars += n`（等级随之重算）+ `user_points.balance += n`。
> - 兑换消费：仅 `user_points.balance -= cost`（等级不回落，符合儿童产品直觉）。

## 2. 后端设计

### 2.1 实体（`server/src/rewards/`）

**`UserPoints`（`user_points` 表）** — 每用户一行，可消费余额：
| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| userId | varchar(唯一) | 关联 `users.id` |
| balance | int default 0 | 可消费积分余额 |
| createdAt / updatedAt | datetime | |

**`Reward`（`rewards` 表）** — 奖励目录（家长 CRUD）：
| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| title | varchar | 奖励名（如「多讲一个睡前故事」） |
| description | varchar nullable | 说明 |
| cost | int | 兑换所需积分 |
| emoji | varchar nullable | 图标 |
| active | boolean default true | 是否在商城展示 |
| createdAt / updatedAt | datetime | |

**`RewardRedemption`（`reward_redemptions` 表）** — 兑换申请单：
| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | |
| userId | varchar | 申请人（孩子） |
| rewardId | varchar | 关联 `rewards.id` |
| rewardTitle | varchar | 快照标题（防目录改删后失联） |
| cost | int | 快照成本 |
| status | enum `pending\|approved\|rejected` default pending | |
| rejectReason | varchar nullable | 驳回原因 |
| decidedAt | datetime nullable | 审批时间 |
| createdAt | datetime | |

> ⚠️ TypeORM + better-sqlite3 陷阱：所有 `nullable` 联合类型字段（`varchar|null`/`datetime|null`）必须显式写 `type`，否则 synchronize 报 `DataTypeNotSupportedError` 拖垮全量 suite。

### 2.2 积分规则（`points.const.ts`）

```ts
export const POINT_RULES = {
  LESSON_COMPLETE: 1,   // 完成课程（沿用 AI-603 的 +1 星）
  TASK_COMPLETE: 1,     // 完成每日任务
  WORD_CORRECT: 1,      // 单词答对一次
  SPEECH_PASS: 2,       // 口语评分通过（≥60）
};
```

### 2.3 服务（`RewardsService`）— 积分/星星单一入口

- `awardStars(userId, n)`：**唯一**累加点。
  1. `usersRepo.increment({id}, 'totalStars', n)`；
  2. 读回 `totalStars` → `computeLevel` 重算，变化则 `usersRepo.update({id}, {level})`；
  3. `userPointsRepo` 自增 `balance`（无行则 `getOrCreatePoints` 建行）。
- `getOrCreatePoints(userId)` / `getBalance(userId)`。
- `spendPoints(userId, n)`：`balance < n` → 抛 `InsufficientPointsException(400)`；否则自减。
- `listRewards(activeOnly=true)` / `createReward(dto)` / `updateReward(id,dto)` / `deleteReward(id)`。
- `redeem(userId, rewardId)`：`spendPoints(cost)` + 建 `pending` 兑换单（快照 title/cost）。
- `listRedemptions({status?, userId?})`：家长看全部（可按 status 过滤）；孩子看自己。
- `approveRedemption(id)` / `rejectRedemption(id, reason?)`：置状态 + `decidedAt`。
- `seedDefaults()`（`onModuleInit`，测试环境跳过）：目录为空时插入内置奖励（见 §4）。

> 依赖方向：`RewardsModule` 为叶子（不依赖 Progress/AI/Tasks），避免循环；`ProgressModule`/`TasksModule`/`AiModule` 均 `imports: [RewardsModule]` 并注入 `RewardsService`。**从而 AI-701 不走 `ProgressModule` 入 `AiModule`，最小化 `ai.module.spec.ts` DI 改动**（仅补 `UserPoints/Reward/RewardRedemption` 仓库 override）。

### 2.4 控制器与端点（`RewardsController`）

全局前缀 `api`；孩子侧加 `JwtAuthGuard`（userId 取 `req.user.userId`）；审批/目录 CRUD 加 `ParentGuard`。

| Method | Path | Guard | 说明 |
|---|---|---|---|
| GET | `/rewards` | — | 列出上架奖励（商城展示） |
| GET | `/rewards/summary` | Jwt | 返回 `{ balance, totalStars, level, levelInfo }`（驱动 Home/奖励页） |
| GET | `/rewards/my-redemptions` | Jwt | 孩子的兑换记录（own userId） |
| POST | `/rewards/redeem/:rewardId` | Jwt | 申请兑换（扣余额，建 pending） |
| GET | `/rewards/redemptions?status=` | Parent | 家长待审批列表（全部用户） |
| POST | `/rewards/redemptions/:id/approve` | Parent | 批准 |
| POST | `/rewards/redemptions/:id/reject` | Parent | 驳回（可选 reason） |
| POST | `/rewards` | Parent | 新增奖励（目录 CRUD） |
| PATCH | `/rewards/:id` | Parent | 改奖励 |
| DELETE | `/rewards/:id` | Parent | 删奖励 |

### 2.5 家长审批门禁（`ParentGuard`）

```ts
@Injectable()
export class ParentGuard extends JwtAuthGuard {
  async canActivate(ctx): Promise<boolean> {
    if (!(await super.canActivate(ctx))) return false;       // 先校验 JWT（当前复用孩子会话）
    const req = ctx.switchToHttp().getRequest();
    const expected = process.env.PARENT_APPROVAL_TOKEN || 'parent-dev-token';
    return req.headers['x-parent-approval'] === expected;     // 临时：AI-702 PIN 会话上线后替换
  }
}
```

### 2.6 接入积分累加钩子

- `ProgressService.completeLesson` → `rewardsService.awardStars(userId, POINT_RULES.LESSON_COMPLETE)`（替换原内联 +1 星逻辑）。
- `ProgressService.recordWordAttempt` → 命中 `correct` 时 best-effort `awardStars(userId, POINT_RULES.WORD_CORRECT)`。
- `TasksService.completeTask` → 新完成分支 best-effort `awardStars(userId, POINT_RULES.TASK_COMPLETE)`（与 `maybeTriggerReport` 同口径 try/catch）。
- `AiSpeechFeedbackService.feedback` → `passed && userId 有效` 时 best-effort `awardStars(userId, POINT_RULES.SPEECH_PASS)`（绝不阻断反馈返回）。

## 3. 前端设计

### 3.1 API 客户端（`src/lib/api.ts`）

- `ProgressOverview` 扩展 `level: number` + `pointsBalance: number`（`getProgress` 后端返回）。
- 新增：`listRewards()` / `getRewardsSummary()`（= getProgress 复用）/ `getMyRedemptions()` / `redeemReward(id)` / `getPendingApprovals()` / `approveRedemption(id)` / `rejectRedemption(id, reason?)`。审批类请求带 `x-parent-approval` 头（取自 `NEXT_PUBLIC_PARENT_APPROVAL_TOKEN` || `'parent-dev-token'`）。

### 3.2 等级环（`src/components/LevelRing.tsx`）

复刻 `ProgressRing` 思路的 SVG 环，输入 `totalStars` → 经 `buildLevelInfo` 显示「Lv.X + 档名 + 本级进度 + 距下一级」，用于 Home 奖励卡与 `/rewards` 页。`mascotLevel.ts` 加 `LEVEL_NAMES` + `levelName(level)`。

### 3.3 TabNav

加 `{ href: '/rewards', label: '奖励', icon: Gift }`（lucide `Gift`）。

### 3.4 Home「我的奖励」卡（`src/app/page.tsx`）

在 MascotGrowthCard 之后插入 `RewardsHomeCard`：`data-component="RewardsHomeCard"`，展示 `progress.pointsBalance` + `LevelRing` + 「去兑换」深链 `/rewards`。

### 3.5 `/rewards` 页（`src/app/rewards/page.tsx`，AuthGate 包裹）

`data-component="RewardsStore"`，三段：
1. **余额 + 等级环**（`RewardsBalance`）：`getProgress().pointsBalance` + `LevelRing`。
2. **奖励商城**（`RewardCard` ×N，`data-reward-id`，`RedeemBtn`）：列出上架奖励，点击兑换。
3. **我的兑换**（`MyRedemptions`，`data-redemption-status`）：孩子自己的兑换记录 + 状态徽章。
4. **家长审批区**（`ParentApproval`，`ApprovalItem` + `ApproveBtn`/`RejectBtn`）：列出 pending 兑换，点击审批（带家长头）。标注「家长模式（PIN 锁将在 AI-702 上线）」。

所有写操作（redeem/approve/reject）后重新拉取列表，保证异步 UI 即时刷新；E2E 用 `waitForFunction` 等状态变更。
