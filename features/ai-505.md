# AI-505 — 每日 AI 报告自动生成触发

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM + better-sqlite3) | 分支: feat/ai-505
> 依赖: AI-502（POST /api/ai/report/daily，已落地的幂等生成） | 前置: feat/ai-504 | 下游: AI-506（家长周报）消费已落库报告
> 优先级: P1 | 在 M5 中的位置：AI-501→502→503→504→**505（本 feature）**→506

## 1. 目标

AI-502 已落地 `POST /api/ai/report/daily`（`AiReportService.generateDailyReport`），且**幂等**（同日已有报告直接返回）、**无活动自动友好默认**、**有活动调 AI 生成**、**AI 失败降级**。
AI-504 的 Home「今日 AI 小结」卡片在加载时调用该接口拉取报告。

但当前报告只在「用户打开 Home 触发前端拉取」时生成——若用户当天从未打开 Home，则报告不会生成，家长周报（AI-506）也拿不到数据。
本 feature 增加**后端自动触发**，让每日报告在两种条件下自动生成（且不重复）：

1. **完成当日全部任务** → 立即触发生成（孩子在完成最后一项任务的那一刻，报告就备好了）。
2. **每日固定时段（默认 20:00）** → 全量扫描所有用户补生成（覆盖「当天活跃但没做完所有任务 / 没打开 Home」的孩子）。

验收核心：**完成条件触发一次；不重复生成**（由 AI-502 幂等保证）。

## 2. 接口契约

本 feature **不新增 HTTP 路由**、**不新增前端 UI**（报告展示旅程已由 AI-504 覆盖）。仅新增后端触发逻辑。

### 2.1 Trigger A — 完成任务联动（改 `TasksService`）
- `TasksService` 新增构造依赖 `AiReportService`（来自 `@Global AiModule`，需把 `AiReportService` 加入 `AiModule.exports`，因 `AiModule` 已 `@Global`，`TasksModule` 无需 import 即可注入）。
- `completeTask(userId, taskId)` 在「本次为**新完成**（非 `alreadyCompleted`）」且落库成功后，调用私有方法
  `maybeTriggerReport(userId)`：
  - 调 `getDailyTasks(userId)` 取得当日全部任务及完成态；
  - 若 `tasks.length > 0 && tasks.every(t => t.completed)`（全部完成），则 `await aiReportService.generateDailyReport(userId)`；
  - 全程 `try/catch` 包住，自动生成失败仅 `logger.warn`，**绝不**影响任务完成响应（任务完成是主流程，报告生成是副作用）。
- 幂等保证：即便多次「全部完成」也不会重复生成（AI-502 同日直接返回已有）。

### 2.2 Trigger B — 每日 20:00 全量扫描（新 `ReportSchedulerService`）
- 新文件 `server/src/ai/report-scheduler.service.ts`，`@Injectable()`，注册进 `AiModule`（同模块可注入 `AiReportService`）。
- 构造依赖：`AiReportService` + `@InjectRepository(User) userRepo`（需在 `AiModule` 的 `TypeOrmModule.forFeature` 中追加 `User` 实体）。
- 公共方法：
  - `runDailySweep(): Promise<void>` — `const users = await this.userRepo.find();` 遍历每个 `u.id` 调 `generateDailyReport(u.id)`；**逐用户 try/catch**，单个用户失败不中断整轮。
  - `computeMsUntilNext(hour: number, now: Date): number` — 纯函数，返回距下一个 `hour:00`（本地）的毫秒数：若 `now < 今日 hour` → 今日 hour；否则 → 明日 hour（整点启动，不立即触发）。
  - `start()` / `stop()` — `start()` 用 `computeMsUntilNext(20, new Date())` 计算延迟，`setTimeout` 到点跑 `runDailySweep`，跑完后 `setInterval` 每 24h 再跑；句柄存 `this.timer` / `this.interval`，`stop()` 清除。
  - `onModuleInit()` — 仅当 `process.env.NODE_ENV !== 'test'` 且 `process.env.REPORT_SWEEP_ENABLED !== 'false'` 时 `start()`（避免单测/可选关闭时挂定时器）。
  - `onModuleDestroy()` — `stop()`。

### 2.3 行为边界（设计决策）
- **报告是生成时刻的快照**：若在 15:00 完成全部任务触发生成，之后当晚的额外学习不会改写该报告；20:00 扫描遇到已有报告直接跳过（幂等「不重复生成」）。
  - 这恰好满足验收「不重复生成」；对「当天活跃但未做完所有任务」的孩子，其报告由 20:00 扫描基于当日**全量**活动生成（此时已含晚间学习）。
- **20:00 扫描会为「无活动」用户也生成友好默认报告**（AI-502 无活动分支），保证 Home 卡片始终有内容；幂等，每人每天仅一份。

## 3. 数据模型 / 依赖

- 复用 `AiReport`（`ai_reports`）、`User`（`users`）实体，均已在 `appEntities` 注册。
- `AiModule.forFeature` 追加 `User`（与 `UsersModule` 重复注册同一实体仓库无冲突，与既有 `TaskCompletion` 等多实体同模块注册同口径）。
- 不引入新 npm 依赖（自实现轻量 `setTimeout/setInterval` 调度，避免引入 `@nestjs/schedule` 带来的安装/lock 风险与测试复杂度）。

## 4. 验收标准

- [ ] 完成当日**全部**任务（新完成时）触发一次 `generateDailyReport(userId)`；报告为生成时刻快照。
- [ ] 完成**部分**任务（未全部完成）/ 重复完成已完成的任务 → **不**触发。
- [ ] 用户当日**零任务** → 不触发（无「任务」可全部完成）。
- [ ] 每日 20:00（本地）`runDailySweep` 遍历所有用户各调一次 `generateDailyReport`，逐用户容错。
- [ ] `computeMsUntilNext` 在「当前 < 20:00」返回到今日 20:00 的延迟；「当前 ≥ 20:00」返回到明日 20:00（约 24h）。
- [ ] `nest build` / `tsc` 0 错误；jest 全绿；pre-commit 质量门强执通过。
- [ ] 任务完成主流程**不受**报告生成失败影响（副作用隔离）。

## 5. 风险点

- **副作用隔离**：`maybeTriggerReport` 必须 `try/catch`，否则 AI 超时/限流会让「完成任务」接口 5xx。已用 catch + `logger.warn` 兜底。
- **循环依赖**：`TasksService → AiReportService`；`AiModule` 已 `@Global` 且**不** import `TasksModule`，故无循环。`AiReportService` 仅需加入 `exports` 即可被 `TasksModule` 注入。
- **测试定时器泄漏**：`onModuleInit` 在 `NODE_ENV==='test'` 时跳过 `start()`；`ReportSchedulerService` 单测直接 `new` 不触发 `onModuleInit`；`ai.module.spec` 编译 `AiModule` 时（NODE_ENV=test）不会挂真定时器。
- **`ai.module.spec` 新增 `User` 实体**：须在 `compileAiModule` 中补 `getRepositoryToken(User)` 的假仓库覆盖，否则 DI 装配失败。
- **无裸 console**：全部走 `logger`（LOG-101 约定）。

## 6. 测试计划（硬约束 #6）

### 单元测试（jest + ts-jest，覆盖有逻辑分支的源码）
- **扩展 `tasks.service.spec.ts`**（注入 `AiReportService` 假对象）：
  - 完成最后一项任务（当日全部完成）→ `aiReportService.generateDailyReport` 被调用 1 次且参数为该 `userId`。
  - 完成一项但**未全部完成** → 不调用 `generateDailyReport`。
  - 完成已完成的任务（`alreadyCompleted:true`）→ 不调用 `generateDailyReport`。
  - 当日零任务（任务列表为空）→ 不调用 `generateDailyReport`。
- **新增 `report-scheduler.service.spec.ts`**（直接 `new ReportSchedulerService(aiReportService, userRepo)`，不触发 `onModuleInit`）：
  - `computeMsUntilNext`：当前 10:00 → ≈10h；当前 21:00 → ≈23h（到明日 20:00）；给定固定 `now` 断言精确毫秒。
  - `runDailySweep`：`userRepo.find` 返回 `[u1,u2]` → `generateDailyReport` 被调用 2 次，参数分别为 `u1.id`/`u2.id`。
  - `runDailySweep` 容错：`u1` 抛错时 `u2` 仍被调用、`runDailySweep` 不 reject。
  - `start()`/`stop()`：用 `jest.useFakeTimers()`，`start()` 后 `jest.getTimerCount()` 增加；`stop()` 后定时器被清除；断言到点后 `runDailySweep` 被调度（advanceTimersByTime 到计算延迟）。
