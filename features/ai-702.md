## 1. 目标与范围

AI-701 已实现「积分/奖励商城/兑换状态机」，但家长审批端点是**临时门禁**（`ParentGuard` 校验 `x-parent-approval: parent-dev-token` 明文 dev token）。AI-702 把这道临时门禁升级为**真正的家长 PIN 会话**：

- **4 位 PIN**：按 child 哈希存储（`User.parentPinHash`，bcrypt，非明文），验证通过签发**家长会话 JWT**（独立 token，`role: 'parent'`，15 分钟过期）。
- **控制面板 `/parent`**：PIN 门禁 → 进入后含「奖励审批（AI-701 兑换 pending→批准/驳回）」+「PIN 管理（修改 PIN）」+「未来 M5 报告入口预留」。
- **儿童模式默认无审批权限**：审批/奖励目录 CRUD 端点改由新 `ParentGuard` 校验家长 JWT；孩子（child JWT）无法审批。
- **PIN 修改入口**：首次进入需「设置 PIN」（无 PIN 时）；已进入后可「修改 PIN」（需旧 PIN 校验）。

> 安全口径说明：4 位 PIN 仅 10⁴ 组合，bcrypt 哈希仅满足「不落明文」基线（backlog 验收标准），属 demo 级控制；不引入限流/锁定（超范围），文档与质量门标注此已知限制。

## 2. 后端设计

### 2.1 实体改动（`server/src/entities/user.entity.ts`）

`User` 加一列（显式 `type`，避开 better-sqlite3 联合类型陷阱）：

| 字段 | 类型 | 说明 |
|---|---|---|
| parentPinHash | varchar nullable | 家长 PIN 的 bcrypt 哈希；null = 尚未设置 PIN |

### 2.2 新建 `server/src/parent/` 模块

**`parent.service.ts`**（`ParentService`，注入 `Repository<User>` + `JwtService`）：
- `hasPin(userId)`：`!!user.parentPinHash`。
- `verifyPin(userId, pin)`：`parentPinHash` 为空 → `false`；否则 `bcrypt.compare(pin, hash)`（捕获异常→`false`）。
- `setPin(userId, pin)`：校验 4 位数字（`/^\d{4}$/`）→ `bcrypt.hash(pin, 10)` → 更新 `parentPinHash`。（供「首次设置」）
- `changePin(userId, oldPin, newPin)`：`verifyPin(oldPin)` 失败 → 抛 `UnauthorizedException`；否则 `setPin(newPin)`。
- `signParentToken(userId)`：`jwtService.sign({ sub: userId, role: 'parent' }, { expiresIn: '15m' })`。

**`parent.controller.ts`**（`ParentController`，全局前缀 `api`）：
| Method | Path | Guard | 说明 |
|---|---|---|---|
| GET | `/parent/status` | Jwt(child) | `{ hasPin }` —— 前端决定显示「设置」还是「输入」PIN |
| POST | `/parent/verify-pin` | Jwt(child) | body `{ pin }` → `verifyPin` → 成功 `{ parentToken }`；失败 401 |
| POST | `/parent/setup-pin` | Jwt(child) | body `{ pin }` → 仅当 `hasPin` 为 false 时 `setPin` → `{ parentToken }`；已设置则 409 |
| POST | `/parent/change-pin` | **ParentGuard** | body `{ oldPin, newPin }` → `changePin` → `{ success: true }` |

> 说明：`setup-pin` / `verify-pin` / `status` 用 child JWT 鉴权（知道当前登录的是哪个孩子）；`change-pin` 必须先进入家长模式（ParentGuard），即「改 PIN 需先验证旧 PIN 拿到家长 token」。

**`parent.guard.ts`**（`ParentGuard`，替代 `rewards/parent.guard.ts`），**不再**继承 `JwtAuthGuard`、不再读 `x-parent-approval` 头：
```ts
@Injectable()
export class ParentGuard implements CanActivate {
  constructor(private jwtService: JwtService) {}
  canActivate(ctx: ExecutionContext): boolean {
    const req = ctx.switchToHttp().getRequest();
    const auth = req.headers.authorization;
    if (typeof auth !== 'string' || !auth.startsWith('Bearer ')) return false;
    try {
      const payload = this.jwtService.verify(auth.slice(7));
      if (payload?.role !== 'parent') return false;
      req.user = { userId: payload.sub, role: 'parent' };
      return true;
    } catch {
      return false;
    }
  }
}
```

**DTOs**（`parent/dto/`）：`VerifyPinDto { pin }`、`SetupPinDto { pin }`、`ChangePinDto { oldPin, newPin }`，均 `@IsString() @Matches(/^\d{4}$/, { message: 'PIN 必须是 4 位数字' })`。

**`parent.module.ts`**：`providers: [ParentService]`、`controllers: [ParentController]`、`exports: [ParentGuard]`（供 RewardsModule 用）。`ParentService` 需 `JwtModule`（全局已注册）与 `User` 仓库（`TypeOrmModule.forFeature([User])`）。

### 2.3 接线（替换 AI-701 临时门禁）

- `RewardsModule`：`imports: [..., ParentModule]`；`RewardsController` 中 `import { ParentGuard } from '../parent/parent.guard'`。

## 3. 前端设计

### 3.1 API 客户端（`src/lib/api.ts`）

- **移除** `PARENT_APPROVAL_TOKEN` 常量与 `parentApprovalHeaders()`（AI-701 临时）。
- 新增模块内存 `parentToken`：`setParentToken(t)` / `getParentToken()` / `clearParentToken()`（与 `accessToken` 同口径，仅内存，刷新即清 —— 家长模式每次刷新需重新输 PIN，对儿童产品是正向安全摩擦）。
- `request<T>(path, options, auth=true, token?: string | null)`：新增第 4 参数 `token`；当传 `token` 时 Authorization 用其值（覆盖 `accessToken`）；不传则沿用 `accessToken`。
- 新增：
  - `getParentStatus(): Promise<{ hasPin: boolean }>`（`GET /parent/status`）
  - `verifyParentPin(pin): Promise<{ parentToken: string }>`（`POST /parent/verify-pin`）
  - `setupParentPin(pin): Promise<{ parentToken: string }>`（`POST /parent/setup-pin`）
  - `changeParentPin(oldPin, newPin): Promise<{ success: boolean }>`（`POST /parent/change-pin`，带 parentToken）
- **审批类请求改用 parentToken**：`getPendingApprovals` / `approveRedemption` / `rejectRedemption` 调用 `request(..., true, getParentToken())`（不再带 `x-parent-approval` 头）。

### 3.2 `/parent` 控制面板（`src/app/parent/page.tsx`，AuthGate 包裹）

`data-component="ParentPanel"`；两段状态：

1. **PIN 门禁**（`data-component="ParentPinGate"`，未持家长 token 时显示）：
   - 4 位 PIN 输入（`data-component="PinInput"`）+ 按钮（`data-component="PinSubmit"`）。
   - 挂载时 `getParentStatus()` 决定文案：
     - `hasPin=false` → 「设置家长 PIN」（提交调 `setupParentPin` → 存 parentToken → 进面板）
     - `hasPin=true` → 「输入家长 PIN」（提交调 `verifyParentPin` → 存 parentToken → 进面板）
   - 校验失败显示 `data-component="PinError"`（如「PIN 错误」/「PIN 必须是 4 位数字」）。

2. **面板**（持家长 token 时显示）：
   - **奖励审批区**（`data-component="ParentApprovals"`）：`getPendingApprovals('pending')` 列表 + 「批准」(`data-component="ApproveBtn"`)/「驳回」(`data-component="RejectBtn"`)；写后重拉。
   - **PIN 管理区**（`data-component="PinManage"`）：旧 PIN + 新 PIN 输入 + 「修改 PIN」(`data-component="ChangePinBtn"`)，调 `changeParentPin`。
   - **退出家长模式**按钮（`data-component="ExitParentBtn"`）：`clearParentToken()` → 回到门禁（E2E 用它验证「锁住儿童」）。
   - **M5 报告入口预留**（`data-component="ReportPlaceholder"`）：禁用卡片「家长周报（即将上线）」，标注 AI-507 预留，不跳转。

### 3.3 TabNav

加 `{ href: '/parent', label: '家长', icon: ShieldCheck }`（lucide `ShieldCheck`）。PIN 锁挡住儿童进入面板，故暴露入口无妨。

### 3.4 `/rewards` 页改为纯儿童商城

移除「家长审批区」`ParentApproval` 及其 `ApprovalItem`/`ApproveBtn`/`RejectBtn`；`loadAll`/`handleRedeem` 不再调 `getPendingApprovals`（改由 `/parent` 负责）。保留：余额+等级环、可用奖励、我的兑换（status 徽章）。

## 4. 验收标准（对应 backlog AI-702）

- [ ] 家长 PIN 4 位，bcrypt 哈希存储于 `User.parentPinHash`，**不落明文**（单测断言哈希 ≠ PIN 明文）。
- [ ] PIN 锁可挡儿童进入家长区：`/parent` 未持家长 token 时仅显示 PIN 门禁；child JWT 无法调用审批端点（ParentGuard 拒 `role!=='parent'`）。
- [ ] 控制面板可批准/驳回兑换：家长 PIN 验证通过后签发家长 JWT，审批端点放行，`pending → approved/rejected`。
- [ ] PIN 修改入口：首次「设置 PIN」（无 PIN 时）；已进入后「修改 PIN」（旧 PIN 校验）。修改成功后家长 token 刷新。
- [ ] 未来 M5 报告入口预留（占位卡片，不实现真实跳转）。
- [ ] AI-701 的 `x-parent-approval` 明文 dev token 门禁被完全移除，无残留引用。
- [ ] 四质量门（consistency/tests/review/optimization）全绿，`.quality-gate.json` staged，仅 commit 不 push。

- `parent.service.spec.ts`（mock `Repository<User>` + `JwtService`）：
