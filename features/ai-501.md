# AI-501 — 每日 AI 报告数据模型（实体 + 建表）

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM) | 分支: feat/ai-501
> 依赖: — | 前置: 当前链 feat/ai-409←...←feat/ai-501（在 master 上建新分支）| 下游: AI-502（报告接口）/ AI-503（ReportAgent）/ AI-504（Home 卡片）/ AI-505（自动触发）/ AI-506（家长周报）消费本实体

## 1. 目标

为 M5「AI 错题与进度报告」落地**数据底座**：建立 `ai_reports` 表，记录每个儿童每一天的 AI 学习小结
（`userId` / `date` / `summaryText` / `weakWords` / `suggestionText` / `createdAt`）；
以 `(userId, date)` **唯一约束**保证「同日重复生成返回已有报告」（AI-502 的生成幂等由该约束兜底）。
后续 AI-502（聚合接口）/ AI-504（Home「今日 AI 小结」卡片）/ AI-506（家长周报）将直接消费本 feature 的实体与 `AiModule` 仓库。

## 2. 接口契约

### 后端（纯数据模型，无新 HTTP 路由；路由在 AI-502 落地）
- 新增 `AiReport` 实体 → 表 `ai_reports`（字段见 §3）。
- `(userId, date)` 组合唯一：`@Unique(['userId', 'date'])`，与 `AiUsage`（AI-107）同口径——
  保证 AI-502 同日重复生成时 `save` 命中唯一约束、可被业务层捕获并返回已有报告，实现幂等。
- 与 `AiUsage` / `AiSpeechAttempt` 同口径：`userId` 存 `varchar` **非硬外键**（审计型追加记录，不级联删 User）。
- 实体注册进 `config/database.config.ts` 的 `appEntities`（dev `synchronize` 自动建表，与
  AI-107/108/201/301 一致），并注册进 `AiModule` 的 `TypeOrmModule.forFeature`（供 AI-502 注入仓库）。

## 3. 数据模型

- `AiReport` (`ai_reports`)：
  - `id` uuid PK
  - `userId`(varchar 255, **index**) — 报告归属儿童
  - `date`(varchar 10, **index**) — 报告日期 `YYYY-MM-DD`（本地日，与 `AiUsage.date` 口径一致）
  - `summaryText`(text) — 鼓励语气的总体小结（AI-503 输出）
  - `weakWords`(simple-array, default '') — 弱项单词列表（如 `['apple','banana']`）；
    **采用 `simple-array` 而非 `json`**：项目 `better-sqlite3` 驱动未使用 `json` 列类型（grep 确认无先例），
    `simple-array` 在 sqlite/postgres 双驱动可移植，与 `AiSpeechAttempt.weakPhonemes` / `Sentence` 同口径；
    JSON 结构化契约（含弱项详情）保留在 AI-502/503 的 DTO/agent 层，落库只存单词名清单。
  - `suggestionText`(text, default '') — 给儿童的明日建议（AI-503 输出）
  - `createdAt`(CreateDateColumn)
- **不写迁移**：沿用项目 `synchronize` 模式（与 AI-107/108/201/301 一致）。
- **时间列铁律**：一律 `@CreateDateColumn()`，不用 `@Column({type:'timestamp'})`（better-sqlite3 不支持，AI-107 踩坑）。
- **可移植**：无 DB 原生 enum；`weakWords` 用 `simple-array`（database.config 注释确认可移植）。
- **唯一约束**：`@Unique(['userId','date'])`，重复插入触发 TypeORM `QueryFailedError`（SQLITE_CONSTRAINT_UNIQUE）。

## 4. 验收标准

- [ ] `ai_reports` 表由 `synchronize` 自动建立（`DataSource.initialize` 不抛错，CI seed 同等校验）。
- [ ] `(userId, date)` 唯一：同用户同日两条 `save` 第二次抛唯一约束错误（AI-502 据此返回已有报告）。
- [ ] `weakWords` 为空 / 多元素时经 `simple-array` round-trip 一致；`summaryText` / `suggestionText` 正确落库。
- [ ] `createdAt` 自动生成。
- [ ] `nest build` / `tsc` 0 错误；jest 全绿；覆盖率 90/70 基线不退化；pre-commit 质量门强执通过。

## 5. 风险点

- **时间列**：遵守铁律，避免 CI seed `DataTypeNotSupportedError`。
- **无硬 FK**：`userId` 不级联删 User（审计型追加记录，与 `AiUsage` 同口径）。
- **弱项存储口径**：`weakWords` 用 `simple-array`（项目无 json 列先例，强可移植）；结构化弱项详情在 AI-502/503 DTO 层处理，本层只存单词清单——避免把 JSON 序列化耦合进实体。
- **不越界**：本 feature 仅建表 + 实体 + 模块注册，不实现聚合/生成/页面（属 AI-502/503/504），不自创需求。

## 6. 测试计划（硬约束 #6）

### 单元测试（jest + ts-jest，覆盖有逻辑分支的源码）
- `ai-report.entity.spec.ts`：in-memory better-sqlite3 + `appEntities` 行为测试
  - synchronize 建表：`ai_reports` 表存在，save 后 `id` 生成、`createdAt` 为 `Date`。
  - 默认值：`weakWords` 空数组 round-trip 仍为 `[]`；`suggestionText` 默认 `''`。
  - `simple-array` 多元素 round-trip 一致（`['apple','banana','cat']` 存读一致，可移植到 postgres）。
  - `(userId,date)` 唯一约束：同用户同日第二次 `save` 抛 `QueryFailedError`（唯一冲突），证明幂等兜底成立。
  - 不同用户 / 不同日期可共存（约束只作用于同组合）。

### BDD/E2E 用户旅程
- **豁免（约束 #6）**：纯数据模型 + 后端实体增强，无前端 UI 旅程、无 HTTP 路由（路由在 AI-502 落地）；
  不为纯后端写 BDD（与 AI-108 / AI-201 / AI-301 同口径，已在 `features/backlog.md` 标注）。
  E2E 报告旅程随 AI-504（Home「今日 AI 小结」卡片）交付。
