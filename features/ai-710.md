# AI-710 — 家庭绑定（家长创建 / 认领孩子账号）

> 状态: backlog | 栈: node-ts（NestJS 后端 + Next.js 前端，全栈） | 分支: feat/ai-710
> 来源: `features/backlog.md` M8 / AI-710；用户设想：家长注册 → 家长创建孩子账号 → 孩子自动继承家长 AI provider。

## 1. 目标

把「家长账号 = 家庭枢纽」落为可操作的 UX：

1. **公开注册仅限家长账号**：注册页不提供「孩子」角色选项；后端 `POST /auth/register` 强制 `role:'parent'`，对 `role:'child'` 入参一律忽略或拒绝（400），**孩子账号不允许自注册**。
2. **家长直接创建孩子账号**：在家长面板内填昵称 / 用户名 / 密码即生成 `role:'child'`、`parentId=家长.id` 的账号，孩子用这套凭据自行登录。
3. **家长认领已有孩子**：输入孩子用户名 + 密码校验通过后，把该孩子的 `parentId` 指向自己（覆盖旧归属需二次确认）。
4. 创建 / 认领完成后，孩子端发出的 AI 请求**自动经由 AI-705 的 `AiProviderRouter` 解析到家长默认 provider**（无需任何额外代码，链路已通）。

用户价值：让「家长配 key → 孩子用」从预留字段变成真实可走通的闭环，是 AI-711 / AI-712 的前置依赖。

## 2. 接口契约

### 2.1 后端（全部挂 `ParentGuard`，`req.user.userId` = 家长 `User.id`）

| 方法 | 路径 | 说明 | 请求体 / 参数 | 响应 |
|---|---|---|---|---|
| POST | `/parent/children` | 家长创建孩子账号 | `CreateChildDto` | `ChildView`（含临时明文密码仅本次返回一次） |
| POST | `/parent/children/claim` | 认领已有孩子（校验其密码） | `ClaimChildDto { username; password }` | `ChildView` |
| GET | `/parent/children` | 列出本人名下孩子 | — | `ChildView[]`（不含密码，含进度摘要字段占位） |
| DELETE | `/parent/children/:childId` | 解除归属（仅清 `parentId`，不删账号） | — | `204` |

- `CreateChildDto`：`nickname`(string,1..40)、`username`(string,3..30, 唯一)、`password`(string, 强度同注册)、`ageRange?`(枚举, 可选)。
- `ChildView`：`id, nickname, username, role:'child', level, totalStars, streakDays, hasProviderOverride(预留 AI-711), createdAt`。**绝不**返回 `password`。
- 鉴权：`ParentGuard` 拒绝儿童 JWT；`parentId` 一律服务端取 JWT 的 userId，禁止客户端传入（越权返回 403/404）。
- **公开注册端点约束**：`POST /auth/register` 在本 feature 后**仅创建家长账号**。若请求体带 `role:'child'`，服务端忽略该字段并强制存 `role:'parent'`（或返回 400，取「忽略并强制 parent」以兼容旧客户端）；孩子账号的唯一创建入口是本节 `POST /parent/children`（受 `ParentGuard` 保护）。
- 创建时若 `username` 已存在 → 409（提示「该用户名已被占用，请认领或直接换名」）；认领时密码错误 → 401；认领他人孩子 → 409（归属冲突，需先解除）。

### 2.2 前端

- 家长页 `src/app/parent/page.tsx` 新增「我的孩子」卡片：
  - 孩子列表（昵称 / 用户名 / 等级 / 星星），每行「解除绑定」按钮。
  - 「添加孩子」向导：`Tab` 切换「新建账号」（昵称/用户名/密码表单）与「认领已有」（用户名/密码）。提交调对应接口，成功后列表刷新，并提示「已自动使用该家长配置的 AI」。
- 注册页 `src/app/[locale]/register/page.tsx` 定位为**家长注册页**：移除（或默认隐藏）任何角色选择控件，表单只收集用户名 / 密码 / 昵称，提交时显式 `role:'parent'`（或不传、由后端强制 parent）；标题与文案明确「创建家长账号」。可保留可选「家长邀请码」占位字段（本期不实现邀请码，仅留 UI 槽位，AI-711/712 后扩展）。
- 路由：家长登录后（`user.role==='parent'`）默认进 `/parent` 面板（AI-707 已就）；孩子登录进 `/`。

## 3. 数据模型

- **复用现有 `User` 实体**（`server/src/entities/user.entity.ts`）：`parentId` 字段已在 AI-705 新增（可空 uuid），本 feature **不新增任何表 / 列**，仅通过端点写 `parentId`。
- `role` 落库规则：创建孩子时强制 `role:'child'`（仅经 `POST /parent/children`）。
- **公开注册默认角色变更**：`auth.service.ts` 的 `register()` 当前默认 `role:'child'`（`role && role === 'parent' ? 'parent' : 'child'`），本 feature 改为**公开注册默认且强制 `role:'parent'`**，孩子角色只能通过受 `ParentGuard` 保护的 `POST /parent/children` 在家长上下文创建。

> 零新增实体 = 零迁移风险；向后兼容（历史 `parentId` 全 null 的孩子在列表里不出现，家长可认领）。

## 4. 与 AI-705 路由的衔接（关键）

`AiProviderRouter.resolve()` 已具备：`role==='child'` → 查 `User.parentId` → `resolveDefault(parentId)` 取家长默认配置。**只要本 feature 把孩子的 `parentId` 写对，孩子 AI 调用即自动走家长 provider**，无需改动 router。AI-711 才会在此基础上加 per-child 覆盖。

## 5. 验收标准

- [ ] 家长可创建孩子账号并立即在列表看到；孩子用该凭据能登录。
- [ ] 孩子登录后发出的聊天 / 报告 / TTS 请求，实际落到家长配置的 provider（用 mock server 端点验证请求 header/body 来自该 provider）。
- [ ] 家长可认领已有孩子（密码校验）；认领冲突 / 密码错误有清晰报错。
- [ ] 家长可解除绑定（仅清 `parentId`）；解除后孩子回退 env 默认 provider。
- [ ] 越权 / 儿童 JWT 不可访问 `/parent/children*`（ParentGuard 拒绝）。
- [ ] 公开注册无法创建孩子账号：直接调 `POST /auth/register` 带 `role:'child'` 被忽略 / 拒绝，落库为 `role:'parent'`；注册页 UI 无「孩子」角色选项，文案明确「创建家长账号」。
- [ ] 单元 + BDD/E2E 覆盖（见 §8）。

## 6. 测试计划（硬约束 #6）

### 6.1 单元测试（有逻辑分支的源码）
- `auth.service.spec.ts`：register 不带 `role` → 落库 `role:'parent'`；register 带 `role:'child'` → 被忽略或 400，落库仍为 `role:'parent'`；register 带 `role:'parent'` → 正常存 parent。
- `parent.service.spec.ts`：createChild 落库 `role:'child'` + `parentId` 正确；username 重复 → 409；claim 密码错误 → 401；claim 他人孩子 → 409；unlink 仅清 `parentId` 不删账号；跨账号访问拒绝。
- `parent.controller.spec.ts`：ParentGuard 拒绝儿童 JWT；端点契约字段正确（`ChildView` 不含密码）。

### 6.2 BDD/E2E（用户可感知旅程，必做）
- 场景：家长登录 → 进入「我的孩子」→ 新建一个孩子（昵称/用户名/密码）→ 列表出现该孩子 → 用孩子凭据登录 → 进入聊天选场景发一条消息 → 断言后端收到来自家长 provider 配置的请求（mock server 记录）→ 家长解除绑定 → 孩子再次请求回退 env 默认（mock）。

## 7. 风险点

| 风险 | 缓解 |
|---|---|
| 家长创建弱密码孩子账号 | 复用注册密码强度校验（class-validator），不降低标准 |
| 认领覆盖他人孩子 | 归属冲突 409，需先解除旧归属；解绑只清 parentId 不删数据 |
| 跨账号越权 | `parentId` 强制取 JWT userId；`ownerUserId` 校验贯穿列表/操作 |
| 邀请码槽位空置 | 本期仅留 UI 占位，不接逻辑，避免半成品流程 |
| 孩子自注册绕过家庭绑定 | 公开注册端点强制 `parent`；孩子创建入口仅限 `ParentGuard` 下的 `/parent/children`，自注册 child 路径被堵死 |
