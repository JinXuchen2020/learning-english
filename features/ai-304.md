# AI-304 — STT 集成（转写 + 降级编排层）

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM) | 分支: feat/ai-304
> 依赖: AI-102(BigModelProvider 降级口径), AI-106(retry/降级调用链), AI-303(评测接口可消费本能力) | 前置链: feat/ai-303
> 下游: AI-305(发音评分策略, 用转写文本相似度兜底), AI-306(据 degraded 给低分 + 落库), AI-307(`/speech` 消费评分)

## 1. 目标

为 M3「AI 每日口语训练」交付**语音转写（STT）能力编排层**：新增 `AiTranscribeService.transcribe()`，
调用 `provider.transcribe`（经 AI-106 的「重试 + 配额 + 日志」韧性链），并对**降级 / 失败结果做识别标注**
（`degraded` / `degradeReason`），**不抛错**，供下游消费：

- **AI-305**（发音评分策略）：当 `degraded` 为真时走「转写文本相似度（编辑距离）+ LLM 评估」兜底评分。
- **AI-306**（评分反馈）：据 `degraded` / 低置信度给低分（呼应 backlog「静音音频返回低分」）。

本 feature **不实现底层 STT 网络调用**（真实 STT 端点不在本项目能力内，见 §6），只做**调用编排 + 降级识别**；
可测性由 `MockAiProvider.transcribe` 返回确定性 `MOCK_TRANSCRIPT` 保证（验证「清晰发音的单词可被转写」）。

## 2. 接口契约

### 2.1 纯逻辑层 `transcribe-result.util.ts`（node 可测，对齐 AI-302/303 lib 模式）
- `normalizeTranscript(text: string): string` — 转小写、折叠连续空白、去除首尾空白、剥离常见标点
  （`, . ! ? ; : " ' ( ) [ ]` 等，保留字母/数字/空白），用于下游相似度比对与展示归一化。
- `DEGRADED_CONFIDENCE_THRESHOLD = 0.3` — 置信度低于此值视为低质转写。
- `TranscriptDegradeReason = 'empty' | 'low_confidence' | 'provider_error'`。
- `classifyTranscript(input: { text?: string; confidence?: number }): { degraded: boolean; reason?: TranscriptDegradeReason }`
  — `text` 为空/纯空白 → `{ degraded:true, reason:'empty' }`；`confidence != null && confidence < 阈值`
  → `{ degraded:true, reason:'low_confidence' }`；否则 `{ degraded:false }`。
- `summarizeTranscript(result: TranscriptResult): TranscriptSummary` — 合并产出
  `{ rawText; normalizedText; wordCount; confidence?; degraded; degradeReason? }`（`wordCount` 取自 `normalizedText` 分词）。
- **零依赖纯函数**，无 Nest / 无 logger，便于 node 单测直覆。

### 2.2 服务 `AiTranscribeService`
- 注入 `AI_PROVIDER_TOKEN`（`AiProvider`，即 AI-106 包装后的完整链：retry + 配额 + 日志）。
- `async transcribe(audio: AudioInput, opts?: TranscribeOptions): Promise<TranscriptOutcome>`
  1. `try { const r = await provider.transcribe(audio, opts) }` — **捕获任何异常**（provider 网络层未来接入时可能抛 `AiProviderException`）。
  2. 异常分支 → 返回降级结果 `{ text:'', confidence:0, durationMs:0, degraded:true, degradeReason:'provider_error' }`
     + `logger.warn`（**不抛错**，与 AI-102 降级口径一致：降级仅标记不阻断）。
  3. 成功分支 → 调 `classifyTranscript({ text:r.text, confidence:r.confidence })` 合并 `degraded`/`degradeReason`，
     原样透传 `words`/`durationMs`，返回 `TranscriptOutcome`。
- `TranscriptOutcome = TranscriptResult & { degraded?: boolean; degradeReason?: TranscriptDegradeReason }`
  — **类型在 service 文件内定义，不污染 `AiProvider` 接口契约（AI-101）**，避免跨 feature 改动接口。
- 用 `logger`，**无裸 console**。

### 2.3 注册（AiModule，@Global）
- `providers` 加 `AiTranscribeService`；`exports` 加 `AiTranscribeService`（供 AI-305 注入）。
- 仅依赖已注册的 `AI_PROVIDER_TOKEN`，**不引入新的 Repository 依赖**（守边界，不落库、不查词表）。

## 3. 验收标准
- [ ] `MockAiProvider` 下 `transcribe()` → 非空 `text`（MOCK_TRANSCRIPT）、`degraded=false`、`confidence=1`（清晰发音可被转写）。
- [ ] `provider.transcribe` 抛错 → 返回降级结果（`degraded:'provider_error'`、空文本）**且不抛异常**。
- [ ] provider 返回空 `text` → `degraded:'empty'`；低置信度（<0.3）→ `degraded:'low_confidence'`。
- [ ] `normalizeTranscript` 正确归一化（小写/去标点/折叠空格）。
- [ ] 服务透传 provider 结果（含 `words`/`durationMs` 轴）供 AI-305 对齐。
- [ ] `tsc --noEmit`(server) 0 错误；`nest build` 通过；`jest` 全绿；覆盖率 90/70 基线不退化。
- [ ] pre-commit 质量门强执通过。

## 4. 风险点
- **E2E 豁免（约束 #6）**：纯后端服务（无 HTTP 端点、无前端 UI；AI-303 评测接口是消费者，本服务是其内部依赖）。
  按本项目「不为纯后端逻辑写 BDD」铁律豁免 BDD/E2E，验收由单元测全覆盖；用户级口语旅程随 AI-307 `/speech` 交付。
  与 AI-301 / AI-303 / AI-106 纯后端豁免同口径。
- **真实 STT 端点未接入（边界）**：智谱 BigModel 无公开 STT API（AI-102 已定 `transcribe` 返回降级空结果），
  本项目不硬接未配置的真实端点（无 key 无法验证，违反质量门）。`AiTranscribeService` 的职责是**调用编排 +
  降级识别标注**，真实 STT 接入留作后续增强（如接入 Azure / 第三方，届时 provider 实现替换即可，接口不变）。
  当前 BigModel 返回空降级、`Mock` 返回确定性转写，二者共同保证 AI-304 行为可测。
- **不落库**：STT 结果持久化在 AI-306（消费 AI-301 `ai_speech_attempts`），本 feature 不引入该依赖。
- **降级不抛错**：异常 / 空 / 低置信统一降级标记，与 AI-102 既定降级口径一致，避免阻断上游评分流程。

## 5. 测试计划（硬约束 #6）
### 单元测试（jest，node，fake provider）
- `transcribe-result.util.spec.ts`：`normalizeTranscript`（大写→小写 / 标点剥离 / 多空白折叠 / 空串）、
  `classifyTranscript`（空 text→empty / 低置信→low_confidence / 正常 / confidence 缺失不误判）、
  `summarizeTranscript`（合并 degraded + wordCount 计算）。
- `ai-transcribe.service.spec.ts`：fake `AiProvider`（transcribe 记录入参并返回预设 `TranscriptResult`）；覆盖
  成功(带 words 透传, degraded=false) / 空 text(degraded='empty') / 低置信(degraded='low_confidence') /
  provider 抛错(降级 degraded='provider_error' 且**不抛异常**) / provider 入参断言(audio, opts 透传)。
- 回归：`ai.module.spec.ts` **无需改动**（`AiTranscribeService` 仅依赖模块内已注册的 `AI_PROVIDER_TOKEN`，
  编译期 DI 可解析）。
