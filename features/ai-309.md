# AI-309 — 句子跟读库（Sentence Library）

> 状态: in-progress | 栈: node-ts (NestJS 10 + TypeORM) + next-ts (Next.js 14) | 分支: feat/ai-309
> 依赖: AI-306(评分反馈/落库) / AI-307(`/speech` 页消费) / AI-303(评测接口, sentenceId 路径打通) | 前置链: feat/ai-308
> 下游: 句子模式口语训练（本 feature 在 `/speech` 页启用）；AI-602（难度自适应，可选消费 level 字段）

## 1. 目标

为 M3「AI 每日口语训练」补齐**句子跟读库**：建立 `Sentence` 实体与预置分级跟读句，
提供可查询接口（`GET /api/sentences`，按 `level` / `wordText` 过滤），并把 AI-303 评测接口里
此前显式返回 400 `SENTENCE_SCORING_NOT_READY` 的 `sentenceId` 路径**打通为可用**——查库取
`Sentence.text` 作参考文本进入评分。同时在前端 `/speech` 页增加**单词 / 句子双模式切换**，
句子模式加载句库、渲染句子卡片并以 `sentenceId` 提交评测。

本 feature 收尾 M3「听→录→评→星」闭环的**句子维度**，使 AI-303 DTO 的 `sentenceId` 三选一
真正落地（此前仅 `wordId` / `referenceText` 可用）。

## 2. 数据模型

### `Sentence` 实体（`server/src/entities/sentence.entity.ts`，表 `sentences`）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid PK | 自动生成 |
| `text` | varchar/text | 英文跟读句（评测参考文本） |
| `meaning` | varchar/text | 中文释义（前端展示） |
| `level` | varchar(16) default `'L1'` | 分级 L1/L2/L3（难度递增） |
| `wordTexts` | simple-array | 关联 P0 词汇（存单词**文本**字符串，如 `['cat','dog']`）；双驱动可移植，避免 seed 期 uuid 耦合 |
| `tags` | simple-array | 主题标签（如 `['animal','greeting']`）便于后续检索 |
| `lessonId` | varchar nullable | 预留与课程/课节关联（当前 seed 不填，留扩展位） |
| `sortOrder` | int default 0 | 同 level 内排序 |

> 关联语义：`wordTexts` 以**词汇文本**而非 uuid 关联课程词汇（种子里 Word 为 uuid 自动生成，
> 文本关联更稳健，且满足「与课程词汇关联 / P0 单词覆盖」验收）。评分仅需 `text`，关联字段供
> 前端高亮/后续自适应消费，不参与评分链路。

## 3. 接口契约

### 查询句库 `GET /api/sentences`（SentencesController，`@UseGuards(JwtAuthGuard)`，与 WordsController 同口径）
- 查询参数（可选）：
  - `level`：仅返回该分级（如 `L1`）。
  - `wordText`：仅返回 `wordTexts` 含该词汇文本的句（不区分大小写按包含匹配）。
- 响应：`Sentence[]`，按 `level` 升序 → `sortOrder` 升序。
- 鉴权：沿用 WordsController 的 `JwtAuthGuard`（前端 `request()` 默认带内存 token；E2E 已登录）。

### AI-303 `sentenceId` 路径打通（`AiSpeechEvaluatorService.resolveReferenceText`）
- 原：`sentenceId` 存在 → 抛 400 `SENTENCE_SCORING_NOT_READY`。
- 新：`sentenceId` 存在 → `sentenceRepo.findOne({where:{id}})`：
  - 命中 → 返回 `sentence.text` 作参考文本（进入评分，与 `wordId` 同口径）。
  - 未命中 → 抛 404 `SENTENCE_NOT_FOUND`（替代原 400，语义与 `WORD_NOT_FOUND` 对齐）。
- 同时更新 `speech-evaluate.dto.ts` 的 `sentenceId` JSDoc（移除「句库未落地」措辞）。

## 4. 预置数据（seed.ts）

新增 `sentenceRepo`，清表后写入 **36 句**分级跟读句，覆盖 P0 动物词汇（Cat/Dog/Fish/Bird/Rabbit/
Frog/Horse/Duck/Bear/Turtle）并补充生活主题，分布：
- L1（12 句）：极简主谓/主系表，单句 ≤4 词，含 1 个 P0 词。
- L2（12 句）：简单句，含 1-2 个 P0 词 + 基础修饰。
- L3（12 句）：复合/带连词，含 2+ 个 P0 词或更长结构。

每条写入 `wordTexts`（覆盖其用到的 P0 词文本，小写）与 `tags`（主题）。seed 末尾日志增加
`sentences` 计数。

## 5. 前端（`/speech` 句子模式）

- `src/lib/api.ts`：新增 `getSentences(query?)`（`request<Sentence[]>("/sentences?...")`）；

  - 提交时按模式携带 `wordId` 或 `sentenceId`。
  - 句子模式空数据（`sentences.length===0`）友好提示（理论不发生，seed 已铺）。
- 纯逻辑（如有可测分支，如 mode 切换的状态派生）以 vitest 覆盖；UI 行为由 E2E 覆盖。

## 7. 风险点
- **E2E 导航铁律（沿用 AI-308）**：token 存内存，必须从 TabNav 点击进入 `/speech`（client-side 导航），
  禁用 `page.goto('/speech')`。句子模式切换为页面内 state 变更，无整页导航，天然安全。
- **共享 sqlite 污染**：反复跑 E2E 累积状态；提交前清库重 seed + 重启后端拿干净读数（沿用 AI-308 教训）。
- **双 forFeature 注册**：`Sentence` 实体在 `SentencesModule` 与 `AiModule` 各注册一次（与既有 `Word`
  同口径，NestJS 允许），`ai.module.spec.ts` 须补 `getRepositoryToken(Sentence)` 桩。
- **speech-evaluate.dto.ts**：仅改 JSDoc，字段定义不变，向后兼容。
- **不破坏既有 word 模式**：句子模式为增量分支，单词模式路径零改动（共用卡片/反馈组件）。
