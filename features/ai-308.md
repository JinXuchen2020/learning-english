# AI-308 · 口语任务联动（Daily-task → /speech 深链 + 完成回写）

> 状态：in-progress · 优先级：P0 · 依赖：AI-307（`/speech` 页）、现有 TasksModule（AI-206/209）
> 分支：`feat/ai-308`（自 `feat/ai-307` 切出）

## 1. 目标
把「每日任务」里的**口语类（mic 图标）任务**变成可直达的入口：
- Home 上 mic 任务卡片点击 → 客户端导航到 `/speech?taskId=<id>`；
- 用户在 `/speech` 完成整轮跟读会话（听→录→评→反馈→得星）后，`/speech` 自动调用
  `PATCH /tasks/:id/complete` 把该任务勾选完成，并触发后端已有的「进度回写」（计划任务回写
  `study_plan_days.isDone`；`getProgress` 反映 stars/streak）。
- 验收闭环：**从 Home 任务卡直达口语页 → 完成会话 → 回到 Home，任务显示已勾选**。

headphones / pencil 类任务**保持现状**（点击即 `completeTask`，不导航）。

## 2. 契约 / 接口（均复用现有，无新增后端）
| 用途 | 端点 | 说明 |
|---|---|---|
| 取每日任务 | `GET /tasks/daily` | 返回 `{id,title,description,icon,completed}`；`icon ∈ headphones|mic|pencil` |
| 完成任务（幂等） | `PATCH /tasks/:id/complete` | 后端 `TasksService.completeTask`：写 `task_completions` + 计划任务回写 `study_plan_days.isDone` |

前端既有封装已就绪：`api.getDailyTasks()`、`api.completeTask(taskId)`（`src/lib/api.ts`）。

## 3. 数据模型
**无新实体、无新表、无 schema 变更。** 仅前端行为变化：
- `DailyTask.icon === "mic"` 且 `!completed` → 渲染为 `<Link href={speakingTaskHref(id)}>`；
- 其余 → 维持 `<button onClick={handleCompleteTask}>`。
- 所有任务卡片统一加 `data-task-id={id}`（测试钩子 + 稳定定位）。

## 5. 风险与对策
### 5.1 Token 为模块内存（非 localStorage）— 全程客户端导航
本项目 JWT 仅存模块内存（`src/lib/api.ts` 注释明确）。任何整页 `page.goto` 都会清空 token，
AuthGate 跳 `/login`。因此 Home→/speech→Home **必须客户端 SPA 导航**（点 `Link` / `nav a`，
不 `page.goto` 目标路由）。本 feature 全部点链接完成，天然满足；E2E 同口径。

### 5.2 `useSearchParams` 必须包 `<Suspense>`
Next.js 14 App Router 静态渲染页用 `useSearchParams` 而未包 `<Suspense>` 会在 `next build` 报错
（bail to client / build error）。已在 `SpeechPage` 默认导出用 `<Suspense fallback={...}>` 包裹
`SpeechInner`。

### 5.3 完成回写的「完成」定义
以「口语会话结束」为完成信号：`SpeechInner` 的 `finished` 状态（最后一词点 Finish →
`handleNext` 置 `finished=true`）触发 `completeTask`。**只调一次**（`taskMarked` 守卫）。用户中途
离开 `/speech` 则不回写（符合「完成才勾选」）。

### 5.4 E2E headless 麦克风（已固化）
沿用 AI-307 结论：launch flags `--use-fake-device-for-media-stream` + `--use-fake-ui-for-media-stream`
（`hooks.ts`）+ `speech.ts` 的 `Object.defineProperty` 注入，保证 `/speech` 录音可 headless 跑通。
本 feature 的 `SpeechPage.completeSession()` 复用该机制，无需额外处理。

### 5.5 `HomePage.taskCount()` 计数口径（回归防护）
原 `taskCount()` 只数 `button`，mic 改 `Link` 后计数会从 3 跌到 2，破坏 `home-dashboard.feature`
的「3 daily tasks」断言。已改为数 `[data-task-id]`（全部卡片），保持 3。

### 5.6 `completeAllTasks()` 须覆盖深链任务（回归防护）
`plan-progress.feature` 用 `completeAllTasks()` 驱动计划日回写。增强该方法：遇到
`[data-speech-link]` 卡片时，客户端导航进 `/speech` → `completeSession()` → 返回 Home，再继续；
按钮类任务维持原点击逻辑。保证含 mic 的计划日也能被勾选回写。
