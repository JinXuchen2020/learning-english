# AI-606 — 拍照学单词 (OCR)

> 状态: done | 栈: node-ts (NestJS + Next.js) | 分支: feat/ai-606 | 来源: docs/ai-integration.md M6

## 1. 目标
孩子拍照 / 上传图片（实物、绘本页、手写单词）→ 多模态 OCR（`chatWithImage`，GLM-4.6V-Flash）识别物体/文字 → 生成单词卡片（英文 + 中文 + 配图 prompt）→ 一键加入个人「生词本」。含 429 限流退避（复用 AI-106 `RetryableAiProvider`）与「识别不出」友好兜底。

## 2. 接口契约
### 后端
- `POST /api/scan/recognize` — `multipart/form-data`：`image`(文件, png/jpg, ≤5MB) + 可选 `prompt`(文本)。鉴权 `JwtAuthGuard`，userId 取自 `req.user.userId`。
  - 成功 `200`：`{ cards: ScanCardView[], recognized: true }`
  - 未识别 `200`：`{ cards: [], recognized: false, message: "没有认出单词，换一张更清晰的图片试试～" }`
- `POST /api/scan/confirm` — body `{ ids: string[] }`（class-validator 校验非空字符串数组）。将当前用户拥有的 pending 卡片置 `saved`，返回更新后的 `ScanCardView[]`。
- `GET /api/scan` — 返回当前用户 `saved` 状态的生词本列表 `ScanCardView[]`。
- `ScanCardView`: `{ id, wordText, meaning, example, imagePrompt, status }`

### 前端
- `src/lib/api.ts`: `recognizeImage(file, prompt?)`(复用 `postFormData` 多部件上传) / `confirmScanWords(ids)` / `listScannedWords()`
- `src/lib/types.ts`: `ScanCard` / `ScanResult` / `ConfirmScanDto`
- 新页 `src/app/scan/page.tsx`：`AuthGate` 包裹；上传控件（`<input type="file" accept="image/*" capture="environment">`）→ 识别 → 卡片预览（每张带「加入」按钮 + 顶部「全部加入生词本」）→ 生词本列表。
- `TabNav` 新增「拍照」标签 → `/scan`。

## 3. 数据模型
新实体 `ScannedWord`（表 `scanned_words`）：
- `id` uuid PK
- `userId` varchar（NOT NULL）
- `wordText` varchar（英文）
- `meaning` varchar（中文）
- `example` varchar nullable（例句）
- `imagePrompt` varchar nullable（配图 prompt）
- `status` varchar default `'pending'`（`'pending' | 'saved'`）
- `createdAt` datetime (CreateDateColumn)

> 不复用 `words` 表（`Word` 强依赖 `lessonId` + 测验字段），也不复用 `ai_word_cards`（全局待审内容库）；OCR 生词本是**个人**收藏，故独立实体。

## 4. 验收标准
- [ ] 上传图片 → 调 `chatWithImage` → 解析 JSON 卡片 → 落库 pending → 预览
- [ ] 点「全部加入生词本」→ `confirm` → 卡片变 `saved`，生词本列表出现
- [ ] 识别不出（解析为空/无有效卡）→ 不 500，返回 `recognized:false` + 友好文案
- [ ] 429 限流由 AI-106 退避层处理（不在本 feature 重复实现）
- [ ] E2E（MockProvider）跑通：登录 → 上传 → 见卡 → 加入 → 生词本含该词

## 5. 风险点
- **图片大小/格式**：multer 硬上限 10MB 防内存爆，service 层精确校验 ≤5MB + MIME 白名单（png/jpeg）→ 413/415。
- **OCR 解析脆弱**：LLM 可能返回非 JSON / 围栏包裹 / 无关文本 → `parseScanOutput` 剥离围栏 + 结构校验，失败归为「识别不出」友好兜底，不抛 500。
- **越权**：`confirm`/`list` 严格按 `userId` 过滤，跨用户 id 拒绝。
