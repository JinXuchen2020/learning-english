# AI-713 — AI provider 去 env 化 + 系统默认智谱种子 + 去 mock

> 状态: in-progress | 栈: node-ts（NestJS 后端 + Next.js 前端，全栈） | 分支: feat/ai-713
> 来源: `features/backlog.md` M9 / AI-713；用户决策（2026-08-14）：
> 1. seed 用单个引导变量 `ZHIPU_API_KEY`（仅播种用，运行时不再读任何 AI env）。
> 2. 聊天内容安全分类器（`chat-safety`）去除 NVIDIA env，复用系统默认智谱 provider 做 LLM 安全判断（fail-open 兜底）。

## 1. 目标

把 AI provider 的配置从「环境变量 + 代码兜底 mock」彻底改为「数据库驱动 + 系统默认种子」。具体：
- 删除 `.env` 中所有 AI provider 字段（`AI_PROVIDER` / `BIGMODEL_*` / `NVIDIA_*`）。
- 智谱（Zhipu）配置作为**系统默认** provider 种子插入 `provider_configs` 表（`ownerUserId=NULL, isDefault=true`，密钥 AES-256-GCM 加密落库）。
- 家长/孩子未设置自己 provider 时，AI 调用回退到该「系统默认」。
- 删除 `MockAiProvider` 及所有 `'mock'` 类型痕迹（类型联合 / DTO / switch / e2e / 单元测试假值）。
- 聊天安全分类器去掉 NVIDIA env 依赖，复用系统默认智谱 provider 做 LLM 安全判断（失败 fail-open）。
- e2e：移除「mock provider 类型」（step `type:"mock"` / `provMock` i18n / `MockAiProvider` 类），后端不再设 `AI_PROVIDER=mock`，e2e 后端走系统默认智谱种子；`page.route` 仅用于 UI 确定性夹具数据（scenes/stars/sessions/speech/report 等，**非** provider 抽象），保留以避免对真实 LLM 网络的脆弱依赖。

用户价值：部署不再需要配 `AI_PROVIDER`；默认即用真实智谱；家长仍可自带 key 覆盖（AI-705）；测试走真实 AI，行为更可信。

## 2. 接口契约（无新增路由，均为内部解析路径变更）

### 2.1 后端 provider 解析（改 `ai.module.ts` + `provider-config.service.ts`）

- `ai.module.ts` 的 `AI_PROVIDER_TOKEN` 工厂不再从 `ConfigService`/`readAiConfig` 读 env 构建默认 provider；改为：
  - 启动时 `await providerConfigService.resolveSystemDefault()` 取系统默认实体；
  - 用 `providerConfigService.buildProvider(sysCfg)`（retry 包装）后，再套 `createUsageLimitedProvider` + `createLoggedProvider`（与旧 env 默认等价：retry+quota+logged）；
  - 构造 `new AiProviderRouter(auditedDefault, providerConfigService)` 作为 `AI_PROVIDER_TOKEN` 单例。
  - 若 `resolveSystemDefault()` 返回 null（未 seed）→ `logger.error('[AI] 未找到系统默认 provider，请先 npm run seed')` 并兜底构造 `new BigModelProvider({ apiKey:'', baseUrl: DEFAULT, model: DEFAULT, ... })`（调用时失败但应用可启动）。
- `AiProviderRouter.resolve()` 末尾回退从「env 默认」改为「`await this.providerConfigService.resolveSystemDefault()`」；若仍无 → 抛 `AiProviderException('no default provider')` 或复用兜底（与上面一致）。

### 2.2 数据写入契约（与 AI-705 不变）

`ProviderConfig` CRUD（`/provider-config`）契约不变，仅 `type` 枚举变化：

- `CreateProviderConfigDto.type`：`'openai-compatible'`（移除 `'mock'`，`'bigmodel'` 保留为 legacy 兼容但 DTO 不开放选取）。
- `ProviderTypeDto = 'openai-compatible'`（移除 `'mock'`）；`@IsIn(['openai-compatible'])`.

### 2.3 删除的 env 字段（`.env` / `.env.example`）

移除：`AI_PROVIDER`、`BIGMODEL_API_KEY`、`BIGMODEL_BASE_URL`、`BIGMODEL_MODEL`、`BIGMODEL_VISION_MODEL`、`BIGMODEL_TTS_MODEL`、`BIGMODEL_TTS_VOICE`、`NVIDIA_API_KEY`、`NVIDIA_BASE_URL`、`NVIDIA_MODEL`、`NVIDIA_SAFETY_MODEL`。
新增（仅播种用，运行时不用）：`ZHIPU_API_KEY=replace-with-key`（`.env.example` 占位；`.env` 填真实值，已 gitignore）。
保留：`PROVIDER_ENC_KEY`（加密密钥，seed 与运行时须一致；缺失时 crypto.util 用 dev 固定 key 并 warn）。

## 3. 数据模型

### 3.1 `ProviderConfig` 实体（`server/src/ai/provider-config/provider-config.entity.ts`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid PK | |
| `ownerUserId` | uuid，**可空**（`nullable: true`） | 系统默认行 `= NULL`；家长配置 `= 自身 userId` |
| `name` | varchar | 展示名（系统默认：`'Zhipu (system default)'`） |
| `type` | varchar | `'openai-compatible' \| 'bigmodel'`（移除 `'mock'`） |
| `baseUrl` | varchar nullable | 系统默认：`https://open.bigmodel.cn/api/paas/v4` |
| `apiKeyEnc` | text nullable | AES-256-GCM 密文 |
| `modelsJson` | text nullable | `{ chat:'glm-4.7-flash', vision:'glm-4.6v-flash', tts:'glm-tts' }` |
| `capabilitiesJson` | text nullable | `['chat','vision','tts']` |
| `isDefault` | boolean default false | 系统默认行 `= true`；家长账号内互斥 |
| `createdAt` / `updatedAt` | datetime | |

> 注册铁律：`@Entity()` 已在 `appEntities` 登记（AI-705 已完成），本次仅改列定义，无需重新登记。

### 3.2 新增方法 `provider-config.service.ts`

- `resolveSystemDefault(): Promise<ProviderConfig | null>` → `repo.findOne({ where: { isDefault: true, ownerUserId: IsNull() } })`（`import { IsNull } from 'typeorm'`）。
- `resolveDefault(ownerUserId)` 保持按 owner 查询（不受影响）。
- `buildProvider(config)`：移除 `case 'mock'` / `default → MockAiProvider`；未知 type 抛 `BadRequestException('Unknown provider type: ' + config.type)`。

## 5. 风险点

| 风险 | 缓解 |
|---|---|
| 系统默认无 owner 归属 | `ownerUserId` 改为可空；`resolveSystemDefault()` 用 `IsNull()` 查；`setDefault` 仍按 owner 过滤，不波及系统行 |
| 种子 key 来源 | `ZHIPU_API_KEY` 仅播种用（seed.ts 读）；运行时读 DB；`.env.example` 占位，不提交真实 key；`.env` 已 gitignore |
| `PROVIDER_ENC_KEY` 不一致 | seed 与运行时用同一 `PROVIDER_ENC_KEY`（缺失都用 dev 固定 key，自动一致）；生产须显式设同值 |
| `buildProvider` 包装层级 | 系统默认在 `ai.module.ts` 工厂里显式包 retry+quota+logged，等价于旧 env 默认；用户覆盖配置仍走 `buildProvider`（retry only，与既有行为一致） |
| 移除 `'mock'` 致大量 spec 编译失败 | 批量将 spec 中 `name:'mock'` 假值改 `'bigmodel'`；删除 `ai.factory.spec.ts` / `ai-config.spec.ts`（测试已删的 `createAiProvider`/`readAiConfig`）；改写 `ai.module.spec.ts` 按 DB 系统默认断言 |
| e2e 真实 AI 慢/限流 | **已规避**：聊天/口语 UI 断言保留 `page.route` 确定性夹具，不触达真实 LLM；e2e 后端 AI 路径虽走系统默认智谱，但 UI 桩拦截了相关请求，故无真实网络依赖/限流风险。仅 provider 配置流（新增/设默认/掩码/删除）真实可用 |
| 安全分类器改 LLM 调用 | 复用 `AI_PROVIDER_TOKEN`（router）；调用失败 fail-open（放行 + 关键词黑名单兜底）；不阻塞主流程 |
| NVIDIA 安全能力降级 | 旧 NVIDIA 安全模型不再可用；改用默认智谱 LLM 判断（用户已确认），无 NVIDIA env |

## 6. 测试计划（硬约束 #6）

### 6.1 单元测试（有逻辑分支的源码）

- `provider-config.service.spec.ts`：新增 `resolveSystemDefault` 命中（ownerUserId=NULL）/ 未命中；`buildProvider` 移除 mock 后未知 type 抛错；`setDefault` 不影响系统行。
- `ai-provider.router.spec.ts`：parent 有默认 → 自定义；无配置 → 回退系统默认（`resolveSystemDefault`）；解密失败/异常 → 回退；异常不向外抛启动错误。
- `chat-safety.classifier.spec.ts`：复用默认 provider 做安全判断；LLM 抛错 → fail-open 放行；命中黑名单 → 拦截。
- `bigmodel.provider.spec.ts` / `openai-compatible.provider.spec.ts`：去 env 后构造参数来自 config（无 env 兜底）。
- `ai.module.spec.ts`：改写——不再断言 `AI_PROVIDER=mock/bigmodel`，改为断言系统默认由 DB 解析、工厂返回 `AiProviderRouter`；补 `ProviderConfig` fake repo（铁律）。
- 删除 `ai.factory.spec.ts`、`ai-config.spec.ts`（测试已移除的函数）；其余 spec 中 `name:'mock'` 假值批量改 `'bigmodel'`。

### 6.2 BDD/E2E（用户可感知旅程，必做）

> 范围决策（2026-08-14）：AI-713 的「去 mock」指**移除 mock provider 类型**（`type:"mock"` / `provMock` / `MockAiProvider`），并非移除所有 `page.route` 网络桩。`src/e2e/support/pages/{home,speech,chat}.ts` 中的 `page.route` 桩（report/daily、speech/evaluate、chat/scenes、chat/messages、chat/stars、chat/sessions）是**确定性 UI 数据桩**，与 provider 抽象无关；移除它们会使 e2e 依赖真实智谱网络（沙箱受限、易超时/限流）并破坏既有断言（如 `FOX_VOICE_WAV` 音频 src 断言）。故保留这些 UI 桩，仅清理 mock provider 概念。e2e 后端配置不再设 `AI_PROVIDER=mock`，因此后端 AI 路径走系统默认智谱种子（真实但未被 UI 桩触达）。

- `parent-provider-config.feature` / `per-child-provider.feature`：`type:"mock"` → `type:"openai-compatible"`（per-child 用占位 baseUrl/key，仅作配置存在性前置，不真正调用）。
- 场景（provider 配置流真实可用，聊天/口语 UI 断言用 `page.route` 确定性夹具）：
  - 家长登录 → 进入「AI 提供商」→ 新增一个 openai-compatible provider → 设为默认 → 列表掩码展示 → 删除。
  - 家长创建孩子 → 每孩 provider 覆盖：给孩子指定一个 openai-compatible 配置 → 实测生效；设 null 回退家长默认 → 系统默认。
  - 聊天/口语 UI 旅程的断言继续由 `page.route` 确定性夹具驱动（scenes/stars/sessions/speech/report），不依赖真实 LLM 网络。
